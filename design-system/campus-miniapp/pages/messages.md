# 消息页面视觉覆盖

本文件覆盖 [`../MASTER.md`](../MASTER.md) 中与消息列表、私信入口、消息详情和未读状态相关的细节。未写明的内容继续遵循主规范。

## 1. 消息列表

- 消息首页以“校园通知”置顶行开头，下面直接展示私信会话；私信行直接展示头像、昵称、最后一条消息、时间和会话未读数，列表末尾按需提供“查看全部私信”。
- “校园通知”不与私信混入同一条时间线，而是作为置顶入口展示未读数和提醒说明。点击后进入通知列表，继续提供搜索、分类筛选、已读和详情 Sheet。
- 消息页使用页面级清晰的未读强调；未读通过浅蓝边框/层级、红色数量角标或状态点表达，不依赖大面积高饱和色块。
- 私信会话和校园通知入口共用白色表面、细分隔线和统一触控高度，不使用胶囊或阴影卡片堆叠；类型差异通过头像、图标、辅助文案和状态色表达，入口保持轻量可点击行。
- 无未读时不显示空的角标、占位红点或伪造数量；长标题、昵称和摘要遵循单行/两行截断规则。
- 会话列表时间按校园自然日分段：同日显示“刚刚 / X分钟前 / X小时前”，前一天显示“昨天”，近七日显示“X天前”，更早显示具体日期；跨年日期带年份。通知详情保留完整日期和时刻，聊天详情按时间间隔显示星期与时刻分隔条。

## 2. 详情 Sheet 与输入

- 消息详情采用白色底部 Sheet，上圆角、独立关闭图标和紧凑内容区；内容超出可用高度时主体内部滚动，固定操作栏不被遮挡。
- 私信聊天使用页面底色、按时间间隔出现的时间分隔条、左右头像和不对称圆角气泡；收信使用白色气泡，发信使用 Ousea 主色气泡，消息正文不再为每条消息重复占用时间行。
- 消息输入和评论输入沿用 `KeyboardSafeInput`/`KeyboardSafeTextarea` 的键盘安全区处理。打开图片选择、切换输入态或返回详情时，不应因重排导致输入框和键盘无故关闭。
- 底部操作只展示服务端允许的动作；提交中保持按钮尺寸，失败提示靠近操作区域，不通过整页刷新制造闪烁。
- 私信图片采用“先发后审”：选图后先在聊天流追加本地缩略图，上传阶段显示确定进度，发送阶段显示轻量进行中状态；上传完成后自动发送，不要求再次点击发送。发送接口成功后立即移除临时发送卡片，消息回到正常时间线，不单独悬挂“审核中”状态。
- 图片消息发送成功后，服务端通过 `image_state` 返回 `pending`、`available`、`rejected` 或 `expired`。客户端只对接统一的图片消息发送接口和消息状态字段；服务端负责兼容历史请求行为，客户端不再查询媒体详情或调用旧版审核提交接口。
- `pending` 图片保留原消息位置和尺寸，使用中性图片占位，不在客户端持续展示审核进度或发起媒体审核轮询；`available` 图片才允许点击预览大图；`rejected`/`expired` 统一展示不可点击的“图片已失效”，不删除消息、不改变时间线和头像布局。状态在重新进入、下拉刷新或服务端消息刷新时自然更新。

## 3. TabBar 未读角标

- 首页顶部不再重复放通知图标，消息未读统一由自定义 TabBar 的一个总数字角标承载。总数为私信未读与校园通知未读之和，`1–99` 显示具体数量，超过 `99` 显示 `99+`，`0` 隐藏。
- 应用 `onShow` 时全局重新请求未读数，并同步当前 TabBar 实例、持久化值和下一帧 UI；不能只在消息页首次打开时请求。
- 角标采用 `danger-500` 红底白字，保持绝对定位，不改变图标、文字和 TabBar 的整体高度。

## 4. 交付检查

- [ ] 冷启动、从后台返回和重新加载小程序后未读数都会刷新。
- [ ] 消息 TabBar 总角标与私信、校园通知两类未读状态一致，页面内部可分别显示各自数量。
- [ ] 消息首页默认可见私信会话列表，校园通知只有一个清晰入口。
- [ ] 详情 Sheet 长内容可滚动，关闭按钮没有矩形外围。
- [ ] 键盘和输入框在图片选择、提交和切换输入态时保持稳定。
- [ ] 选图后消息流立即出现本地缩略图；上传和发送有确定/进行中状态，发送成功后临时卡片消失并并入正常时间线。
- [ ] 审核通过后图片可预览，审核拒绝或媒体失效后原位置显示“图片已失效”。
- [ ] 客户端不主动轮询图片审核；重新进入、下拉刷新或服务端消息刷新后可获得最新状态。
- [ ] 服务端兼容历史请求行为时，客户端仍只走统一的图片消息发送接口，不额外调用旧审核接口。
