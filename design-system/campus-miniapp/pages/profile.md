# 我的页面视觉覆盖

本文件覆盖 [`../MASTER.md`](../MASTER.md) 中与“我的”页面、账号信息和个人服务入口相关的细节。未写明的内容继续遵循主规范。

## 1. 页面骨架

- 页面内容左右使用 `32rpx` 留白，与首页保持一致；页面背景使用 `bg.page`，身份区和功能分组使用白色 `surface` 卡片。
- 顶部身份卡使用 `card-lg` 圆角、浅边框和轻阴影，头像、昵称、账号信息和右箭头建立清晰层级；不要把所有信息压缩成一排胶囊。
- 分组标题复用首页的“短竖向标记 + 标题 + 可选提示”样式，标题字号、标记高度和间距保持一致。

## 2. 服务宫格与分组列表

- “我的服务”使用三列紧凑宫格，服务入口保持统一的图标底板、图标尺寸和文字基线；使用真实 SVG/PNG，不使用 Emoji。
- “显示与外观”“账号与身份”等分组使用白色卡片、细分隔线和单行列表。左侧图标与标题对齐，右侧值和箭头保持同一中心线。
- 菜单文案保持短而直接，避免为每一项重复添加“我的”；长文案在真实空间不足时省略，不通过主动简写破坏含义。
- 普通列表不使用过强彩色背景。颜色只承担功能识别和状态反馈，主文字仍使用 `ink-900/ink-700`。

## 3. 移动端交互

- 手机端不使用 hover 作为信息展示或操作前提。点击列表项使用透明度或轻微缩放反馈，反馈不改变分隔线、行高和箭头位置。
- 列表行和图标按钮的可点击区域不小于 `88rpx`；图标本身可以小一些，但不能缩小触控热区。
- 账号、认证、退出等高风险操作使用明确的确认和就近反馈，不把主要动作藏进三点菜单。

## 4. 交付检查

- [ ] 页面左右留白与首页一致，卡片没有额外的外层嵌套空隙。
- [ ] 三列服务宫格在窄屏不溢出，图标、标题和箭头基线稳定。
- [ ] “显示与外观”“账号与身份”标题样式与首页区块标题一致。
- [ ] 手机端不存在依赖 hover 的入口状态。
