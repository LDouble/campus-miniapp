# 首页视觉覆盖

本文件覆盖 [`../MASTER.md`](../MASTER.md) 中与首页、服务入口和全校通知相关的细节。未写明的内容继续遵循主规范。

## 1. 页面骨架

- 页面内容左右统一使用 `32rpx` 留白，底部为自定义 TabBar 和安全区预留空间；不要让不同模块使用不同的主 gutter。
- 首页采用 Ousea `bg.page` 作为背景，服务区、通知区和内容区使用白色卡片分组。卡片保留 `card-lg` 圆角、浅边框和紧凑的内部间距，不使用无边界漂浮胶囊。
- 区块标题使用“短竖向标记 + 标题 + 可选提示/操作”的组合。标记使用 `ocean-500 → wave-400` 的短渐变，标题和操作在同一行对齐。

## 2. 服务与通知

- 服务入口使用紧凑宫格，图标采用真实 SVG/PNG，图标底板使用统一尺寸和浅色业务底，不使用 Emoji；每个入口保留不小于 `88rpx` 的触控区域。
- 常用服务展示“猫猫图鉴”，直达图鉴列表；猫咪线性图标提供浅色和深色版本，复用生活服务暖色底板。
- 全校通知使用白色圆角卡片，内部采用连续列表和浅分隔线。条目以图标、标题、来源/日期和右箭头建立层级，长标题最多两行，不压缩箭头和触控高度。
- 首页顶部不重复放置通知图标。通知中心和消息入口通过明确的区块/TabBar 进入，避免同一条未读信息出现多个高权重入口。

## 3. 消息角标与生命周期

- 未读消息数只在自定义 TabBar 的消息项上显示数字角标：`1–99` 显示具体数量，超过 `99` 显示 `99+`，为 `0` 时隐藏。
- 应用进入前台时由全局 `onShow` 重新请求未读数；首页重载不能成为请求条件。数据需要同步到持久化值、当前 TabBar 实例，并在下一帧补一次 UI 同步以覆盖冷启动时序。
- 角标使用 `danger-500` 浅量级红底配白字，不与页面内业务色混用；角标不改变 TabBar 图标和文字的布局。

## 4. 移动端反馈

- 首页不提供 hover 视觉。服务入口、通知条目和 TabBar 使用按压时透明度或轻微缩放反馈，动画在 `120–160ms` 内完成且不引发布局位移。
- 固定 TabBar 使用扁平、全宽结构和顶部细边框，不使用悬浮胶囊、强阴影或 backdrop blur；激活项使用 `ocean-500`，未激活项使用 `text-secondary`。

## 4.1 通知与签到引导

- 未读消息仍由 TabBar 数字角标承担数量表达；首页通知引导仅说明“开启提醒”的价值，不重复显示未读数字或新增顶部铃铛。
- 通知引导为底部 Sheet：`surface` 背景、`sheet` 顶圆角、深色遮罩，两个操作保持明确主次关系；主操作为蓝色实底，次操作为浅色表面，不做并列胶囊。
- 进入首页时按运行时配置逐个读取微信订阅模板状态：所有模板均已接受时不展示引导；“开启提醒”在用户点击链路中直达微信订阅设置页，统一管理总开关与各模板。
- 签到入口与周次并列在首页头部左侧安全区域：未签到使用绿色图标加文字操作，已签到显示“已连签 N 天”轻量状态；两者均不使用描边胶囊或独立卡片高度。头部需为微信右上角胶囊预留空间。
- 引导卡片和 Sheet 的交互目标最小 `88rpx`，按压只改变透明度，不引发布局位移；减少动态效果时不使用入场动画。

## 5. 交付检查

- [ ] 首页所有主要区块左右边距一致，卡片内部没有多余空白。
- [ ] 通知图标没有与消息 TabBar 角标重复表达同一提醒。
- [ ] 冷启动、返回前台和切换 Tab 后未读数字均能及时更新。
- [ ] 320–375px 宽度下服务入口、标题和角标不横向溢出。

## 6. Figma 3770:2：首页课程与讨论入口

设计参考：[Figma 3770:2](https://www.figma.com/design/xf5G1hBBYt03E3sTZ2rmBV/Untitled?node-id=3770-2)，对应 Stitch 项目 `3237828770888524086`、屏幕 `2a6684215dc54f52b9488493f3d997f8`。原始图片、HTML 和图标来源记录保存在工作区 `outputs/gh240-figma-3770/`。

- 首屏顺序为账号/签到与校区、两行服务宫格、今日或明日课程、全校通知。保留已有社区动态、运营 Banner、资格版引导和底部导航的真实业务入口。
- 服务宫格最多显示九项已启用服务，第十格固定为「全部服务」，剩余服务可从服务页进入。默认依次为课程表、成绩单、考试安排、空闲教室、通过率、二手、校历、校车和找同行，已保存的用户自定义顺序不覆盖；不创建设计稿中的未实现业务。
- 页面使用语义浅蓝到页面色的渐变；卡片使用 surface 白底、浅描边和 OUSea card 圆角。沿用系统字体、OUSea 字号和暗色语义色，不引入设计稿的网页玻璃滤镜和 hover。
- 课程区取消外层白色大容器，使用横向 Swiper：当前卡完整展示，下一张露出一角，下方同步分页条；单门课程取消分页与预览留白。课程换日或集合变化时归零，无自动轮播。
- 卡片展示淡色序号、课程状态、单行省略课名、“第 N–M 节”和地点；遵循此前产品要求，不显示上课起止时间。状态来自真实课程时间，明日预览不会显示「进行中」。
- 卡片底部按用户确认展示三枚叠放的 Stitch 模拟头像和「大家正在聊…」，仅保留「进讨论组」，不展示教师和提问入口。头像是静态视觉素材，不代表真实成员，不调用创建或参与接口获取统计。
- 缺少选课号或学期时讨论保留不可用反馈；资格版遵循迁移入口。异步打开使用同步锁防止重复进入。
- 保留空课表、假期、校历事件与提醒、模块开关、加载和失败提示；通知使用真实来源短标签和标题，保留详情跳转。
- 课程卡与 Sheet 操作热区最小 88rpx。地点、讨论、全部服务图标直接使用 Figma 导出的原始 SVG；暗色仅对这些功能图标定向提高对比度。

- 课程卡按 Stitch 紧凑比例：标题与地点紧邻，取消标题行占两行的预留空白；卡片整体 240rpx，底部按钮保持 88rpx 热区，视觉胶囊与头像按小尺寸排布。

首页常用服务视觉微调：五列保留用户排序，图标底座改为76rpx浅色圆角、标签22rpx，标题28rpx；自定义采用带编辑图标的低对比胶囊。样式仅在course-home范围内生效。

首页有校历事件时，课程轮播（或空课提示）与校历提醒共用一张 surface 卡片，下方用分隔线展示事件。事件固定显示，不随课程切换重复；保留校历跳转、提醒操作和课程讨论入口。无事件时沿用独立课程卡轮播。

合并卡片采用紧凑布局：假期不重复展示标题区已有的开学倒计时；无课提示缩小内边距。校历日期与事件标题同行，长内容允许换行，去掉时间轴圆点；提醒按钮保留 88rpx 热区。

开学前一天全天预览新学期首日课程，并在有教务凭据且缺少缓存时加载该学期课表；已同步但无课程展示“明天没有课”，缺少缓存展示“课表尚未同步”。更早的假期保留假期提示。

## 7. Stitch 紧凑首页间距（2026-09-20）

参考项目 `17489657399732060214` / 页面 `773674a9b1504187bb3b6526994cf7a6`，原始 HTML 与截图保存在工作区 `outputs/gh240-compact-stitch/`。本次仅迁移间距与信息密度，不恢复已关闭的校园推荐。

- 卡片间距 24rpx、服务卡内边距 28rpx、宫格行距 24rpx；图标 80rpx、标签行高 1，保留五列和用户自定义顺序。
- 课程标题 28rpx，课程计数取消额外胶囊内边距；课程/校历共用卡片，校历上方使用原稿虚线分隔。
- 通知标题取消多余分隔线，列表取消重复计算的垂直 padding 高度，标题单行省略并可进入详情查看全文。
- 允许差异：继续使用 OUSea 主色与现有功能图标；微信真实顶部安全区、88rpx 操作热区和现有 TabBar 保留，因此不复制网页的超小按钮高度。按用户要求不截图验收，由开发者工具预览反馈视觉效果。

用户后续确认继续压缩：服务卡上下内边距、宫格行距、头部及卡片之间间距统一为16rpx；合并卡课程轮播200rpx、指示区16rpx。通知标题及整行可点的条目采用64rpx紧凑高度，覆盖此前88rpx通知行约定；讨论和校历提醒按钮仍保留88rpx。

最终确认：首页服务区移除标题与自定义行，自定义从全部服务进入；宫格上下内边距与行距24rpx。三个区块标题与右侧入口对齐。讨论入口采用同色图标加文字，不使用胶囊；缺少课堂身份时仅提示课程信息不完整，不展示模拟头像与聊天提示。课堂学期显示对应名称，选课号仅保留在标题。

- 用户截图覆盖 Stitch 的白色信息条：入口位于常用服务之后、课程之前，使用「大家在聊」蓝青主题横幅。浅色洗底、文字与对话标识分别消费 `--campus-today-hot-{wash-start,wash-end,text,brand}`；暗色洗底为低透明蓝色至透明、文字复用 `text-heading`，品牌蓝保持不变。

- 保留已有可见性暂停和减少动态效果的逻辑；页面后台时暂停。滚动由现有短周期定时器驱动，Swiper 禁用手势拖动，避免与首页纵向滑动竞争。
