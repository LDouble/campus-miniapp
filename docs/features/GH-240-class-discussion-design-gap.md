## 功能核对

| 稿中能力 | 当前支持 | 补充工作 |
| --- | --- | --- |

| 帖子、点赞、评论预览 | 已有列表、点赞和多级评论 | 讨论卡样式和展示动作需适配新稿 |
| 收藏、分享 | 通用收藏及详情分享已具备 | 列表卡接入；不能只画按钮 |
| 全部讨论、最新发布 | topic_id + sort=latest 可用 | 可直接接入 |
| 热门精选 | 有 curated/featured 排序，没有明确热度排序与分数 | 明确精选与热门含义；新增 hot 排序/统计，不能将首屏局部排序冒充全部热门 |
| 问作业/资料分类及数量 | 快捷提问只预填草稿；无结构化帖子分类 | 增加 post_kind、筛选参数和分类统计，不用正文关键词猜测 |

| 帖内资料附件、下载数 | 资料库有文件与受控下载；帖子没有资料关联 | 关联现有 material_id，复用审核、下架、下载计数及短期授权下载 |

## 资料关联建议

第一步将课堂“资料”入口关联现有 `/pages/materials/index`，复用 `openCourseMaterials({courseName, courseCode, periodId})`。已有资料列表支持课程、学期过滤，上传也有现成流程。讨论组身份继续使用选课号和学期；资料课程属于课程级实体，不能直接把选课号当课程代码。

为支持首页、课表、分享链接、消息通知等所有入口，服务端应让课堂 Topic 返回结构化 `class_discussion`：`class_num`、`period_id`、`course_name`、可选 `course_code`、可选 `material_course_id`。资料课程匹配优先使用课程代码；课程名/别名匹配存在歧义时应让用户选择，不能绑定第一个同名结果。

第二步增加帖子与现有资料的关联（例如 `post_id + material_id`）。发布接口可接收数量受限的 `material_ids`，服务端校验资料发布状态和访问权限；列表/详情返回资料摘要、文件信息和下载统计。关联读取时再次处理资料下架，不能缓存永久公开下载地址。

点击附件继续调用现有 `POST /api/v1/course-materials/{materialId}/files/{fileId}/download`，不复制文件或绕过审核。需明确跨学期共用资料与本学期资料的展示策略。
