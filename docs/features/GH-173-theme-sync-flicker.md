# GH-173 微信主题统一适配

## 最终行为

根据用户最新决定，小程序取消手动深色、浅色和跟随系统三选一，统一跟随微信主题。“我的”页移除显示与外观选择区。历史手动主题存储不再读取，也不做迁移，不会覆盖微信当前主题。

此前手机在微信浅色、小程序强制深色的组合下，四个底部 Tab 首次切换仍出现白闪。最终采用微信原生主题作为唯一来源，避免原生窗口初始颜色与业务强制主题互相覆盖。旧的手动模式试验和补丁不再作为最终架构保留。

## 实现范围

- 原生窗口、导航和 TabBar：darkmode、themeLocation 与 theme.json 颜色变量。
- 所有页面、组件、自定义 TabBar、AI 卡片：媒体查询决定深浅样式；页面根与 page 的语义变量同时适配。
- 首页、我的、全部服务的图片资源：仅用系统主题读取与监听选择正确图片，回前台重新读取以恢复后台遗漏事件。
- 删除独立偏好模块、存储读写、手动选项与入口、Page 数据注入、生命周期包装、存活页集合、主题页面栈遍历、动态 page-meta、原生换色与预加载补丁。
- 保留静态页面根作用域和原有业务布局，保留社团骨架等语义颜色修复。静态类不再携带 light/dark 状态。
- 删除手动模式诊断生成器和过期测试；回归改为验证微信主题、媒体查询、无手动覆盖及既有页面深色可读性。

仅涉及小程序，不改后端契约，不启动或修改本地 Release 环境。

## 验收矩阵

| 场景 | 预期 |
| --- | --- |
| 微信浅色，历史手动偏好为 dark | 原生窗口、全部页面和底栏均浅色，旧值无效 |
| 微信深色，历史手动偏好为 light | 原生窗口、全部页面和底栏均深色，旧值无效 |
| 四个 Tab 首次与重复切换 | 无应用层浅深色校准步骤，主题由微信渲染器直接应用 |
| 微信运行中改变主题 | 媒体查询同步更新颜色，必要图片资源接收有效变化 |
| 后台切换主题后回前台 | 颜色跟随微信，图片重新读取系统主题 |
| 加载、空态、错误态和弹层 | 保留业务内容和交互，语义背景与文字跟随微信 |
| 页面卸载或重复订阅 | 图片组件取消订阅，无额外 Page 主题状态和生命周期包装 |
| 构建产物 | 70 个路由无主题 page-meta、无独立偏好和主题数据注入 |

- `test:design-tokens`、`test:typography`、`test:tabbar-layout`、`test:clubs`、`test:academic-schedule`、`test:community-what-to-eat` 通过。
- 最终构建 `TARO_APP_RELEASE=wechat-system-theme-20260920-r5 corepack yarn build:weapp` 通过（12.79 秒）；仍有既有 Sass 提示和公共包体积告警。
- 70 个路由产物检查通过；全量产物未发现旧偏好键、动态主题 Page 数据、手动深色类或外观入口。

- 已恢复模拟器浅色；AI 卡片完成编译与静态检查，本次未启用 AI 入口做运行时验证。
- 手机预览标识为 `wechat-system-theme-20260920-r5`。该预览不代表正式版发布。

模拟器或静态检查不能代替手机首次切换的逐帧验收；手机首进仍需使用本次二维码验证。
