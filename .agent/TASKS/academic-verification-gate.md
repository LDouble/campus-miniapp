## 目标

- 微信登录与校园身份认证解耦，微信登录成功不再等同于已认证学生。
- 新用户默认保持 `guest`，可以浏览允许公开访问的内容。
- `guest` 调用声明了 `academic_verification: required` 的接口时，统一返回 HTTP `403` 和业务码 `academic_verification_required`。
- 小程序只弹出一次认证提示，用户确认后进入独立认证页。
- 认证页支持教务账号同步验证和学生证材料人工审核两条路径。
- 教务账号验证成功或人工审核通过后，后端原子升级为 `member`，小程序回到触发认证的业务页面。

## 实施阶段

### 阶段一：权限契约与生成元数据

- 将 `academic_verification` 标记写入生成式权限元数据。
- 修正通用权限中间件的拒绝分支，区分“缺少校园身份”和“真正无权限”。
- 保留生成 Adapter 内的教务认证门槛，避免自定义角色或管理员权限绕过校园身份校验。
- 补充后端 HTTP、生成器和权限元数据测试。

### 阶段二：小程序统一错误处理

- 扩展 API Client，识别 `academic_verification_required`。
- 实现单例提示与安全回跳信息保存，避免并发请求产生多个弹窗。
- 不自动重放发布、接单、下单等非幂等业务动作，认证完成后由用户再次确认操作。

### 阶段三：独立校园身份认证页

- 新增独立非 TabBar 页面和 API Repository。
- 支持查询本人认证状态、教务账号验证、学生证图片上传和人工申请提交。
- 展示未认证、审核中、已通过、已驳回、已撤销等状态，并支持驳回后重新提交。
- 认证成功后刷新当前用户与权限，再返回原业务页面。

### 阶段四：联调与验收

- 验证 guest 浏览、认证门槛、普通无权限、两种认证路径和角色升级。
- 验证图片格式、大小、失败重试、重复提交、页面回跳与弹窗去重。
- 完成后端生成检查、测试与构建，以及小程序类型检查和微信端构建。

## 交付边界

- 复用现有认证表、材料私有存储、审核后台和角色升级逻辑，不新增重复的认证模型。
- “没有学生账号”按“没有可登录的教务账号”处理，人工认证仍需填写学生证上的姓名和学号。
- 本期不自动重放认证前失败的写请求，不将密码或学生证图片写入日志、本地存储或页面参数。
- 本期不新增公开材料 URL；认证图片仍只允许管理员通过受控接口查看。
