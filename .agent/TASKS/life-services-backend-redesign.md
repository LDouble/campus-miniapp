## 目标

- 将当前前端 Mock 列表和本地发布逻辑替换为真实后端数据。
- 保留社区 Tab 内“社区、跑腿、二手、拼车”的产品入口，但拆分业务实现、详情页和发布流程。
- 让发布、审核、接单/加入/下单、履约、完成、取消、评论、通知形成完整闭环。
- 统一认证、请求、幂等、乐观锁、错误处理、分页、刷新和草稿能力。
- 补齐现有后端缺少的通用媒体、举报和部分业务结构化字段。

## 实施阶段

### 阶段一：契约与基础设施

- 扩展后端 OpenAPI Schema，补齐媒体、举报和三类业务字段。
- 建立小程序 API 客户端、微信登录、令牌刷新、错误模型和幂等键。
- 从后端 `api/openapi.yaml` 生成或同步前端类型，禁止重复手写契约类型。

### 阶段二：业务浏览与详情

- 重构社区 Tab 的生活服务容器。
- 新增跑腿、拼车、二手独立详情页。
- 接入分页、搜索、筛选、下拉刷新、加载失败和空状态。
- 根据 `viewer_relation` 与 `available_actions` 渲染操作，不在前端复制权限规则。

### 阶段三：统一发布器与媒体

- 将通用单页表单改为“一个统一发布器 + 类型化结构字段”，同一页面同时支持新建、编辑和重新提交。
- 支持本地自动草稿、图片上传、字段校验、联系方式保护和审核状态。
- 支持编辑、重新提交、撤回及版本冲突恢复。

### 阶段四：履约、我的服务与通知

- 跑腿接单、取件、送达、确认完成、取消。
- 拼车加入、退出、发布者取消。
- 二手商品提交审核、预订下单、订单取消、卖家确认完成。
- 新增“我的服务”聚合页，区分我发布的、我参与的和交易订单。
- 消息页接入通知中心，并支持跳转到具体业务资源。

### 阶段五：安全与验收

- 接入评论与举报。
- 校验学籍认证门槛、联系方式可见性、幂等重试和乐观锁冲突。
- 完成后端目标包测试、生成与迁移检查，以及小程序类型检查和构建。
- 在微信开发者工具 `dist` 中完成真机尺寸和完整业务链路验收。

## 交付边界

- 本期使用线下支付，不接微信支付。
- 本期不建设即时聊天，联系方式仅在后端授权后展示。
- 社区动态继续使用校园圈与评论模块，本任务只重构它与生活服务的导航和发布入口。
- 失物招领保留现状，后续单独建立领域模型，不强行复用跑腿或二手。
