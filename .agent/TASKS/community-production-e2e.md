## 实施范围

- 父模块可直接发帖，并聚合自身及全部启用子模块的已审核帖子。
- 根板块与子板块的名称、slug、排序和状态完全由服务端板块树驱动，前端不保留业务板块硬编码。
- 父模块、子模块发布都保留来源板块 ID，不再固定投递到某个业务板块。
- 评论/评价在审核前后保持正确可见性与计数。
- 管理员审核通过、驳回和非法重复审核符合状态机与权限约束。
- 自动化测试使用唯一前缀数据并在退出时清理，不污染本地联调数据库。
- 后端日常开发采用 Go 宿主机 Air 热重载，Docker 只运行 MySQL、Redis 中间件，并写入服务端开发规范。

## 准出证据

- 后端社区与评论目标包测试、生成检查、迁移检查通过。
- 小程序 TypeScript 检查、微信构建、差异格式检查通过。
- 微信开发者工具真实模拟器完成五条用户链路，关键接口均为预期 HTTP 状态。
- E2E 动态读取服务端板块 ID 与 slug，不依赖固定数据库 ID 或前端常量。
- 模拟器无 `TypeError`、`ReferenceError`、`Unhandled` 或接口 5xx。
- E2E 临时帖子、评论、点赞和审核记录均已清理。
