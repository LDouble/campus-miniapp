# 海大校园小程序：社区模块上线级 E2E

**Priority:** High
**Status:** Done
**Type:** Enhancement
**Created:** 2026-07-26
**Last Updated:** 2026-07-26

## 一、概述

社区已经具备板块树、帖子、点赞、评论和后台审核接口，但小程序曾把根板块错误实现为某个固定子板块，并且从子模块进入发布器后仍固定投递到同一板块。评论在待审核时还会提前增加公开评论数。这些问题使现有页面虽可操作，却无法证明父子模块、审核和评价链路达到上线标准。

本任务将父模块定义为可直接接收帖子、同时聚合自身及启用子模块内容的启用根板块；子模块定义为所属启用根板块下可直接接收帖子的启用子板块。用户从父模块发布时直接投递到该根板块，从具体子模块发布时投递到来源子板块。所有新帖子和评价均进入审核，审核通过前不进入公共列表。

## 二、用户故事

**作为** 校园社区用户
**我想** 在综合流看到各子模块的最新内容，并在当前子模块直接发帖和评价
**从而** 内容出现在正确板块，审核状态和数量始终可信。

**作为** 内容审核管理员
**我想** 对帖子与评价执行通过或驳回
**从而** 未审核内容不会公开，审核决定可追踪且不能被重复或越权执行。

## 三、范围与验收标准

### 3.1 评价功能

- 已审核帖子详情支持提交非空评价。
- 新评价默认 `pending_review`，作者可看到自己的待审核评价，但公开 `comment_count` 不提前增加。
- 管理员审核通过后，刷新详情可看到评价，公开计数增加一次。
- 空内容、超长内容和重复幂等请求不会生成多条评价。

### 3.2 列表功能

- 根板块、子板块名称、slug、排序与启用状态只读取 `GET /api/v1/campus-circle/sections`，前端不得硬编码业务板块或 slug 映射。
- 父模块使用 `parent_section_id` 聚合根板块自身及全部启用子模块的已审核帖子。
- 子模块使用 `section_id` 精确过滤，不能混入其他板块内容。
- 卡片显示帖子实际所属板块，而不是当前筛选名称。
- 搜索、第一页加载、加载更多、去重、空态、错误重试和下拉刷新可用。
- 待审核、已驳回和已撤回帖子不能出现在公共列表。

### 3.3 审核功能

- 普通成员不能调用管理员帖子或评价审核接口。
- 管理员可以审核通过或驳回待审核内容；驳回必须包含原因。
- 已审核内容再次审核返回冲突，不能重复改变状态。
- 帖子审核通过后进入公共列表；评价审核通过后进入详情评价列表。

### 3.4 子模块发帖

- 从任一服务端返回的启用子模块进入发布器时自动选中来源子模块。
- 发布器展示当前目标板块，并允许在服务端返回的可发布根板块、子板块间切换。
- 提交请求的 `section_id` 与所选子板块一致。
- 审核通过后只出现在对应子模块及父模块聚合列表。

### 3.5 父模块发帖

- 从任一服务端返回的启用父模块进入发布器时自动选中该根板块。
- 用户可以填写标题或正文，提交后进入待审核状态。
- 提交请求的 `section_id` 与该根板块 ID 一致。
- 审核通过后在父模块聚合列表中可见，并标注服务端返回的真实板块名称。

## 四、技术方案

### 4.1 小程序

- 社区首页先加载服务端板块树，按服务端顺序渲染全部启用根板块及其启用子板块。
- `CommunityFeedPanel` 同时支持 `section_id` 与 `parent_section_id` 查询。
- 父模块聚合项由根板块动态生成，其他频道直接使用服务端叶子板块 ID，不维护名称或 slug 常量。
- 卡片通过 `post.section_id` 映射真实板块名称和 slug。
- 发布入口携带 `community_section_id`，发布器以递归板块树解析并选中可发布根板块或子板块。
- 服务端板块树为空或没有可发布板块时展示错误并禁用提交，不回退到硬编码板块。
- 评论仅在创建结果已审核时即时增加公开计数，待审核评价依赖刷新后的服务端结果。
- 为频道、帖子、评价、发布板块和提交按钮增加稳定自动化选择器。

### 4.2 后端

复用现有接口，不新增业务端点：

- `GET /api/v1/campus-circle/sections`
- `GET /api/v1/campus-circle/posts`
- `POST /api/v1/campus-circle/posts`
- `GET /api/v1/campus-circle/posts/{id}`
- `GET /api/v1/comments`
- `POST /api/v1/comments`
- `POST /api/v1/admin/campus-circle/posts/{id}/review`
- `POST /api/v1/admin/comments/{id}/review`

后端补充或固化以下测试：

- `parent_section_id` 聚合与 `section_id` 精确过滤。
- 公共列表只包含 `approved`。
- 启用根板块、启用子板块的发帖约束及禁用板块拒绝规则。
- 帖子、评价审核通过/驳回/重复审核和权限门槛。

### 4.3 E2E 数据

- 使用当前已登录且完成校园认证的微信联调账号创建帖子与评价。
- 使用本地 bootstrap 管理员通过正式登录和审核 API 完成审核，不直接修改审核状态。
- 分页列表使用唯一前缀的隔离夹具，测试结束通过事务安全顺序清理评论、点赞、图片和帖子。
- 脚本无论成功或失败都执行清理，并验证残留数量为零。

## 五、自动化流程

1. 打开社区父模块，提交父模块帖子，确认待审核时公共列表不可见。
2. 管理员审核通过，刷新综合列表，确认帖子出现且显示真实板块。
3. 从服务端板块树动态选择一个子模块，从该入口发布，确认请求写入该子板块 ID。
4. 管理员审核通过，确认目标子模块可见、其他子模块不可见、所属父模块聚合可见。
5. 打开帖子详情提交评价，确认待审核计数不增加。
6. 管理员审核评价，刷新详情，确认评价文本和计数正确。
7. 验证滑动触底自动分页、搜索结果、接口 HTTP 状态、控制台异常和 5xx。
8. 清理夹具并验证数据库无 E2E 前缀残留。
9. 在脚本中动态读取服务端板块树，确认页面板块数量和目标 ID 与接口一致。

## 六、上线准出门槛

- 五项显式需求均有真实 UI/API/数据库证据，不以静态代码推断代替。
- 代码扫描确认不存在社区业务板块名称、slug 或固定 ID 硬编码。
- 后端单元与集成测试通过，OpenAPI 与生成物无漂移。
- 小程序类型检查和生产微信构建通过。
- 真实模拟器截图、网络日志、控制台日志均完成取证。
- 不泄露管理员密码、访问令牌、微信 openid、联系方式或审核内部字段。
- 自动化可重复执行且不依赖固定业务 ID。

## 七、风险

- 当前前后端工作区存在用户未提交改动，实施只做增量修改，不覆盖无关文件。
- 微信模拟器对动态文本选择器支持有限，因此使用稳定 class 选择器并辅以文本读取断言。
- 本地 E2E 依赖 Docker MySQL、运行中的当前后端及 bootstrap 管理员密码；缺失时脚本应明确失败，不降级为假通过。

## 八、本地开发部署规范

- Go API、Worker、迁移和初始化命令必须在宿主机运行。
- 日常开发只允许 MySQL、Redis 等中间件通过 Docker Compose 运行，不在 Docker 中运行 API 或 Worker。
- API 和 Worker 使用仓库 `go.mod` 锁定的 Air，通过 `make dev`、`make dev-worker` 自动编译并热重载。
- 本机进程必须通过 `scripts/run-local.sh` 把 Compose 服务名地址转换为宿主机回环地址，避免误用容器 DNS。
- E2E 启动前必须检查 MySQL、Redis 健康、宿主机 API ready，且 Docker 中不存在 API、Worker 容器。
- 完整命令、配置规则和故障恢复以服务端 `docs/local-development.md` 为准。

## 九、完成证据

- `npm run e2e:community` 在微信开发者工具真实模拟器完整通过。
- E2E 动态读取服务端板块树并校验页面板块数量，没有依赖固定名称、slug 或数据库 ID。
- 根板块帖子落到根板块 ID；子板块帖子落到来源子板块 ID。
- 普通成员审核返回 403；管理员覆盖驳回、重复审核 409、撤销审核、再次通过。
- 待审核评价作者可见且公开计数为 0，审核通过后公开计数为 1。
- 父列表聚合根自身和子板块内容；目标子板块可见，兄弟子板块不可见。
- 第一页 20 条，滑动触底后自动追加；唯一标题搜索只返回目标帖子。
- 模拟器关键 GET 返回 200，帖子和评价 POST 返回 201，无接口 5xx，无 `TypeError`、`ReferenceError` 或 `Unhandled`。
- 脚本退出后临时帖子和评价残留数为 0。
- 后端全量 `make test`、目标模块 race、目标模块 lint、`go vet ./...`、`make build`、`make generate-check`、`make migration-check` 通过。
- 小程序 OpenAPI 生成、TypeScript 类型检查、微信生产构建和 `git diff --check` 通过。
