# OUSea小程序：修复通过率趋势学期标签

**Priority:** High
**Status:** Done
**Type:** Bug
**Created:** 2026-08-14
**Last Updated:** 2026-08-14

## 问题概述

通过率趋势页自行把 `term_code` 末段翻译为季节，当前错误映射为 `1=秋、2=春`，并把 `3` 原样显示。生产源数据的本科口径实际为 `1=夏、2=秋、3=春`，因此 `2025-2026-2` 的 2610 份成绩被误标为“25-26 春”，`2025-2026-3` 的 1903 份成绩则显示为“25-26 3”。

## 修复目标

- `2025-2026-2` 展示为“25-26 秋”。
- `2025-2026-3` 展示为“25-26 春”。
- 课程趋势、当前数据点详情和教师趋势保持一致。
- 后端已返回 `term_label` 时直接展示该字段，避免小程序重复推导业务口径。
- 对尚未返回新字段的缓存或旧响应使用正确映射兼容。

## 技术方案

- 同步当前后端 OpenAPI 契约，使趋势点类型包含 `education_level`、`period_id` 和 `term_label`。
- 抽取可测试的趋势学期标签格式化函数，优先读取 `term_label`。
- 兼容路径按本科源数据规则映射 `1=夏、2=秋、3=春`，无法识别时回退原始 `term_code`。
- 课程图表标签、选中点详情和教师趋势列表统一调用该函数。
- 趋势渲染键使用完整学期身份，避免不同培养层次或周期发生键冲突。

## 文件范围

- `src/pages/academic/statistics/index.tsx`：替换错误标签转换和趋势点键。
- `src/features/academic-statistics/`：增加可测试的学期标签工具及测试。
- `src/api/generated/schema.ts`：通过契约同步生成最新趋势点类型。

## 测试要求

- 验证后缀 1、2、3 分别显示夏、秋、春。
- 验证存在 `term_label` 时优先使用服务端标签。
- 验证非法学期代码安全回退。
- 执行相关单元测试、TypeScript 类型检查和 `git diff --check`。

## 非目标

- 不修改后端统计数据、通过率计算或生产数据库。
- 不改变趋势图的数值、排序和交互。
- 不在本次修复中调整课程搜索或统计隐私阈值。
