# 小程序：考试默认当前学期、小时级截止倒计时与座位号展示

**Priority:** High
**Status:** In Progress
**Type:** Enhancement
**Created:** 2026-09-02
**Last Updated:** 2026-09-02

## Overview

调整本科生考试安排页面的学期策略，使页面首次打开和每次重新进入都优先查看服务端标记的当前学期，并在没有当前标记时回退到最近开始的学期。历史学期仅允许在当前页面会话中临时查看，不写入本地偏好。同时修正生活服务截止时间的相对倒计时，避免把 1 天 12 小时直接显示为 2 天，并将考试卡片的座位号单独展示。

## User Story

**As a** 使用教务和校园生活服务的本科生
**I want** 考试安排每次打开都默认到当前学期、单独看到座位号，并看到精确到小时的截止时间
**So that** 我不需要手动切换旧学期，也不会误判任务还有多久截止。

## Context

当前考试页使用硬编码的 `2025-2026-2` 作为初始学期。页面获取服务端学期列表后，`resolvePeriodId` 会优先保留这个仍存在的旧 ID，因此无法随校历自动切换到当前学期。服务端返回的学期已经包含 `is_current` 标记；同时，考试页不应把用户上次查看的历史学期带到下一次进入。

当前生活服务截止文案在小时达到 24 小时后使用 `Math.ceil(hours / 24)`，例如剩余 36 小时会显示为“2 天后截止”。

## Implementation Overview

- 只在考试安排页面引入默认学期选择策略：服务端返回学期后优先取 `isCurrent`，否则取按开始日期排序后的最近学期。
- 每次重新进入考试页时强制同步服务端学期列表并恢复当前学期；学期选择器仍可临时查看历史学期，但不持久化 `examPeriodId`，下次进入不沿用历史选择。
- 保留现有后端接口和 OUC `xnxqid` 契约，不修改成绩、课表、选课的查询行为。
- 将生活服务截止时间在超过一天时显示为“X 天 Y 小时后截止”；整天时显示“X 天后截止”，小于一天的分钟/小时文案保持现有行为。
- 将考试卡片中的考场和座位号拆成两个独立信息行，详情页现有座位信息保持不变。

## Features / Requirements

1. **考试页默认学期**
   - 不再依赖固定的 `2025-2026-2` 作为考试页默认学期。
   - 有 `isCurrent` 学期时优先选择它。
   - 没有 `isCurrent` 学期时选择最近开始的学期。
   - 用户明确选择历史学期后，只在本次页面会话内查看；退出并重新进入考试页时始终恢复服务端当前学期。
   - 兼容旧版本本地存储，但忽略并清空其中的 `examPeriodId`，不恢复历史学期。
   - 重新进入时强制刷新学期列表；请求失败时继续沿用已有校历缓存和现有错误处理逻辑。
   - 学期列表为空时继续沿用现有空状态和错误处理逻辑。

2. **截止倒计时精度**
   - 剩余时间小于 1 小时：显示分钟。
   - 剩余时间小于 1 天：显示小时。
   - 剩余时间为 1 天以上：显示完整天数和剩余小时，例如“1 天 12 小时后截止”。
   - 恰好整天时不显示多余的“0 小时”。
   - 已截止、无效时间和待确认文案保持不变。

3. **考试座位号展示**
   - 考试列表卡片单独展示“座位号”字段。
   - “考场”字段只展示考试地点，不再拼接座位号。
   - 考试详情浮层继续展示完整的座位信息。

## Technical Considerations

- 默认当前学期只针对考试页；历史学期查询仍可在当前会话中使用，但不跨页面进入保存。
- 服务端校历可能同时包含未来学期，因此“当前学期”优先于单纯按开始日期取最新学期。
- 重新进入时使用 `force: true` 绕过客户端学期列表缓存，确保以服务端当前标记为准；网络失败时退回已有校历缓存。
- 倒计时继续基于统一的 `apiDateTimeTimestamp` 处理时区和 API 时间格式。
- 小程序构建使用现有 full/qualification 双版本流程，不引入原生微信 API 依赖。
- 远端同步在本次准备阶段因 SSH、HTTPS 代理均不可用，工作区基于本地已有 `origin/master` 引用创建；实现前需重新确认远端基线是否已更新。

## Testing Requirements

### Unit Tests

- 自动选择当前学期。
- 没有当前学期时回退到最近学期。
- 旧版本本地存有历史 `examPeriodId` 时，进入考试页不恢复该学期。
- 用户手动选择历史学期后离开并重新进入时回到当前学期。
- 36 小时显示为“1 天 12 小时后截止”。
- 24 小时显示为“1 天后截止”。
- 49 小时显示为“2 天 1 小时后截止”。
- 考试卡片单独渲染“座位号”，考场行不再包含座位号。

### Manual Testing Checklist

- 打开考试安排页，默认显示服务端 `is_current` 学期。
- 手动切换到历史学期后，在当前页面可以查看该学期；离开并重新进入后恢复服务端 `is_current` 学期。
- 重新进入页面会重新拉取学期列表，并能跟随服务端当前学期变化。
- 跑腿列表中剩余 36 小时的项目显示为“1 天 12 小时后截止”。
- 小于 1 小时、少于 1 天、整天和已截止场景文案正确。
- full 和 qualification 两个小程序版本均能通过类型检查和构建。

**Implementation Notes:**

本任务假设用户所说的“1.5 天倒计时”指校园跑腿卡片复用的 `relativeDeadline` 截止时间文案；校历页面的开学日倒计时仍按自然日展示，不在本次范围内。用户补充的座位号需求覆盖考试列表卡片，详情浮层同步使用“座位号”标签。
