# OUSea小程序：修复社团页亮色视觉与输入聚焦跳动

**Priority:** High
**Status:** Done
**Type:** Bug
**Created:** 2026-08-17
**Last Updated:** 2026-08-17

## 概述

修复社团广场及社团创建页的三处体验问题：亮色模式下主页 Hero 卡片右侧社团图标不可见；创建页顶部“主页完成度”快捷引导文字与背景对比度不足；点击长表单输入框时页面发生重复跳动，最终没有稳定停留在当前输入位置。

本次保持现有蓝青视觉方向、暗色模式表现、社团数据与提交逻辑不变，只修正主题对比度和键盘避让时序。

## 用户故事

**作为** 浏览社团广场的用户
**我想** 在亮色和暗色模式下都能清楚看到主页视觉图标
**从而** 正确识别页面主题和视觉层级。

**作为** 创建或编辑社团主页的用户
**我想** 看清顶部各资料区块的引导入口，并在点击输入框后稳定停留在当前字段
**从而** 连续填写长表单而不被页面跳动打断。

## 问题描述

### 主页 Hero 图标不可见

社团广场 Hero 固定使用白色描边的 `clubs-white.svg`，但其承载容器在亮色模式下使用近白色的 `--campus-surface-glass`。白色图标与近白背景对比度接近 1:1，因此看起来像图标没有加载。暗色模式下同一变量为深色，所以问题不明显。

### 创建页顶部引导颜色不正确

“基础、形象、图集、介绍”四个快捷项被最终样式覆盖为白色文字，背景仍使用亮色模式下的近白玻璃表面，导致文字几乎不可读。暗色模式下玻璃表面为深色，因此同一规则反而可读。

### 输入聚焦时页面重复跳动

社团编辑页使用共享 `KeyboardSafeInput` 和 `KeyboardSafeTextarea`。共享组件关闭原生 `adjustPosition` 后，在 `onFocus` 与 `onKeyboardHeightChange` 两个事件中都安排手动 `pageScrollTo`。当键盘高度事件晚于首次焦点滚动时，第一次滚动已开始，第二次又基于键盘动画中的瞬态位置重新计算，造成二次跳动和最终落点偏移。

此外，当前异步选择器查询没有请求版本校验；用户快速切换输入框或收起键盘时，上一字段已经发出的查询回调仍可能继续滚动页面。

## 实施方案概览

1. 保留白色社团 SVG，将 Hero 图标承载面改为主题遮罩色或等效的深色半透明背景，确保白色图标在亮色、暗色 Hero 上均可见。
2. 将创建页顶部快捷引导改为主题主色文字搭配主题玻璃表面，亮色下为蓝字浅底，暗色下为浅蓝字深底。
3. 调整共享键盘安全输入组件：微信小程序只由 `onKeyboardHeightChange` 触发可见区域滚动，`onFocus` 继续透传焦点及键盘高度状态，但不重复启动同一轮页面滚动。
4. 为延迟计时、选择器查询和滚动提交增加请求序号或等效失效机制；新键盘事件、失焦和组件卸载会使旧请求失效。
5. 保留非微信平台的焦点事件回退，避免不支持 `onKeyboardHeightChange` 的平台失去键盘避让能力。

## 功能要求

### 社团广场 Hero

1. 亮色模式下白色社团图标清晰可见。
2. 暗色模式下图标与背景继续具有清晰对比度。
3. 不替换或新增图标资源，不改变 Hero 尺寸、布局和蓝青渐变。
4. 图标承载面不得继续使用亮色下近白且与白色图标低对比的背景。

### 创建页顶部引导

1. “基础、形象、图集、介绍”四项在亮色模式下清晰可读。
2. 四项在暗色模式下保持清晰，不新增只服务亮色但破坏暗色的硬编码覆盖。
3. 快捷项点击、滚动到区块和按压反馈保持现有行为。
4. 整体完成度渐变、进度条和完成数量展示不改变。

### 输入与键盘避让

1. 微信小程序同一次键盘打开过程最多触发一轮有效的手动页面滚动。
2. 点击输入框后，目标字段若已位于键盘可见区内，页面不得无谓滚动。
3. 目标字段被键盘遮挡时，页面只滚动到足以完整显示该字段及既定间距的位置。
4. 快速切换输入框、失焦、收起键盘或卸载组件后，旧字段的异步回调不得继续改变页面位置。
5. `onFocus`、`onBlur`、`onKeyboardHeightChange` 和 `onKeyboardVisibilityChange` 的对外回调继续正常透传。
6. 保留 `adjustPosition={false}` 的单一手动避让策略，避免原生上推与业务滚动叠加。
7. 非微信平台保留现有焦点高度回退；不支持键盘高度事件的平台不能因本次修复完全失去避让。
8. 社团搜索框、账号密码、课程编辑等其他共享组件使用方不得出现回归。

## 技术实现

### 视觉修复

Hero 图标继续使用 `clubs-white.svg`，容器背景采用 `--campus-overlay` 或等效深色半透明色，并可保留轻量白色边框。这样不需要在运行时判断主题，也不会让绿色普通图标在暗色背景上失去对比度。

顶部快捷引导使用 `var(--campus-primary)` 作为文字色，背景继续使用 `var(--campus-surface-glass)`。亮色下形成蓝字浅底，暗色 token 自动形成浅蓝字深底。

### 键盘滚动时序

微信小程序中，焦点事件只负责透传状态，稳定的键盘高度变化事件负责触发可见区计算。非微信平台可继续通过焦点事件返回的高度调用回退滚动。

每次键盘事件、失焦或卸载时递增请求序号。延迟回调和 `SelectorQuery.exec` 回调执行前检查自己是否仍为最新请求；过期请求直接退出。新的请求继续清除未执行的旧计时器。

可见区计算仍基于目标控件底部、页面滚动位置、窗口高度、键盘高度和 `keyboardVisibilitySpacing`。只有控件底部超出可见区时才调用 `Taro.pageScrollTo`。

### 设计与可访问性

- 图标和文字在两种主题下保持可识别对比。
- 不通过替换语义、增加闪烁或缩放来表达可点击状态。
- 输入聚焦后保留当前字段和光标上下文，不将用户带离正在填写的位置。

## 验收标准

1. 亮色模式打开社团广场，Hero 右侧白色社团图标清晰显示。
2. 暗色模式打开社团广场，Hero 图标仍清晰且容器不过亮。
3. 亮色模式进入创建社团主页，顶部四个快捷引导文字均清晰可读。
4. 暗色模式下四个快捷引导仍保持清晰。
5. 依次点击社团名称、简称、年份、口号、挂靠单位，页面没有先跳一次再跳第二次。
6. 点击图集说明、社团简介和详细介绍时，页面稳定停留在当前字段，并且字段不被键盘遮挡。
7. 快速切换两个输入框时，前一个字段的旧查询不会把页面拉回。
8. 收起键盘后，已排队的旧滚动不会再次触发。
9. 社团搜索、教务账号密码、资料发布和课程编辑等其他共享输入场景正常聚焦。
10. 社团相关冒烟测试、暗色模式测试、类型检查和微信小程序构建通过。
