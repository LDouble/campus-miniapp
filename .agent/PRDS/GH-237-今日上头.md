# 首页「今日上头」与独立精选页方案（v3）

> Feature GH-237：已确认，正在开发。

- 日期：2026-09-16
- 状态：已确认采用独立精选页；未开始业务开发，数值参数仍为第一版建议值。
- 涉及组件：小程序、后端、管理端。
- 核心目标：让首页用户被具体校园内容吸引，进入独立精选页浏览、参与讨论，看完后自然进入第二个社区 Tab 继续逛。

## 1. 已确认的产品决策

1. 首页使用紧凑轮播入口，不固定只放两三条内容。
2. 内容由后端根据真实浏览、点赞、评论定期选取，不依赖每天人工配置。
3. 列表与详情继续隐藏浏览量；上报和统计保留。热度分值也不对外展示。
4. 参考狐友的入口与连续浏览方式，视觉使用本项目 Ousea 设计体系，不复刻狐友品牌、吉祥物和黄色皮肤。
5. 当前只产出方案；实施、接口定稿、建 Issue、迁移、PR 和部署在方案确认后进行。

## 2. 参考观察与实现边界

实际操作狐友确认：圈子首页为左侧固定标识、右侧自动切换的帖子摘要；点击右侧摘要进入「今日上头」完整帖子流；点击帖子进入详情；返回榜单保留滚动位置。榜单支持向下连续浏览。

未验证其精确轮播间隔、候选数量、后台算法及刷新频率。本文的 5 秒、5 分钟等参数属于我们的建议，不是对狐友实现的判断。

本轮确认调整：完整精选帖子流承载于独立的「今日上头」页面，不嵌入社区 Tab，不在现有社区中增加「大家正在聊 / 最新」排序栏。有限精选与持续更新的社区信息流分别呈现，通过列表结尾的入口衔接。

## 3. 第一版范围

| 包含 | 不包含 |
| --- | --- |
| 首页轮播、独立有限精选页、结尾社区入口 | 恢复浏览量数字展示 |
| 近期热度计算、定时任务、榜单快照与缓存 | Redis 暂存浏览总量再异步刷库 |
| 新帖探索、作者去重、冷启动补位 | 个人兴趣画像、复杂推荐模型 |
| 后台开关、排除、推荐、有效期、手动刷新 | AI 改写标题、AI 生成帖子或评论 |
| 页面漏斗埋点、运行监控、灰度开关 | 热门消息订阅推送、付费竞价排名 |

本期仅收录公开审核通过的校园圈帖子；二手、跑腿等内容不混入候选池。候选必须限制在用户当前可访问的学校/社区范围，不能因为做热榜而扩大内容可见性。

## 4. 首页交互

### 4.1 位置与结构

根据用户补充的线上截图，入口放在「明天」日历卡与「常用服务」之间。常用服务有四排，不应把入口放到长宫格之后才被看到。保留日历、完整服务宫格、原有运营卡和中央发布按钮，不把整段 Feed 搬回首页。

```text
┌──────────────────────────────────────────┐
│ 今日上头 │ 食堂新品到底值不值得排队？       │
│          │ 刚吃完，分量可以，但建议避开…  › │
└──────────────────────────────────────────┘
                      点击整条
                          ↓
独立「今日上头」页面（有明确结尾）
                          ↓
                 精选帖子 → 详情
                 列表结尾 → 去社区看看新动态
```

- 左侧固定模块标识；右侧最多两行真实正文摘要与进入箭头。
- 第一版不展示名次，避免人工推荐、新帖探索与“严格排行榜名次”产生冲突。
- 不展示浏览量、内部得分或没有依据的“爆”“万人在看”等文案。
- 帖子摘要使用现有内容解析器处理话题、提及和表情；纯图帖使用真实配文，没有配文则显示“图片动态”并附缩略图，不凭空编写吸引标题。
- 视觉复用 Ousea 字体、圆角、颜色和暗色模式 Token；减少动态效果时停止自动轮播，仍可手动操作。

### 4.2 轮播规则

| 参数 | 默认建议 | 边界 |
| --- | --- | --- |
| 自动轮播间隔 | 5 秒 | 后台允许 4–10 秒 |
| 首页单次候选池 | 最多 20 条 | 可配置 5–30 条；实际有多少返回多少 |
| 服务端榜单快照 | 最多 100 条 | 分页 20 条；上线按查询成本评估扩容 |
| 手动切换 | 上下滑动 | 正常竖向页面滚动优先，不抢占长距离页面滑动 |
| 自动轮播方向 | 向上 | 仅切换摘要，模块整体高度固定 |

“最多 20 条”是传输和可读性边界，不是内容总量限制；用户无需等完整一轮，点进去即可浏览完整热门流。

- 候选池按榜单切成相邻窗口，同一用户会话保持起始窗口稳定；不同会话可轮换起点，避免尾部内容长期没有机会。
- 仅模块进入可视区域且页面在前台时自动播放；触摸时暂停，手动操作结束后重新计时。
- 仅一条时静态展示，不自动切换；零条时隐藏入口，不展示空白热榜。
- 当前显示条目和点击目标使用同一个 post_id，点击期间冻结轮播，避免打开刚切换的另一条。
- 服务端新版本在重新进入首页或刷新时应用；不突然替换正在阅读/点击的条目。

### 4.3 跳转与上下文

点击模块任意位置进入独立「今日上头」页面。标题和摘要采用一致行为；不直接切第二个 Tab，也不直接跳过精选页进入详情。

使用普通页面导航携带点击 post_id、snapshot_id 与来源；返回键回首页。首页点中的帖子优先作为上下文卡片展示，并从后续列表去重。若点击时帖子已失效，提示「这条动态暂不可见」，保留其他可用精选内容；不泄露不可见正文。

## 5. 独立「今日上头」页面

### 5.1 页面结构

- 顶部为返回键、紧凑标题「今日上头」、微信胶囊；下方一句「看看校园里正在聊什么」。不使用大幅 Banner。
- 独立页没有底部 TabBar、中央发布按钮、业务 Tab、板块筛选或「热门 / 最新」切换，降低有限内容的预期歧义。
- 复用当前朋友圈式帖子卡片与点赞、评论、详情能力。保留蓝色昵称、时间与来源板块、评论预览及操作按钮；继续不显示浏览量、热度分或排名。
- 内容范围为当前授权学校/社区，可跨该范围内的校园圈板块；卡片注明真实来源板块，不继承社区 Tab 之前的关键词或板块筛选。二手、跑腿等内容不混入。

### 5.2 有限内容与翻页

- 一轮快照有明确上限，默认最多 100 条，按 20 条分批加载；实际只有几条就展示几条，不凑数。首页默认轮播最多 20 条仍可配置。
- 加载下一页只是分批获取这轮精选，不无限追加新榜单、不混入最新流。页面不展示无限内容承诺。
- 下拉刷新才获取新快照；翻页固定 snapshot_id，防止后台重排导致重复或跳动。
- 只有服务端确认没有下一页，才显示终点；网络失败显示重试，不能误显示「看完了」。

### 5.3 结尾与继续浏览

列表结束后顺序显示：

> 今天的热门就到这里
> 去社区发现更多新动态
> **去社区看看新动态 ›**

按钮随列表内容滚动，不悬浮遮挡帖子。点击后进入第二个社区 Tab 的现有校园圈最新内容，使用一次性导航意图明确目标业务、排序与授权范围；消费后清除，不影响之后普通切 Tab。避免落入用户上次遗留的闲置业务或旧搜索结果。跳转不应依赖新加的热门模式。

没有任何可展示内容时显示「暂时没有精选动态」和同一社区入口；首页没有候选时隐藏轮播。空榜不能显示「热门就到这里」，防止误解为已读完。

### 5.4 返回与状态

- 精选页进入详情后返回，保留精选列表、快照和滚动位置，仅同步真实互动变化。
- 从精选页返回首页，保留首页滚动位置及轮播上下文。
- 页面在后台不刷新列表、不自动重排；重新进入时按快照有效期处理，过期明确允许刷新。
- 社区页面的现有业务 Tab、板块筛选、帖子样式与底部导航保持原有结构，不新增排序栏。

## 6. 候选与排序规则

### 6.1 候选范围

默认取最近 72 小时公开审核通过且已发布的帖子。剔除删除、撤回、审核不通过、禁用范围内内容、运营排除项；按现有用户可见性和拉黑规则做最终过滤。

内容不足时可把新鲜内容补位范围放宽至最近 7 天；没有有效互动的补位内容可标记「新鲜发布」，不标注虚构热度。人工推荐也必须满足公开可见性，不得把私有/审核中帖子带上榜。

### 6.2 近期信号

优先用近期新增行为，不能直接按历史累计总量降序：

- V：最近 24 小时新增、已通过当前去重规则的有效浏览次数。它是有效浏览次数，不是独立人数；同一读者超过去重窗口再次阅读仍可能计数。
- L：最近 24 小时产生且目前仍有效的点赞用户数，作者自身不参与。
- C：最近 24 小时公开可见的有效评论的独立用户数，作者自身与已删除/不可见评论不参与；同一人反复评论只计一个参与者。
- 新鲜度：以帖子发布时间为主要衰减基准，旧帖不靠长期累计优势占榜。

### 6.3 第一版评分建议

```text
互动分 = 0.5 × ln(1 + V) + 3 × ln(1 + L) + 5 × ln(1 + C)
热度分 = 互动分 × 2 ^ (-发布后小时数 / 24)
```

这是可解释、可调参的初始规则，不是经过数据验证的最佳权重。对数压缩浏览量的大数量级优势，评论参与者权重高于点赞，浏览仅作为辅助。

每轮发布后记录算法版本、信号窗口和汇总贡献，后台可解释某帖子为什么被选中。不向普通用户暴露得分。

### 6.4 多样性和反馈循环

默认每 10 个位置安排约 8 个热度候选、2 个新帖探索；不足时相互补位。同一帖子只出现一次，同一作者不连续出现、前 20 条默认最多 2 条，避免刷屏；候选不足时缩短列表。

新帖探索优先最近 24 小时、未被反复展示的合格帖子；以快照/时间段为种子做稳定轮换，不随每次请求随机抖动。运营推荐优先参与展示，但前 20 条最多 2 个明确推荐位，与作者限制和可见性共同生效。

首页摘要模块的展示只算模块曝光，不计帖子有效阅读，也不参与 V。进入完整帖子流并满足原有效曝光阈值后才计浏览。该规则能避免轮播本身给自己“刷热度”；完整 Feed 仍可能产生正反馈，因此还需要低浏览权重和新帖探索。

## 7. 数据与定时生成

### 7.1 当前能力和缺口

已完成的浏览量能力提供累计阅读数、列表/详情共享去重、批量上报和同步 MySQL 更新。PR 已确认合并，但合并不代表已经部署。

- [后端 PR #261](https://github.com/LDouble/backend_demo/pull/261)，契约提交 `92fe8050b52be9894b7e156fea9fa2709ea562b7`。
- [小程序 PR #177](https://github.com/LDouble/campus-miniapp/pull/177)，隐藏展示提交 `ccf1d45f79812ea5962fb24d0f7e80e8cb2dce0f`。
- 当前浏览指标仅保存累计 view_count，不足以还原任意过去 24 小时的增长。
- 已有推荐/精选字段可复用部分运营入口，但现有 recommended 排序不是自动近期热榜，不能直接换个标题当作实现完成。

### 7.2 浏览增量采集

第一版推荐由 5 分钟定时任务批量采样候选帖的累计浏览量，保存 `(post_id, observed_at, view_count)`；同一帖子/时间槽唯一，任务重试幂等。计数成功上报仍保持原来的同步 MySQL 事务，不为了热榜再给每次上报增加分桶写入。

- V 使用最新采样值减去约 24 小时前的有效采样值，记录真实起止时间；这是采样窗口增量，正常误差约一个采样周期，不宣称精确实时滚动窗口。
- 基准时点缺失时使用窗口内最早有效采样，标记观察窗口不足 24 小时；只有一个样本时 V=0，依赖点赞、评论和新帖补位。不得将第一次观测到的历史总量全部算作近期增长。
- 两次采样之间任务短暂失败，下一次累计差值仍包含间隔内增长；长时间中断导致观察区间不足时显示预热/降级状态，不按每分钟外推制造增长。
- 累计值意外回退时本轮增量按 0 处理并告警，不产生负热度；重置基线等待后续样本。
- 仅采样候选窗口及有效运营推荐中的帖子；指标样本保留 72 小时，按批次清理。扫描近期候选和插入采样需批处理，评估候选规模和写入成本，不扫描全站历史帖子。
- 新发布帖子优先使用发布后的最早样本；缺失首个采样之前的少量增长可以接受，规则必须一致且可解释。

备选方案是把小时/分钟增量桶与累计浏览量放在同一事务更新，更适合以后要求更精确时间窗口的场景，但会增加当前上报写入量。本期先使用采样，保留后续替换信号提供器的边界。

点赞可查询最近 24 小时创建且仍存在的点赞记录；这表示近期仍有效的点赞用户，不代表历史点赞事件总数。评论以 `reviewed_at`（缺失时回退 `created_at`）为可见时间，并沿用现有 approved 且根评论链可见的规则，按 author_id 去重。需评估新增组合索引，避免用无时间索引的全表聚合支撑定时任务。

### 7.3 定时任务

复用现有 `cmd/worker/main.go` 的 `runPeriodic` 模式新增热榜任务，不为这件事另引第三方 cron。每 5 分钟对每个启用范围执行：

1. 获取带租约的分布式锁；多副本只允许一个有效发布者，运行超时有监控和安全退出。
2. 读取候选、批量采样累计浏览量，并按范围批量聚合 V/L/C，不逐帖 N+1 查询，不在用户首页请求内计算。
3. 应用排除、评分、多样性和推荐规则，生成新 snapshot_id、算法版本、截止时间。
4. 写入不可变榜单快照，完成后原子切换当前版本指针；只允许更新的运行版本发布，防止过期锁持有者覆盖新结果。
5. 更新 Redis 读取缓存；失败保留上一次完整榜单，不先清空线上结果。

手动刷新走相同任务入口并合并重复请求；推荐/排除操作不等待用户访问才生效。

### 7.4 一致性与故障

- 榜单仅存候选 ID 和排序元数据。接口组装卡片前再次执行真实可见性检查，不能仅信任 5 分钟前的快照。
- 审核/撤回事件尽力主动移除缓存项；读时检查作为兜底。旧快照中的不可见帖子同样不得返回。
- Redis 不可用时读取持久化的最近有效快照；不在读请求里全量重算。
- 同一分页会话使用固定快照，建议保留 60 分钟；游标过期明确要求刷新，不悄悄切榜导致重排。
- 自动更新超过 15 分钟未成功触发运维告警，仍可返回过滤后的旧快照；超过 60 分钟无有效结果则隐藏首页入口，独立页提供重试及「去社区看看新动态」降级入口。
- 资格版/功能开关关闭时不请求、不展示、不轮播相关模块。

## 8. 接口与管理端草案

以下为待实现契约，不代表已有 API；正式定义在后端 schemas/campus_circle.yaml，经生成器派生 OpenAPI、权限和客户端。

| 能力 | 请求/响应要点 |
| --- | --- |
| 首页轮播读取 | 请求授权范围；返回 enabled、snapshot_id、generated_at、轮播间隔、items；每项含 post_id、真实摘要、可选缩略图 |
| 独立精选帖子流 | snapshot_id、cursor、size；返回现有帖子 DTO、next_cursor、generated_at；服务端再次过滤可见性 |
| 后台配置 | 开关、轮播数量/间隔、算法权重、时间窗口、新帖比例；范围校验、版本并发控制、审计 |
| 后台运营 | 推荐/排除、原因、开始/结束时间、撤销；现有 curation 能力可复用部分，避免重复造入口 |
| 运行状态 | 上次成功/失败时间、当前版本、候选数、信号预热、单次耗时、失败原因、手动刷新 |

第一版推荐数量 20、间隔 5 秒、任务间隔 5 分钟采用安全默认值；参数管理范围应约束在可承受区间，不开放任意 SQL、公式执行或无限候选数。

## 9. 效果评估

新增独立模块埋点，避免复用帖子阅读接口混淆数据。事件携带版本、来源、post_id（适用时）和幂等事件 ID，不记录原始访问令牌或完整帖子正文。

| 指标 | 定义 |
| --- | --- |
| 模块点击率 | 日内点击模块的去重访问会话数 / 日内看见模块的去重访问会话数 |
| 精选页到达率 | 到达独立精选页的会话数 / 点击模块的会话数 |
| 连续浏览率 | 到达独立精选页后 10 分钟内有效曝光至少 3 个不同帖子的会话数 / 到达会话数 |
| 互动转化率 | 到达独立精选页后 10 分钟内成功点赞或评论的会话数 / 到达会话数 |
| 社区继续浏览率 | 精选页进入会话中，在当次访问内点击结尾入口且成功到达社区的会话数 / 精选页进入会话数；另单独记录结尾按钮点击率 |
| 内容多样性 | 每日得到有效曝光的帖子数、作者数及前 10 帖曝光占比 |
| 护栏 | 首页性能、上报失败率、榜单更新延迟、无效内容率、投诉/审核反馈 |

“看见模块”可定义为至少 50% 可见并持续 1 秒，但只发模块事件。它不意味着轮播中的帖子被完整阅读。

先获取 7 天基线/试运行数据；流量允许时按稳定分组比较有入口与无入口的版本。不在没有样本时承诺增长比例；以点击后继续浏览和互动为主要收益，同时监控作者和内容是否过度集中。

## 10. 验收标准

- 首页只占固定横栏高度；0/1/多条、超长文本、纯图、暗色、减少动态效果均有明确行为。
- 自动/手动切换与点击竞争时始终打开点击时的上下文；不可见页面无轮播计时活动。
- 点击模块进入独立精选页；返回首页、详情返回精选页均保留位置；列表结束后的按钮进入社区最新内容，普通切 Tab 不重复消费旧跳转。
- 仅 has_more=false 时显示结尾，禁止自动拼接下一轮；点击结尾按钮进入现有社区流。
- 列表和详情没有浏览量数字；完整帖子曝光/详情上报回归仍通过。
- 轮播摘要曝光不会增加帖子阅读量；同一读者的列表和详情继续共享去重。
- 构造高浏览低互动、低浏览多人讨论、新帖、旧帖等数据，排序可解释且稳定；作者自身互动不加权。
- 取消点赞、删除评论、撤回帖子不会继续贡献不该展示的互动/内容；同一用户多条评论不放大参与人数。
- 任务并发、失败重试、锁过期、旧运行迟到、缓存故障都不会发布半成品或覆盖新快照。
- 翻页期间新榜发布不引起重复/跳动；过期游标、隐藏帖、空榜和预热均有测试。
- 后台推荐有有效期、排除优先于推荐、不可见优先于所有运营配置；操作记录可审计。
- 完成源契约生成检查、迁移检查、相关后端/小程序/管理端测试及本地真实联调，再按各仓库 CI 规则发布。

## 11. 实施顺序与评审点

1. 后端先确定时间窗口和点赞/评论记录语义，补指标采样、榜单快照、任务、接口与灰度开关。
2. 后端契约稳定后，小程序轮播/独立页面和管理端运营页面可独立并行。
3. 先部署采集和生成但不展示入口，验证预热数据、执行成本、撤回与缓存一致性。
4. 打开内部灰度，确认真实请求、上报和漏斗指标；再逐步开放首页入口。

作为独立 Feature 创建新的 Issue 与工作区，不继续向已合并的阅读量 PR 追加。按需要只创建 backend、miniapp、admin 三端；实施前重新同步各默认分支并核对现有首页、Tab 和数据模型变化。

待评审的主要建议值：5 秒轮播、首页 20 条候选、完整榜单最多 100 条、5 分钟重算、72 小时主候选、24 小时信号、8:2 热度/新帖混排。用户未修改时，这些值可作为第一版实施基线；调参不应依赖重新发布小程序。
