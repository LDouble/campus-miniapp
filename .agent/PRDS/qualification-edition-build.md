# 海大校园小程序：个人资格版双产物构建与新版迁移入口

**Priority:** High
**Status:** Implemented
**Type:** Enhancement
**Created:** 2026-08-09
**Last Updated:** 2026-08-09

## 一、概述

项目历史上使用个人主体小程序提供教务和校园工具。社区、二手、跑腿、拼车、课程资料分享、社团编辑等用户发布、互动和交易能力需要迁移至新的完整版本小程序。当前工程只有一个微信构建命令和一个 `dist` 目录，所有页面均进入同一个主包，运行时模块开关只能隐藏入口，不能证明个人资格版产物中不存在相关能力。

本任务在不修改后端的前提下，为同一代码库增加 `full` 与 `qualification` 两种编译版本。完整版本保留现有功能；个人资格版在构建期裁剪 UGC 页面、数据请求、写入口和相关 Tab，并提供克制、透明、由用户主动触发的新版小程序迁移入口。

## 二、用户故事

**作为** 继续使用原个人主体小程序的校园用户
**我想** 正常使用课表、成绩、考试、校历、校车和空教室等基础功能，同时知道校园生活功能已迁移
**从而** 可以在需要时主动打开新版小程序，且不会在旧小程序中接触不可提供的发布和互动能力。

**作为** 发布维护人员
**我想** 从同一代码库稳定构建两个目录和两个 AppID 对应的产物
**从而** 避免资格版与完整版页面、资源和配置相互污染。

## 三、范围与边界

### 3.1 本任务包含

- 增加 `full`、`qualification` 编译版本及类型安全的版本常量。
- 产物分别输出到 `dist/full`、`dist/qualification`。
- 两个版本分别使用自己的当前小程序 AppID；资格版额外配置新版目标 AppID。
- 资格版移除社区 Tab，以及社区、二手、跑腿、拼车、课程资料和社团相关页面。
- 资格版不请求上述模块的数据，也不包含发布、评论、点赞、上传、接单、交易响应、加入拼车等入口。
- 首页增加静态的“校园生活服务已迁移”卡片。
- 增加统一的跨小程序跳转封装和静态迁移承接页。
- 用户必须点击按钮后才能调用 `Taro.navigateToMiniProgram`；不自动跳转、不启动弹窗。
- 增加构建产物检查，防止资格版包含受限页面、Tab、AppID 错配或关键写接口路径。
- 保持 `full` 版本现有功能和页面路径不变。

### 3.2 本任务不包含

- 不修改后端接口、登录协议或权限模型。
- 不为旧 AppID 增加服务端写操作限制。
- 不修改新版小程序的业务页面；只约定其接收路径和参数格式。
- 不通过 WebView、二维码、口令、微信号或外部网址绕过小程序跳转。
- 不采用审核期间隐藏、上线后通过远程配置恢复功能的方案。

### 3.3 资格版保留能力

- 首页教务概览。
- 校园身份认证与登录。
- 课表、成绩、考试、选课结果、统计和校历。
- 校车、空教室及其他不包含公开用户内容的校园工具。
- 消息、个人中心、隐私协议和账号注销；其中指向已迁移业务的入口改为迁移提示。

## 四、产品与交互要求

### 4.1 首页迁移卡片

- 标题：`校园生活服务已迁移`。
- 说明：`校园社区、闲置互助、课程资料与社团服务，现已在「海大校园新版」提供。`
- 主按钮：`查看新版服务`，先进入静态迁移承接页，再由用户点击 `打开新版小程序`。
- 辅助说明：`将在微信中打开另一小程序`。
- 卡片不得展示真实帖子、商品、评论、用户头像或交易数据。
- 卡片不得成为启动弹窗、全屏遮罩或反复出现的悬浮按钮。

### 4.2 迁移承接页

- 从资格版残余入口进入时展示与首页一致的迁移说明。
- 根据来源模块映射新版目标路径，并在 `extraData` 中携带 `source=qualification` 和模块标识。
- 用户点击后才跳转；失败时留在当前页并显示可理解的错误提示。
- 目标 AppID 未配置时明确提示构建配置缺失，不尝试无效跳转。

### 4.3 导航规则

- `full` Tab：保持首页、社区、消息、我的。
- `qualification` Tab：首页、消息、我的。
- 两个版本的 `app.config` 与自定义 TabBar 列表必须完全一致。
- 资格版所有内部 UGC 入口统一调用迁移导航，不得先打开被裁剪页面。

## 五、技术方案

### 5.1 构建版本

- 在 Taro 构建配置读取 `TARO_APP_EDITION`，只接受 `full` 或 `qualification`。
- 根据版本生成独立 `outputRoot`。
- 通过 `defineConstants` 注入当前版本、目标小程序 AppID、目标默认路径和构建 release。
- 使用 `TARO_APP_ID` 生成对应微信项目 AppID；`TARO_APP_WECHAT_APP_ID` 必须与其一致。
- 新增版本化 npm scripts，不移除现有通用构建命令。

### 5.2 页面与代码裁剪

- `src/app.config.ts` 按编译版本生成页面列表、TabBar 和 `navigateToMiniProgramAppIdList`。
- 资格版页面清单不注册社区详情、生活服务详情、发布中心、我的服务、课程资料、内容举报、社团列表/详情/编辑/管理页面。
- 对首页、消息、个人中心及教务页面中的迁移入口使用编译常量生成资格版分支。
- 受限模块实现应拆到仅由 `full` 分支引用的模块中，使生产构建能够删除资格版不可达代码。
- 资格版构建完成后扫描 `app.json`、TabBar 和关键接口字符串，验证裁剪实际生效。

### 5.3 跨小程序跳转

- 使用 `Taro.navigateToMiniProgram`，参数包括目标 `appId`、业务 `path`、环境版本和来源信息。
- 正式版固定打开目标正式版；开发版和体验版允许通过非生产配置选择目标版本。
- 资格版 `app.config` 声明 `navigateToMiniProgramAppIdList`，且仅包含已配置的新版 AppID。
- 跳转必须由点击事件直接触发，不能在 `useLoad`、`useDidShow` 或启动生命周期中自动执行。

### 5.4 运行时模块配置

- 现有运行时模块配置继续用于 `full` 版本的维护、隐藏和灰度。
- `qualification` 的禁用集合由编译版本强制决定，运行时配置不得重新启用受限模块。

## 六、拟新增文件

- `src/features/app-edition/index.ts`：编译版本、资格版能力策略和类型定义。
- `src/features/app-edition/navigation.ts`：新版目标路径映射与跨小程序跳转封装。
- `src/pages/feature-migrated/index.tsx`：静态迁移承接页。
- `src/pages/feature-migrated/index.config.ts`：迁移页导航配置。
- `src/pages/feature-migrated/index.scss`：迁移页样式。
- `scripts/qualification-build-smoke.ts`：资格版产物静态检查。

## 七、拟修改文件

- `package.json`：增加两个构建命令和资格版产物检查命令。
- `config/index.ts`：读取编译版本、设置独立输出目录并注入构建常量。
- `src/types/build-constants.d.ts`：声明版本和目标小程序编译常量。
- `src/app.config.ts`：生成版本化页面、TabBar 和跳转名单。
- `src/app.ts`：资格版残余模块导航采用编译期强制策略。
- `src/custom-tab-bar/index.js`：生成与版本匹配的 Tab 列表并移除资格版发布入口。
- `src/utils/tabbar.ts`：按 Tab 标识解析版本化索引。
- `src/pages/index/index.tsx`：资格版不加载生活服务数据并展示迁移卡片。
- `src/pages/messages/index.tsx`：资格版消息中的相关资源进入迁移页。
- `src/pages/profile/index.tsx`：资格版隐藏或迁移发布、资料、接单、订单和拼车入口。
- 相关教务页面：资格版“分享资料”等入口进入迁移页。

具体文件列表可在实施中根据拆分结果收敛，但不得扩大到后端仓库。

## 八、依赖与文档依据

- Taro 4.1.11：使用现有锁定版本，不新增框架依赖。
- Taro `defineConfig`、`defineConstants`、`outputRoot` 和微信项目配置生成机制。
- Taro `navigateToMiniProgram`：跳转需要用户主动触发，目标参数包括 `appId`、`path`、`extraData` 和 `envVersion`。
- 微信小程序全局配置：目标 AppID 必须声明在 `navigateToMiniProgramAppIdList`，数量不得超过十个。

已通过 Context7 查询 `/nervjs/taro-docs` 的跨小程序导航与微信项目配置文档；实施以仓库锁定的 Taro 类型定义和构建行为为最终校验依据。

## 九、测试要求

### 9.1 单元与烟雾测试

- 版本解析只接受 `full`、`qualification`，非法值构建失败。
- 新版模块到目标路径的映射正确。
- 目标 AppID 缺失时不调用跳转 API。
- 跳转失败能够展示错误提示。

### 9.2 产物测试

- `dist/full/app.json` 保持现有页面和社区 Tab。
- `dist/qualification/app.json` 不包含受限页面和社区 Tab。
- 两个产物的 `project.config.json` AppID 与各自环境变量一致。
- 资格版声明且只声明新版目标 AppID。
- 资格版产物不包含发布、评论、资料上传、社团编辑等关键写接口路径。
- 先后构建两个版本不会互相残留页面或资源。

### 9.3 回归测试

- `yarn typecheck` 通过。
- `yarn lint` 通过。
- 现有烟雾测试通过。
- `full` 微信生产构建通过。
- `qualification` 微信生产构建和资格版产物检查通过。
- `git diff --check` 通过。

### 9.4 手工检查

- 资格版首页核心教务服务正常。
- 资格版迁移卡片不展示真实 UGC。
- 点击迁移按钮出现微信跨小程序确认流程。
- 取消或跳转失败后旧小程序仍可继续使用。
- 资格版 Tab、消息和个人中心没有进入受限页面的路径。
- 完整版社区、发布、资料和社团功能无回归。

## 十、风险与取舍

- 不做后端权限兜底，因此旧客户端或脱离当前前端的请求理论上仍可调用原写接口；这是本任务明确接受的边界。
- 构建期裁剪优先于保留全部历史深链。无法安全保留的旧 UGC 页面路径可能由微信回退首页或提示页面不存在，内部可控入口必须全部迁移。
- 如果受限实现仍被共享模块静态引用，可能进入资格版 bundle；必须依靠模块拆分和产物扫描验证，而不是只看 UI。
- 新版 AppID、名称和目标路径属于发布参数，不写死真实生产值到源码。

## 十一、完成标准

- 两个构建命令稳定产出两个独立目录。
- 资格版具备完整基础校园工具价值，并有一个克制、用户主动触发的新版入口。
- 资格版页面配置、Tab、网络请求和最终 bundle 均不包含约定的 UGC 能力。
- 完整版行为保持不变。
- 所有自动化验证通过，并形成可重复的发布命令说明。
