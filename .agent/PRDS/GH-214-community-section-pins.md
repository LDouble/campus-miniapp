# 跨端：社区帖子分版块置顶

**Priority:** High
**Status:** Done
**Type:** Enhancement
**Created:** 2026-09-08
**Last Updated:** 2026-09-08

## Overview

让社区帖子置顶在小程序公共列表中真实生效，并将置顶语义明确为“帖子仅在其所属版块内置顶，且每个版块同一时间最多一个有效置顶帖”。除管理端外，具备独立置顶权限的用户也能直接在小程序置顶或取消置顶；后端负责权限、单置顶并发约束和默认列表排序。

## User Story

**As a** 社区运营人员
**I want** 按版块筛选帖子，并在管理端或小程序中对所属版块设置、替换和取消置顶
**So that** 不同版块可以独立维护重点内容，用户在小程序中能优先看到对应版块的置顶帖。

## Context

管理端现有运营接口会写入帖子的 `pinned_at`、`pinned_until` 和 `sort_order`，公共响应也会正确返回 `is_pinned`。但小程序社区列表没有显式传递运营排序，后端又把缺省排序解释为 `latest`；该查询当前仅按发布时间和 ID 倒序，因此会出现卡片带“置顶”标签但位置没有置顶的现象。

帖子当前只属于一个 `section_id`，版块为两层父子结构。为保持兼容和控制范围，本需求不引入跨版块投放模型：一条帖子只能在其所属版块置顶；每个版块同一时间最多一个有效置顶帖；父版块聚合列表包含启用子版块时，各子版块的有效置顶帖仍可同时进入聚合列表置顶区域。

现有管理端 `curation` 接口还允许修改精选、推荐和运营权重，不能直接开放给小程序。新增小程序可用的窄置顶接口和独立权限码，仅允许改变置顶状态；前端可见性由服务端下发的帖子操作能力决定，服务端在执行时再次鉴权。

## Implementation Overview

- 后端在应用版块过滤后，为默认 `latest` 列表增加“有效置顶优先”排序；非置顶内容仍按发布时间和 ID 倒序。
- `curated` 继续保留推荐、精选和运营权重等既有综合排序语义，不用它替代普通最新列表。
- 后端处理 `pinned_until` 与公共列表缓存的边界，避免到期置顶在缓存 TTL 内继续显示为有效。
- 后端在同一事务内锁定版块置顶范围；设置新置顶时自动取消该版块尚未到期的旧置顶，保证并发请求下仍最多一个有效置顶帖。
- 小程序显式提交社区列表的排序意图，并保持根版块使用 `parent_section_id`、子版块使用 `section_id`；列表按服务端顺序渲染，不在单页客户端重排分页结果。
- 后端新增仅能置顶或取消置顶的认证接口与 `campus_circle:pin_post` 权限；该权限不授予默认 member，只进入权限目录供管理员手动配置到权限组；帖子 `available_actions` 只向具备权限的查看者返回 `pin` 或 `unpin`。
- 小程序在帖子更多操作中消费 `pin/unpin` capability，成功后刷新详情和当前版块第一页；权限回收、版本冲突或网络失败时不做乐观成功展示。
- 管理端复用现有版块树，为帖子列表增加版块筛选、版块名称展示，并在运营弹窗中明确“置顶于所属版块”。

## Features / Requirements

1. **默认列表置顶生效**
   - 未传 `sort` 或使用 `latest` 时，有效置顶帖子排在普通帖子之前。
   - 普通帖子继续按 `created_at DESC, id DESC` 排序。
   - 多个有效置顶按现有 `sort_order` 及稳定的时间、ID 规则排序。

2. **按版块隔离**
   - A 版块帖子只能影响 A 版块列表，不能进入或影响 B 版块列表。
   - 每个版块同一时间最多一个有效置顶帖，不同版块可以分别拥有一个有效置顶帖。
   - 设置新置顶时自动取消同版块旧置顶；取消动作与新置顶写入必须位于同一事务。
   - 并发置顶同一版块的不同帖子时，最终只能有一个有效置顶；失败请求不得留下部分更新。
   - 父版块聚合查询包含父版块自身及启用子版块；范围内的有效置顶统一位于聚合列表前部。
   - 不允许管理员把帖子置顶到帖子所属版块之外。

3. **到期和缓存一致性**
   - `pinned_until` 到期后，帖子自动恢复普通排序并返回 `is_pinned=false`。
   - 置顶、取消置顶和调整顺序继续触发现有缓存失效。
   - 列表缓存不得让已到期置顶持续到完整缓存 TTL；缓存有效期应截断到最近的置顶到期时间，或采用等价的正确性方案。

4. **小程序列表行为**
   - 根版块、子版块、刷新和翻页均使用一致的服务端排序。
   - 卡片继续展示有效置顶标签；`is_pinned` 缺失时按 `false` 处理。
   - 不在客户端跨页重排，避免分页重复或漏项。
   - 关键词搜索保持相关性排序，不强插运营置顶。

5. **小程序权限操作**
   - 新增独立的 `campus_circle:pin_post` 权限，不复用或开放完整的管理端 `curation` 能力。
   - `campus_circle:pin_post` 不加入 member 基础角色权限，管理员只能通过现有权限管理将其手动授予指定权限组，再把用户加入对应权限组。
   - 服务端仅向具备权限的查看者返回 `pin` 或 `unpin` 操作；无权限用户、匿名用户和仅为帖子作者的用户不显示入口。
   - 未置顶帖子显示“置顶到本版块”，已置顶帖子显示“取消本版块置顶”，操作前展示明确的确认文案。
   - 列表卡片与帖子详情的更多菜单使用同一能力判断和操作逻辑。
   - 后端在请求执行时实时鉴权；即使前端被篡改或权限刚被收回，也必须返回 403 且不改变数据。
   - 成功后使用服务端返回的帖子版本更新详情，并重新加载当前版块第一页，不能在客户端直接跨页换序。
   - 409 时重新加载最新帖子并提示状态已变化；403 时重新加载以移除失效入口；网络失败保持原状态。

6. **管理端版块运营**
   - 帖子列表支持按版块筛选。
   - 表格与详情展示版块名称，并可附带版块 ID 便于排查。
   - 置顶弹窗明确当前操作作用于帖子所属版块，不新增可选择多个版块的控件。

## Files to Modify

- 后端 `internal/modules/campus_circle/infrastructure/store.go` 及相关测试 - 在版块过滤后的最新列表中增加有效置顶优先排序。
- 后端 `internal/modules/campus_circle/application/manager.go` 及相关测试 - 处理置顶到期与缓存有效期边界。
- 后端 `schemas/campus_circle.yaml`、Handler、领域操作能力和生成产物 - 增加窄置顶接口、权限码及 `pin/unpin` capability。
- 小程序 `src/features/community/feed-panel.tsx`、`post-card.tsx`、`src/pages/community/detail.tsx`、repository 及相关测试 - 提交列表排序并实现有权限的置顶/取消置顶操作。
- 管理端 `apps/web-antd/src/views/admin/campus-circle-posts.vue` 及相关测试 - 增加版块树加载、筛选、名称展示和作用域文案。
- 管理端已有社区运营模型 - 仅在需要适配页面状态时修改，不手工修改生成客户端。

## API Endpoints

- `GET /api/v1/campus-circle/posts` - 不新增字段；兼容调整缺省或 `latest` 排序，使有效置顶优先。
- `PATCH /api/v1/campus-circle/posts/{id}/pin` - 新增认证接口；请求只包含 `expected_version` 与 `pinned`，强制 `Idempotency-Key`，返回更新后的帖子。
- `GET /api/v1/admin/campus-circle/posts` - 复用已有 `section_id` 查询参数。
- `PATCH /api/v1/admin/campus-circle/posts/{id}/curation` - 复用已有 `pinned`、`pinned_until`、`sort_order` 和 `expected_version`。

## Database Changes

不新增表、不新增字段、不创建迁移。现有帖子级置顶字段与单一 `section_id` 足以表达“在所属版块置顶”。设置新置顶时，事务先锁定所属版块行作为并发串行化边界，再取消同版块旧置顶并更新目标帖子；管理端和小程序入口必须复用同一存储规则。

## Libraries / Dependencies

不新增第三方依赖；复用现有 Go、Taro/React 和 Vue/Ant Design Vue 能力。此次改动不依赖新的外部库 API，因此无需引入新的库文档或升级。

## Technical Considerations

- 排序必须在数据库分页之前完成，不能对已分页结果做客户端前置排序。
- “每版块最多一个有效置顶”必须由服务端事务和版块行锁保障，不能依赖客户端先取消再置顶的两次请求，也不能只锁目标帖子。
- 有效置顶条件需同时覆盖已置顶、未到期和永久置顶。
- 父版块聚合查询必须沿用现有启用子版块边界，不能越权或跨版块扩大结果集。
- 缓存键已包含查询参数；仍需确保时间驱动的 `pinned_until` 到期不会被旧缓存掩盖。
- 本需求不改变 `featured`、`recommended` 或 `curated` 的含义。
- 小程序接口不能接受 `featured`、`recommended` 或 `sort_order`，避免置顶权限被扩大为完整运营权限。

## Testing Requirements

### Unit / Integration Tests

- 后端覆盖 `latest` 的有效置顶、永久置顶、过期置顶、取消置顶、多个置顶稳定排序。
- 后端覆盖同版块替换置顶以及两个并发置顶请求，断言最终最多一个有效置顶且无部分写入。
- 后端覆盖无权限 403、幂等重放、陈旧版本 409，并断言窄接口不会修改精选、推荐或运营权重。
- 后端覆盖普通 member 默认无权、权限组授权后可操作、撤销权限或移出权限组后立即返回 403。
- 后端覆盖 `section_id` 与 `parent_section_id` 的隔离和父子聚合。
- 后端覆盖到期时间早于默认缓存 TTL 时的缓存行为。
- 小程序覆盖根版块、子版块请求参数、排序参数、刷新和分页结果透传。
- 小程序覆盖无 capability 时隐藏入口、`pin/unpin` 菜单切换、确认操作、成功刷新、403/409/网络失败处理。
- 管理端覆盖版块筛选参数、名称映射和运营弹窗作用域文案。

### Manual Testing

- 在管理端筛选 A 版块并置顶一条帖子，小程序 A 版块第一页首位出现该帖。
- 在 A 版块置顶第二条帖子，确认第一条自动取消置顶，且小程序只展示第二条为置顶。
- 将 `campus_circle:pin_post` 手动授予测试权限组并把测试用户加入该组后，确认可在小程序列表和详情置顶、取消置顶；撤销权限或移出权限组后入口消失且直接请求返回 403。
- 切换 B 版块后不出现 A 版块帖子，B 版块原有顺序不受影响。
- 在父版块聚合页确认启用子版块的有效置顶进入置顶区。
- 取消置顶或等待短时置顶到期，确认帖子恢复普通排序且标签消失。
- 连续刷新和翻页，确认无重复、漏项或顺序抖动。

## Acceptance Criteria

- 管理端已置顶帖子在对应小程序版块列表中稳定优先展示。
- A、B 版块的置顶运营相互隔离。
- 每个版块同一时间最多一个有效置顶帖；同版块替换和并发置顶保持原子性。
- 具备 `campus_circle:pin_post` 权限的用户可在小程序操作，无权限用户看不到入口且无法绕过服务端鉴权。
- 默认 member 不具备置顶权限，只有管理员手动授权的权限组成员可以操作。
- 父版块聚合行为符合本 PRD 定义。
- 永久、限时、取消置顶和缓存行为均正确。
- 管理端可按版块筛选并显示可读版块名称。
- 后端目标包测试、生成与迁移检查，小程序 lint/typecheck/build，管理端 typecheck/test/build 及各端 `git diff --check` 通过。

## Non-goals

- 同一帖子置顶到多个非所属版块。
- 为不同版块分别保存同一帖子的到期时间或权重。
- 在小程序修改精选、推荐、运营权重或限时置顶截止时间。
- 重构社区卡片视觉或搜索排序。
- 修改现有推荐、精选和综合运营排序策略。

## Risks / Considerations

- 如果未来需要跨版块投放，应新增以 `post_id + section_id` 唯一约束的置顶关系，而不是扩展当前单一布尔字段。
- 默认 `latest` 语义将从“纯发布时间倒序”变为“有效置顶优先，其余最新”，属于有意的兼容行为调整，需要回归所有公共列表调用方。
- 父版块聚合可能同时出现多个子版块置顶；稳定排序规则必须明确，避免分页顺序抖动。
- 应锁定所属版块行作为稳定的事务互斥点；仅锁目标帖子或先查询再更新，会在两个不同帖子并发置顶时违反单置顶约束。
- 当前 Casbin 权限按接口路径和方法授予，不包含版块维度；本期 `campus_circle:pin_post` 对获授权角色适用于所有版块。若未来要求“某用户只能运营指定版块”，需另建版块管理员关系。
- 权限目录生成时不得把 `campus_circle:pin_post` 标记为 member 默认权限，避免权限同步过程误授予全体成员。
