# 小程序：统一发布器体验重设计

**Priority:** High  
**Status:** Implemented (Pending Review)  
**Type:** Enhancement  
**Created:** 2026-08-30  
**Last Updated:** 2026-08-30

## Overview

重设计小程序统一发布页 `/pages/publish`。页面目前同时承载动态、跑腿、二手和找同行四种发布流程，功能完整，但页面由多层卡片、连续字段和固定底部操作区组成，业务类型、正文编辑、业务字段和提交状态的视觉层级不够清楚，长表单操作显得拥挤。

本次只优化小程序端的视觉与交互表达，继续沿用 Ousea / Global 设计令牌，不新增后端接口、数据库字段或运行时 UI 依赖。

## User Story

**As a** 校园内容或生活服务发布者  
**I want** 在一个清晰、轻量的页面里快速完成发布  
**So that** 我能先写下核心内容，再补充必要信息，并随时知道草稿、校验和提交状态

## Context

当前发布器已经支持：

- 动态、跑腿、二手、找同行四类业务切换；
- 社区板块和话题选择；
- 图片上传、表情和 @提及；
- 草稿自动保存、编辑和重新提交；
- 校区、路线建议、联系方式复用；
- 键盘避让、暗色模式和安全区处理。

现有问题集中在呈现层：

- 顶部业务切换、页面标题和草稿状态各自占据一层，首屏缺少明确的任务焦点；
- 正文编辑区与业务字段卡片视觉权重接近，用户不容易判断必填信息和填写顺序；
- 多层白色容器、边框和分隔线叠加，内容显得零散；
- 跑腿、二手、找同行的路线、价格、时间等核心字段没有形成足够明确的业务信息组；
- 底部状态提示和操作按钮占用较多空间，键盘弹起或窄屏时需要更谨慎地处理可见区域。

## Design Direction

- 设计概念：**微信原生内容发布器**。用户进入页面后直接开始创作，界面遵循微信小程序常见的白色编辑面、连续表单和底部主操作模式，弱化配置页和运营页观感。
- 风格：清爽、现代、轻量的移动端编辑器，不使用重度玻璃拟态、大面积渐变或装饰性背景。
- 令牌：页面背景、表面、正文、边框、间距、圆角、动效和暗色值全部复用 `design-system/campus-miniapp` 的 Ousea / Global tokens。
- 业务色：只用于当前业务选中态、关键数字和主提交动作；危险操作继续使用统一 danger 语义色。
- 字体：继续使用系统字体栈，不引入网络字体；通过字号、颜色和间距建立层级，不靠大面积加粗。
- 结构：不沿用旧页面结构。移除 Hero、外层圆角卡片和卡片嵌套，以全宽正文编辑面、页面背景分隔带和连续业务表单重新组织信息。
- 动效：只保留 120–240ms 的按压、颜色和透明度反馈，并为减少动态效果提供静态降级。

### 设计原则

1. **内容优先**：正文编辑器是页面首要视觉焦点，页面不重复展示导航标题、Hero 标题和区块标题。
2. **单一主任务**：页面始终围绕完成当前类型的发布，业务切换和辅助信息不能抢占正文权重。
3. **渐进披露**：只显示当前业务需要的字段，非必填公共信息使用紧凑选择行表达。
4. **连续表单**：业务模块以全宽白色表面和行分隔组织，不为模块或输入框创建悬浮卡片。
5. **克制使用业务色**：业务色仅用于当前类型、关键节点、关键数字和主提交动作。

## Information Architecture

1. 自定义导航栏：保留返回和编辑态语义，中间标题随类型变化；草稿能力静默运行，不展示无操作价值的保存状态。
2. 业务切换区：导航栏下方设置紧凑的固定四等分文字入口，不放入 Hero 或卡片；当前业务使用业务色文字和底部短指示条，编辑/重新提交时继续锁定切换。
3. 核心内容区：正文编辑成为首要视觉焦点，使用一块完整的纸张式表面；表情、提及、图片工具位于编辑器底部，并与图片编辑区域保持在同一视觉容器。
4. 业务信息区：
   - 社区：板块和话题作为独立、易扫读的选择组；
   - 跑腿：取件地、送达地、截止时间、报酬形成任务信息组，时间和报酬采用连续信息行；
   - 二手：出售/求购使用轻量分段选择，课程上下文和价格形成交易信息组，不重复展示无新增语义的标题或图片说明；
   - 找同行：出发地、目的地、出发时间和名额形成行程信息组；时间与名额使用连续信息行，不展示无必要的补充说明编辑区。
5. 公共信息区：校区和联系方式保留现有能力，但降低视觉噪音并明确辅助说明。
6. 底部操作区：使用紧凑、稳定的安全区底栏承载保存退出和提交审核；校验信息仅在无效时显示，异步状态下按钮尺寸不变化。

## Detailed UI Specification

### 1. 导航与业务类型

- 页面标题按当前类型显示为“发布动态”“发布跑腿”“出售闲置”或“发布同行”，不再增加重复的大标题。
- 四类入口采用纯文字标签，减少图形噪音；单项点击热区不小于 `88rpx × 88rpx`，相邻点击目标间距不小于 `16rpx`。
- 未选中项使用次级文字色；选中项使用业务色，并同时提供文字权重或指示条，不能只靠颜色区分。
- 类型切换只使用 150–200ms 的颜色、背景和透明度过渡，不使用缩放动画。
- 类型栏只承担类型切换，不展示“发布类型”“草稿自动保存”等解释性文案或低频操作。

### 2. 正文编辑器

- 页面左右间距为 `24–32rpx`；编辑器高度按业务内容密度调整，跑腿等结构化发布不使用大面积空白抢占首屏。
- 正文建议使用 `30–32rpx` 字号；placeholder 使用现有次级文字 token，但必须保留可访问字段名称。
- 编辑器内部不绘制传统输入框边框；通过表面、留白和底部 `2rpx` 分隔线建立范围。
- 工具栏按钮高度不小于 `88rpx`，使用正式图标和文本可访问名称，禁止使用 Emoji 作为功能图标。
- 图片缩略图紧接工具栏展示，不重复说明用户可从界面直接理解的封面规则。
- 字符计数仅在接近上限或发生错误时增强显示，正常状态降低视觉权重。

### 3. 分业务信息结构

#### 动态

- 正文后依次展示发布板块、话题和发布范围与联系。
- 板块使用稳定的两列选择布局；长文本允许换行，选中态使用浅业务色背景、业务色边框和非颜色辅助标识。
- 话题与板块都使用规则、等宽的小圆角选项，避免按文字长度生成大小不一的胶囊。

#### 跑腿

- 取件地和送达地组成一块路线组件，使用起终点圆点和垂直连线表达关系。
- 截止时间与跑腿报酬组成连续信息行，左侧标签、右侧值，避免不均衡双栏。
- 报酬输入显示明确的人民币单位，并使用数字键盘。

#### 二手

- 详情区顶部以文字选项和短下划线选择“出售 / 求购”，不设置整组背景底板。
- 价格是业务详情中的首要字段，数字视觉权重大于普通辅助字段，并显示明确人民币单位。
- 课程、学院等上下文继续使用紧凑选择行；图片区域不重复解释封面规则。
- 禁止使用促销型渐变、发光或过度商业化装饰。

#### 找同行

- 出发地和目的地复用路线组件。
- 出发时间与可用座位组成同一信息组；座位数使用数字键盘或现有步进交互，点击热区不小于 `88rpx`。

### 4. 公共信息与底部操作

- 校区与联系方式合并为“发布范围与联系”信息组，以紧凑选择行呈现，不隐藏必填状态。
- 底部栏左侧保留“保存退出”次级按钮，右侧为当前业务的主发布按钮，按钮高度为 `88rpx`。
- 主按钮建议占可用操作宽度的 60–65%，文案随业务和编辑模式变化。
- 表单有效时不长期显示状态胶囊；无效时在按钮上方显示一行具体提示，例如“请选择发布板块”。
- 提交中保持按钮尺寸不变、显示加载状态并禁止重复提交。
- 键盘弹出时隐藏固定操作栏，收起后恢复；底栏必须包含设备安全区。

### 5. 视觉与动效

- 页面背景使用 `page`，主要内容使用 `surface`，边框使用现有语义 border token。
- 普通信息组优先使用 `2rpx` 边框和留白，不使用重阴影；圆角建议控制在 `20–24rpx`。
- 区块间距建议为 `24rpx`，组内间距遵循现有 Ousea / Global spacing token。
- 系统字体保持不变，不采用设计检索结果中的 Inter 网络字体或紫绿通用配色。
- 仅动画颜色、透明度和必要的低成本位移，并兼容减少动态效果设置。
- 暗色模式只替换语义 token，不硬编码页面局部反色值。

## Requirements

### 1. 业务切换与页面上下文

- 四类业务的切换逻辑、草稿隔离和业务主题色保持不变。
- 页面进入后能在首屏明确识别当前业务和发布目标。
- 草稿自动保存、编辑和重新提交能力保持不变，但不在类型栏重复展示状态或资源编号。

### 2. 正文编辑

- 正文输入区是页面第一视觉焦点，标题、占位文案和字符计数保持清晰。
- 表情、提及、图片工具保留现有交互、图标和可访问名称。
- 继续支持键盘避让、选区、@提及删除、表情 token、图片上传和图片编辑。
- 社区、跑腿、二手和找同行的占位文案继续随业务变化。

### 3. 业务字段

- 输入框、日期/时间选择器、校区选择器、联系方式和路线建议统一视觉规格。
- 路线字段使用明确的起点/终点语义和轻量关系表达，不改变字段值或提交载荷。
- 价格、报酬、时间、名额等业务关键值比普通说明更容易扫读。
- 社区板块、话题和二手出售/求购选择支持选中、按压、禁用和长文本状态。
- 不渲染服务端未返回的字段，不为视觉效果创建虚假占位内容。

### 4. 状态与反馈

- 加载原内容和恢复草稿时保留稳定的页面骨架，避免内容突然跳动。
- 校验错误在底部提交区明确表达，同时保证提交按钮禁用态可理解。
- 图片上传中、提交中和保存退出中的按钮宽高保持稳定，禁止重复提交。
- 成功、失败反馈继续使用现有 Toast/API 错误语义。

### 5. 触控、可访问性与兼容性

- 主要交互热区不小于 `88rpx × 88rpx`；紧凑文字按钮通过内边距扩充热区。
- 图标按钮继续提供 `ariaLabel`，关键信息不能只依靠颜色表达。
- 保持暗色模式、键盘弹起、安全区和 320/360/375px 等效窄屏布局。
- 页面不引入 Web 专用 hover 逻辑，不使用 emoji 作为功能图标。
- 仅动画 `opacity`、`transform`、颜色和边框等低成本属性。

## Technical Implementation

- 继续使用 Taro React、TypeScript、SCSS 和现有 `@tarojs/components`。
- 保留 `PublisherForm`、草稿 key、编辑/重新提交模式、现有 repository 调用和所有页面测试选择器。
- 以 `src/pages/publish/index.tsx` 调整展示结构，以 `src/pages/publish/index.scss` 重做布局、分组和状态样式；仅在现有图标不足时复用或补充轻量 SVG。
- 不修改 API 类型、请求参数、数据库、页面路由和业务状态机。
- 如需新增静态回归断言，新增或扩展 publisher UI smoke，锁定关键区块、热区、底栏安全区和业务主题映射。

## Files to Modify

- `src/pages/publish/index.tsx` - 收敛头部上下文、整理正文/业务字段区块、保留现有状态与交互契约。
- `src/pages/publish/index.scss` - 优化业务切换、内容编辑卡、字段分组、选择状态和底部操作区。
- `scripts/publisher-ui-smoke.ts` - 如现有 smoke 无法覆盖新的视觉结构，则增加静态结构和关键令牌断言。
- `package.json` - 仅在新增 smoke 时注册对应测试命令。

## Non-Goals

- 不新增或修改后端 API、数据库迁移、OpenAPI 契约和权限规则。
- 不改变社区板块/话题的数据来源，不改变图片上传与审核流程。
- 不改变草稿存储格式、业务校验含义、提交载荷和详情跳转。
- 不引入第三方 UI 组件库、网络字体或大体积图片背景。
- 不顺带改造社区列表、生活服务列表或详情页；这些页面如需调整另立任务。

- `yarn test:dark-mode`

### Build and Manual Checks

- 检查创建、切换、草稿恢复、编辑、重新提交、图片上传、键盘弹起、校验错误、提交中和暗色模式。
- 在 320px、360px、375px 等效宽度下确认无横向溢出、底栏遮挡和文字重叠。

## Acceptance Criteria

1. 进入统一发布器后，当前业务和发布目标在首屏清楚可见，草稿能力静默运行且不占用首屏层级。
2. 正文编辑区是主要视觉焦点，四类业务的信息组有明确差异但共享一致的基础规范。
3. 页面减少重复边框和嵌套卡片，字段间距、标题、提示和选择态形成稳定节奏。
4. 底部操作区在普通页面、键盘弹起、暗色模式和安全区设备上均不遮挡内容，保存退出与提交审核状态明确。
5. 现有动态、跑腿、二手和找同行的所有业务流程与数据行为保持不变。
6. 主要操作可触达、可访问，窄屏无横向溢出，减少动态效果设置下无持续动画。
7. 相关 smoke、lint、typecheck、设计令牌检查、暗色检查和小程序构建通过。

## Design Handoff

实现者交付时需要提供动态、跑腿、二手和找同行四种页面状态截图，并额外验证：

- 键盘展开时正文输入不被遮挡，底部操作栏按规范隐藏；
- 表单错误能定位到具体缺失项，而不是只显示笼统的不可提交状态；
- 图片上传、删除和最多图片数量保持原有行为；
- 创建、草稿恢复、编辑和重新提交模式不改变现有数据行为；
- 保留 `publisher-content`、`publisher-submit` 及各业务字段现有 selector/id；
- 微信开发者工具中完成四种业务流程的人工回归，并附构建和检查结果。

## Risks and Mitigations

- 长表单重排可能影响已有自动化选择器：保留 `publisher-content`、`publisher-submit`、业务字段 ID 和现有语义标签。
- 底部栏调整可能影响键盘场景：继续使用 `useKeyboardInset`、安全区 padding 和固定底栏状态类，并在开发者工具中验证。
- 视觉重构可能误改业务校验或草稿逻辑：限制 TypeScript 改动在展示结构和 className，提交函数与数据映射只做必要的展示适配。
