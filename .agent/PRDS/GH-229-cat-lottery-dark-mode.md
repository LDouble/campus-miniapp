# 猫猫图鉴与抽奖深色模式修复

**Priority:** High
**Status:** In Progress
**Type:** Bug
**Created:** 2026-09-12
**Last Updated:** 2026-09-12

## 证据

- 抽奖详情运行时将 __campusTheme 设置为 dark 后，卡片背景为 rgb(17,24,39)，标题、章节标题、分享文字仍为 rgb(28,25,23)，页面根背景仍为 rgb(250,247,244)。截图 `/tmp/lottery-dark-audit.png` 可见黑底深色字和浅色边框。
- config/plugins/weapp-compat.js 将主题 class 注入页面根元素自身，detail.scss 的 `.campus-theme--dark .lottery-detail-page` 后代选择器不能匹配根元素。根元素上的浅色局部语义变量因此没有被覆盖。不能只将选择器改为自身后继续使用 inherit，因为父级也未必拥有深色变量。
- 猫猫列表 catalog.scss 使用固定的 --cat-paper/card/ink 等浅色值，缺少深色覆盖；详情 atlas.scss 后续 --figma-* 浅色变量未被已有 --campus-cat-* 覆盖。
- 地图、我的图鉴、档案建议仍存在固定浅色背景。上报页、相遇日志已有深色规则，但也需核对根元素匹配与图标可读性。
- 现有 dark-mode、design-tokens、cat-atlas、lottery 测试均通过，说明现有测试未覆盖这些实际级联问题。

## 修复范围

- 抽奖列表、详情、抽奖码、中奖结果的背景、文字、边框、状态与底栏；重点修复详情根节点覆盖。不修改抽奖、分享归因、赞助商复制和公众号逻辑。
- 猫猫图鉴列表、详情、地图、我的图鉴、档案建议、上报、相遇日志的背景、表单、卡片、底栏、加载错误空态与功能图标。
- 浅色外观保持现状。深色使用全局 Campus 语义变量与 Ousea 原始令牌，不新增独立深色调色板、不反色真实照片。
- 不改后端、管理端、接口、认证和业务数据，不替换主仓已构建的提审包。

## 实施

- 先核对 MASTER.md 和页面覆盖规范；复用主仓一致锁文件的 node_modules 软连接。
- 猫猫样式与抽奖样式可独立并行修改；主代理负责主题注入关系、全局变量一致性、回归与整包验证。
- 使用能同时覆盖根元素自身/必要后代场景的选择器，移除或限制只应存在于浅色模式的局部变量。
- 为确定失效的层级、颜色和图标补回归断言；除静态断言外核对微信运行时 computedStyle。

## 验收

- 深色模式下关键正文、标题和功能图标清晰可辨，无浅色背景和边框残留；普通文字以 4.5:1 对比度为目标。
- 列表、详情、底栏、表单、空错加载态检查；真实照片保持原色。
- 浅色模式、主题切换、减少动态效果不回归。
- lint、typecheck、dark-mode、design-tokens、cat-atlas、lottery、typography 和 build:weapp 通过。
- 微信开发者工具确认计算颜色与截图，记录没有数据或未实测的路径，不以静态测试替代视觉验收。
- 仅在新 Feature 工作区构建；用户要求时再预览、发起 PR 或更新提审包。

## 实施结果与剩余验收

- 已修复页面根节点主题匹配、浅色局部变量覆盖、卡片/导航/表单/固定底栏，以及详情功能图标；浅色规则和业务逻辑不变。
- 深色强调文字使用高亮业务语义色，白字操作按钮使用深色业务表面，避免亮橙底白字对比度不足。
- 代码检查与回归测试通过。用户补充开发者工具配置后已成功推送手机预览；逐页截图与计算颜色验收尚未完成，不能以编译测试替代运行时验收。
- 根据预览反馈，移除图鉴列表 dbar 与多余底部留白，在首页增加图鉴入口，并统一首页、全部服务中的猫咪图标及深色资源。
