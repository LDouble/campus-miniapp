## 已确认范围

在课表课程详情和首页快捷课程卡增加课堂讨论入口。首期采用帖子、图片、评论和回复，复用现有社区。

用户明确要求：仅按选课号和学年学期关联，不进行教学班归属校验。此要求替代之前方案中的可信选课关系、成员表和班内私密访问设计。

## 关联规则

- 使用 trim 后的 class_num（选课号）与 period_id（学年学期）二元组作为唯一键，不按课程名称、教师、上课时段或用户 ID 分组。
- 相同选课号和学年学期复用同一讨论组；任一字段不同即为不同组。
- 学期值沿用课表接口的规范 ID，不从日期推测学期，不对未知格式自行合并。
- 缺少选课号或学年学期时明确提示不可用，不按课程名猜测创建。
- 不区分官方、蹭课、模拟来源的成员资格，只要求入口拥有必要关联字段。
- 仅解析创建接口要求现有登录身份；发帖、评论和点赞继续遵守现有社区认证和审核规则，不新增教学班校验。

## 产品体验

1. 课表：课程详情操作区增加“课堂讨论”。
2. 首页：每条快捷课程增加“讨论”按钮，点击时不触发原课程行的课表跳转。
3. 讨论列表复用社区话题页，识别课堂讨论并显示对应文案、学年学期和选课号。
4. 明确说明“公开课堂讨论，不限本班同学参与”，不承诺私密。帖子沿用公开社区展示和分享规则。
5. 发布时自动关联课堂讨论，防止误取消或替换；返回列表刷新，审核状态沿用社区。
6. 覆盖加载、空状态、错误重试、防重复点击、归档不可用、深色模式及资质版模块门控。

## 后端方案

- 在校园圈模块新增 POST /api/v1/campus-circle/class-discussions/resolve。
- 请求：class_num 必填最长128字，period_id 必填最长64字，course_name 可选最长64字。
- 响应：现有 CampusCircleTopicView 标准响应。
- 利用既有 topic slug 唯一索引，使用 class-discussion- 保留前缀与二元组稳定摘要实现幂等创建，无新增表或迁移。
- 首次创建前沿用现有内容审核配置检查课程名称和描述，通过后创建公开话题。不启用自动文本关联；重复调用不覆盖元数据、不重新开放归档话题、不重复审核。
- 复用现有每日自动创建配额，普通管理员建话题不能占用课堂保留前缀；禁止合并课堂话题以保持关联键稳定。
- 内容发布继续走原有审核、评论、举报、分享链路；不修改教务服务、不创建班级成员表。

## 跨端范围

- 小程序：入口、课堂讨论文案、发布预关联、刷新和边界处理。蹭课读取真实 opening_code，旧缓存的班级名称和目录 ID 不作为选课号。
- 后端：关联键规范化、幂等解析、话题状态保护、OpenAPI与权限生成。
- 管理端：复用现有话题和帖子治理页面，无新页面；后台接口保护不可合并和自动关联等身份规则。

## 验收

- 两个入口进入同组；同课程多时段同组；不同选课号或学期不串组。
- 无选课号明确不可用，输入空白和控制字符被拒绝。
- 不执行教学班归属查询，有必要参数的登录用户可解析讨论组。
- 并发首次调用最终仅一组；重复请求、课程改名不覆盖已有信息。
- 归档后不自动恢复；保留前缀不可被普通话题创建流程占用，不允许跨组管理员合并。
- 讨论发布、评论、回复、返回刷新和分享继续使用现有社区流程。
- 小程序目标测试、类型和样式检查、构建通过；后端目标测试、生成漂移、迁移检查通过。
