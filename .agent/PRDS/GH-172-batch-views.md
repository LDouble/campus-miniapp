# 浏览量批量上报优化

用户已于本轮确认按批量上报方案实施，复用当前未合并的浏览量任务分支。

## 目标

- 客户端合并 3 秒内的有效阅读，满 20 帖提前发送；最多 2 个批请求并发，队列有界。
- 新增兼容接口 POST /api/v1/campus-circle/post-views/batch，请求 reader_token、post_ids（1–20 个正整数），响应 data.items，每项 post_id、counted、可选 view_count；不可见帖子不返回计数。
- 后端批量查询公开帖子，Redis pipeline 去重及按帖子数加权限流，按主键顺序锁定帖子后单次批量 upsert 和批量读取；禁止循环调用单帖业务伪装批量。
- 复用单帖 Redis 标记及 30 分钟窗口，排除作者自看；数据库故障释放本人持有的标记以允许重试。
- 保留单帖接口兼容旧客户端；新客户端遇到批接口未上线（404/405）时，限并发回退单帖且会话内缓存能力。
- 页面隐藏时尽力提交已完成曝光的队列，不把未满 1 秒曝光混入；身份切换不以新身份发送旧队列。
- 本期不引入 Redis 异步落库、不改变数据库结构、不发布服务。

## 验收

- 单元测试证明同一批多帖只调用一次批API，分批上限、计时、重试、限流及身份隔离正确。
- 后端测试证明批量 SQL 与 Redis 操作、重复ID及跨接口去重、作者/非公开过滤、失败清理、并发正确。
- 生成与迁移漂移检查、目标测试、lint/typecheck/微信构建通过；记录真实联调与模拟接口验证的边界。
