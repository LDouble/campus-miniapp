# OUSea小程序：修复成绩模拟映射、学分限制与绩点编辑

**Priority:** High
**Status:** Done
**Type:** Bug
**Created:** 2026-08-12
**Last Updated:** 2026-08-12

## 一、问题概述

成绩查询页现有模拟计算存在三类问题：

- 百分制绩点分档与用户提供的《校内成绩与绩点换算表》不一致。
- 等级制先折算为百分制、再使用百分制规则计算绩点，导致“良好”“中等”等等级的绩点不符合五级制规则；现有等级折算分本身也与指定映射不一致。
- 模拟编辑只能修改成绩和学分，不能独立修改绩点；切换等级时也不会同步刷新默认折算分。
- 模拟学分被限制为 `0.5–20`，不符合“只要大于 0 即可”的要求。

## 二、修复目标

- 百分制成绩严格按校内换算表计算默认绩点。
- 五级制、二级制及用户给出的同义文字成绩使用明确的折算分和绩点映射，不再借用百分制绩点规则推导等级制绩点。
- 模拟编辑时，切换文字等级自动带出对应的默认折算分和默认绩点。
- 模拟成绩、折算分、绩点和学分均可手动修改，并立即影响课程卡片和汇总结果。
- 学分只校验为有限数且大于 `0`，不再保留 `0.5` 最低值或 `20` 上限。
- 既有本地模拟数据继续可读；重置模拟时一并清除新增的绩点覆盖值。

## 三、规则定义

### 3.1 百分制绩点

| 成绩区间 | 默认绩点 |
| --- | ---: |
| `95 ≤ x ≤ 100` | 4.0 |
| `90 ≤ x < 95` | 3.9 |
| `85 ≤ x < 90` | 3.7 |
| `81 ≤ x < 85` | 3.3 |
| `78 ≤ x < 81` | 3.0 |
| `75 ≤ x < 78` | 2.7 |
| `71 ≤ x < 75` | 2.3 |
| `68 ≤ x < 71` | 2.0 |
| `64 ≤ x < 68` | 1.7 |
| `60 ≤ x < 64` | 1.0 |
| `x < 60` | 0 |

“补考 60”按数值成绩 `60` 处理，默认绩点为 `1.0`。

### 3.2 文字成绩映射

| 原始文字或同义值 | 默认折算分 | 默认绩点 | 规则来源 |
| --- | ---: | ---: | --- |
| 优秀、优、免修 | 90 | 3.9 | 指定折算方法 + 五级制表 |
| 良、良好 | 80 | 3.3 | 指定折算方法 + 五级制表 |
| 中、中等 | 70 | 2.3 | 指定折算方法 + 五级制表 |
| 合格、及格 | 60 | 1.0 | 指定折算方法 + 五级制表 |
| 不合格、不及格 | 0 | 0 | 指定折算方法 + 五级制表 |
| 通过 | 85 | 3.7 | 指定折算方法 + 二级制表 |
| 不通过 | 0 | 0 | 二级制表 |

未知文字成绩保持现有安全行为：仅展示原值，不参与加权平均分或平均绩点计算，避免默认为零分污染结果。

## 四、根因

- `src/pages/academic/calculations.ts` 的 `getGradePoint` 使用旧分档，例如 `90` 分直接映射为 `4.0`、`64` 分映射为 `1.5`。
- `gradeLevelScores` 当前映射为优秀 `95`、良好 `85`、中等 `75`、及格 `62`，与指定折算方法不一致，也未覆盖同义值和二级制。
- `calculateGradeSummary` 统一调用 `getGradePoint(score)`，无法表达等级制“折算分与绩点分别映射”的规则。
- `GradeOverride` 没有绩点字段，页面编辑状态、保存逻辑和课程卡片均只能从分数反算绩点。
- 等级按钮当前仅更新 `gradeLevel`，不会同步更新折算分。
- 保存入口和表单文案把学分硬编码为 `0.5–20`。

## 五、技术方案

### 5.1 集中成绩规则

- 在 `src/pages/academic/calculations.ts` 中集中维护百分制分档和文字成绩规则，避免页面重复硬编码。
- 保留“折算分”和“默认绩点”两个独立解析结果：
  - 百分制默认绩点由分数分档计算。
  - 等级制默认绩点直接由规范化后的文字等级映射。
- 增加统一的课程绩点解析函数，优先级为：模拟手工绩点覆盖、原始等级默认绩点、百分制默认绩点。
- 加权平均分仍使用实际或模拟分数；平均 GPA 使用实际或模拟绩点，二者均按模拟学分加权。

### 5.2 扩展模拟数据模型

- 在 `GradeOverride` 增加可选的 `gradePoint` 字段。
- 可选字段保证旧版本本地缓存仍可读取；旧数据缺少该字段时按当前成绩规则生成默认绩点。
- 保存模拟数据时同时保存分数、绩点、学分，以及等级制课程的文字等级。
- 重置逻辑沿用清空 `overrides`，自然清除绩点覆盖。

### 5.3 编辑交互

- 打开编辑面板时，绩点输入框默认展示当前覆盖绩点；无覆盖时展示规则计算出的默认绩点。
- 等级制课程切换等级时，同时刷新默认折算分和默认绩点；用户随后可分别手动调整两者。
- 数值成绩被手动修改时，默认同步映射绩点；绩点输入框仍允许用户在同步后继续手动覆盖。
- 绩点保存前校验为 `0–4` 的有限数；成绩校验继续为 `0–100`。
- 学分校验改为有限数且严格大于 `0`，标签改为“模拟学分（大于 0）”。
- 模拟模式提示改为可修改“成绩、绩点或学分”。

### 5.4 展示与汇总

- 课程卡片使用统一的课程绩点解析函数，不再只根据折算分反推绩点。
- 存在模拟覆盖时，原始信息区域继续显示原始成绩和学分，并补充原始绩点，便于对照。
- 汇总结果中的加权平均分和平均 GPA 分别读取模拟分数与模拟绩点。

## 六、拟修改文件

- `src/pages/academic/types.ts`：为 `GradeOverride` 增加可选绩点字段。
- `src/pages/academic/calculations.ts`：修正百分制分档，增加文字成绩折算分、默认绩点和统一绩点解析逻辑。
- `src/pages/academic/grades/index.tsx`：增加绩点编辑状态和输入框，完善等级/成绩切换同步、保存校验、学分文案及课程卡片展示。
- `scripts/academic-calculations-smoke.ts`：新增成绩映射、覆盖优先级和加权汇总冒烟测试。
- `package.json`：增加上述冒烟测试命令，并纳入持续检查。

不修改后端接口、不新增依赖，也不改变教务系统原始成绩数据。

## 七、测试要求

### 7.1 自动测试

- 覆盖百分制每个分档的下界，以及相邻分档边界，例如 `95`、`94.99`、`90`、`85`、`81`、`78`、`75`、`71`、`68`、`64`、`60`、`59.99`。
- 覆盖优秀、优、免修、良、良好、中、中等、合格、及格、不合格、不及格、通过、不通过的折算分和默认绩点。
- 验证模拟绩点覆盖优先于规则默认值。
- 验证 `0.01` 等正学分可参与计算，并验证加权平均分与平均 GPA 分别使用模拟分数和模拟绩点。
- 验证未知文字成绩不参与汇总。
- 执行 `yarn lint`、`yarn typecheck`、新增冒烟测试和微信小程序构建。

### 7.2 手工验收

- 五级制课程切换等级后，折算分和绩点立即按表更新。
- 二级制“通过/不通过”显示并使用 `3.7/0` 绩点。
- 修改模拟绩点并保存后，课程卡片与平均 GPA 同步变化，刷新页面后仍保留。
- 修改成绩后自动带出规则绩点，之后仍可单独修改绩点。
- 输入 `0`、负数或非数字学分会被拒绝，输入任意大于 `0` 的有限数可保存。
- 重置模拟后恢复原始成绩、绩点和学分。

## 八、验收标准

- 所有成绩与绩点映射均符合本 PRD 第三节规则。
- 模拟模式可独立修改成绩、绩点和学分，且汇总计算结果正确。
- 学分只保留“大于 0”的限制。
- 旧模拟缓存不因新增字段报错，新保存数据可正常持久化和重置。
- TypeScript 类型检查、Lint、冒烟测试和微信小程序构建均通过。

**实施说明：**

本方案把“文字成绩的折算分”和“文字成绩的绩点”作为两套独立规则处理，以避免将五级制、二级制错误套入百分制分档。待方案确认后开始修改业务代码。
