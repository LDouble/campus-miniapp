# 小程序：评论与发布器接入校园鲨表情包

**Priority:** High
**Status:** Done
**Type:** Feature
**Created:** 2026-08-16
**Last Updated:** 2026-08-16

## 概述

将已拆分的 32 张校园鲨透明 PNG 表情接入通用评论组件和发布器。交互参考用户提供的设计图：输入区下方是轻量图标工具栏，点击笑脸按钮后展开“最近使用 + 全部表情”面板，发布按钮稳定位于右侧。

由于当前评论和部分发布业务只接受文本字段，本期使用受控表情标记协议存储，由小程序展示端严格解析成本地图片，不新增后端接口或数据库字段。

## 用户故事

**作为** 发布校园内容或参与评论的学生

**我希望** 在输入区直接挑选校园鲨表情

**从而** 以更轻松、直观的方式表达情绪，不需要先保存图片再上传

## 范围与需求

1. **通用表情选择器**
   - 读取 `campusStickers` 资源清单，展示 32 张表情。
   - 参考图采用浅色底、弱分隔线和纵向滚动网格，包含最近使用与全部表情。
   - 表情图标只提供瞬时按压反馈和中文无障碍标签，点击后不保留选择态。
   - 打开表情面板时收起键盘；输入框重新聚焦或键盘升起时自动收起表情面板。

2. **评论组件接入**
   - 在 `DetailComments` 展开态输入区增加笑脸表情入口，可重复追加任意表情，不设置独立数量上限。
   - 选择表情后在当前光标或选区位置插入 `[具体含义]`，不设置独立预览区，最终仍受评论正文总长度约束。
   - 支持“纯表情”和“文字 + 表情”评论，同样适用于回复。
   - 提交时按正文原有顺序将已知标签序列化为带表情 ID 的受控标记；根评论和递归回复均使用同一内容渲染器还原。
   - 社区、二手、跑腿、同行详情页因复用 `DetailComments` 而同时生效。

3. **发布器接入**
   - 在正文输入区下方增加参考图风格的工具栏和表情入口。
   - 表情在 `Textarea` 内以 `[具体含义]` 展示，可与文字任意混排，不暴露内部标记。
   - 动态、二手、跑腿和同行均可选用表情；提交时与正文一起序列化。
   - 表情可重复追加且不设置独立数量上限，通过正文直接编辑或删除。
   - 表情选择纳入现有分区草稿保存、清空、编辑回填和字数校验。
   - 社区/二手的现有图片入口保留，工具栏可复用图片操作；跑腿/同行不显示无效的图片按钮。
   - 无图片时不展示独立图片区；点击工具栏图片图标完成选图后再展开紧凑九宫格，删除最后一张图片后自动收起。
   - 九宫格继续提供追加、封面标识、预览、排序、删除、上传进度和失败重试；达到 9 张后隐藏追加入口并禁用工具栏图片按钮。

4. **内容标记与渲染**
   - 使用有版本、可严格校验的标记格式，仅允许清单内表情 ID 被解析。
   - 支持的表情 ID 渲染为图片；未知版本或未知 ID 降级为 `[具体含义]`，不得暴露协议前缀或渲染任意路径。
   - 旧内容不含标记时完全保持现有展示。
   - 社区动态列表/详情和四类业务的主要卡片/详情使用通用渲染器，避免发布后显示原始标记。

## 不在本期范围

- 不新增后端 `sticker_id` / `media_id` 字段、不改 OpenAPI 和数据库。
- 不增加表情商店、下载、收藏或用户自定义表情；仅保留最近 7 个本地使用记录。
- 不在本期实现参考图中的 `@` 用户选择器，避免出现无功能入口。
- 不把内置表情重复上传到对象存储，避免占用 9 张业务图片限额和产生重复媒体记录。

## 技术方案

### 架构

- `src/components/sticker-picker/`：通用表情按钮、最近使用与全部表情网格面板和样式。
- `src/features/stickers/content.ts`：表情标记序列化、解析、普通文本回退和无障碍文案。
- `src/components/sticker-content/`：统一渲染文字与表情片段。
- 评论与发布器只管理可见正文及光标，不各自重复协议解析逻辑。

### Taro 与小程序约束

- 选择面板使用固定高度的 Taro `ScrollView` 纵向滚动，贴纸使用 `Image mode='aspectFit'` 和 `lazyLoad`。
- 评论固定输入区继续使用 `KeyboardSafeTextarea` 与现有键盘高度机制。
- 触控区不小于 88rpx，贴纸图片与点击区分离，不依赖仅颜色表示状态。
- 不新增 npm 依赖，继续使用 React、Taro、TypeScript 和 SCSS。

## 验收标准

1. 评论和发布器都有与参考图一致的笑脸入口、白底表情条和右侧发布操作层级。
2. 表情面板可纵向滚动查看 32 张表情，并展示最近使用记录，切换时不被键盘遮挡。
3. 评论支持纯表情、文字加表情和回复场景，提交与失败重试状态正确。
4. 四种发布类型均能选择表情，草稿、切换分区、清空和编辑回填不丢失表情及其混排位置。
5. 新内容在评论、社区动态及生活服务主要列表/详情中显示贴纸图片，不暴露内部标记。
6. 非法表情 ID 不能加载任意资源，未知 ID 或版本以 `[具体含义]` 安全回退，不显示内部协议前缀。
7. 旧内容、普通文字评论、图片上传和现有媒体限额行为不回归。
8. 375px 等效宽度和 iPhone 安全区下无溢出，表情点击区满足小程序触控要求。
9. `yarn test:stickers`、`yarn tsc --noEmit`、`yarn build:weapp` 和 `git diff --check` 全部通过。

## 风险与处理

- **旧客户端显示标记**：未升级客户端会将标记当作普通文本。标记使用可读标签作为降级，后续可迁移为后端原生字段。
- **审核可读性**：标记包含中文表情名，审核系统即使未渲染也能理解表达内容。
- **内容长度**：序列化后的真实长度必须在提交前校验，避免预览与服务端限制不一致。
- **渲染覆盖面**：发布器支持四类内容，需要覆盖对应卡片和详情主路径，通过共享组件降低遗漏风险。
