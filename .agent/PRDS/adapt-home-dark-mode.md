# Campus Miniapp：首页适配深色模式

**Priority:** High
**Status:** Done
**Type:** Enhancement
**Created:** 2026-08-21
**Last Updated:** 2026-08-21

## Overview

首页已有全局深色 token 和部分 Hero、服务图标、社区 Feed 的深色覆盖，但导航栏、首页业务卡片、常用服务图标边框、公告、内容列表、空状态与迁移提示仍存在浅色残留或层级不足。目标是在不改动浅色主题、布局、接口与交互的前提下，让首页所有可见模块在系统深色模式下形成连续、清晰且低眩光的视觉层级。

## User Story

**As a** 使用系统深色模式的校园小程序用户
**I want** 首页各模块自动切换为统一、清晰的深色视觉
**So that** 夜间使用时不会出现突兀白块、低对比文字或过亮图标底板

## Context

- 全局已提供 `--campus-*` 深色语义 token，页面底色为 `#0B1220`，卡片表面为 `#111827`，次级表面为 `#172033`。
- 首页多数正文已消费语义 token，无需重写组件结构。
- 当前 `_dark-mode.scss` 已覆盖 Hero 和社区 Feed，但首页其余模块的边框、阴影、图标承载面和状态色不完整。
- 常用服务最近已收紧高度，本任务只处理颜色、边框、阴影和图标可见性，不回退其盒子模型。

## Design Direction

- 页面、卡片、次级区域保持“页面底色 < 卡片表面 < 强调底板”的三层亮度关系。
- 正文使用 `--campus-text-heading/body/secondary/muted`，避免纯白大面积高对比。
- 卡片边界使用深色语义边框与低扩散阴影，不使用浅色描边。
- 常用服务保留现有蓝色功能图标风格，但在深色底板上提高图标可见性并将边框切换为深色语义边框。
- 危险、提醒、进行中等状态继续保留语义色，不通过整体反色处理功能图片。
- Hero 图片和内容图片保持原始色彩；只对功能性 SVG 做定向滤镜。

## Requirements

1. 首页页面背景与顶部导航在深色模式下连续，不出现浅色边线或悬浮白块。
2. 课表、今日事项、常用服务、官方通知、社区与闲置模块使用统一深色卡片表面、边框和阴影。
3. 课表行、任务完成态、公告分隔、内容列表分隔、加载/空/错误状态使用语义次级表面与边框。
4. 常用服务图标底板保持各业务识别色，边框不残留浅蓝色，功能图标在深色背景下具有足够对比度。
5. 标题、正文、辅助信息、状态标签分别使用现有深色文字层级，不新增页面私有颜色 token。
6. 首页迁移提示、新闻列表、官方通知与状态反馈不出现硬编码浅色背景。
7. 保留现有 Hero 深色方案、社区 Feed 深色方案、图片原色、布局尺寸、触控热区与减少动态效果支持。
8. 不修改浅色模式、接口数据、页面导航、加载逻辑或业务状态。

## Technical Implementation

### Architecture Approach

- 继续通过 `@media (prefers-color-scheme: dark)` 下的全局深色覆盖实现，不在页面组件中增加主题判断。
- 优先消费 `src/app.scss` 已定义的 `--campus-*` 深色语义变量。
- 将首页卡片壳、文本层级、分隔线、状态底板和图标样式按职责分组，避免逐元素重复硬编码。
- 对真实功能图标使用明确选择器进行滤镜调整，不影响内容图片、头像或帖子配图。

### Technical Considerations

- 微信真机支持系统主题切换，样式不能依赖 Web 专用脚本或运行时 DOM。
- 深色覆盖文件的加载顺序必须能压过首页后置样式，同时避免提高到难以维护的选择器权重。
- 现有工作区包含同一功能链的未提交修改，本任务只触碰上述范围，不覆盖其他改动。

## Manual Acceptance Criteria

- 系统切换深色模式后，首页首屏没有突兀的白色卡片、浅色边线或不可见图标。
- 卡片与页面背景可分辨，但阴影不过亮、边框不过重。
- 常用服务所有图标及名称清晰，彩色底板不过饱和。
- 课表、今日事项、公告、社区、闲置、加载/空/错误状态的文字层级一致。
- 浅色模式视觉、首页高度和所有点击行为保持不变。
