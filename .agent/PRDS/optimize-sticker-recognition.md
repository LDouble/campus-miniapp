# 小程序: 优化小尺寸表情辨识度

**Priority:** High
**Status:** Done
**Type:** Enhancement
**Created:** 2026-08-16
**Last Updated:** 2026-08-16

## Overview

现有 32 张校园鲨表情在选择器中以 `66rpx` 展示，在评论、信息流和业务卡片中通常以 `40–52rpx` 展示。素材文件已经是 `96×96`，主体透明边界约占画布的 70%–89%，因此问题并非文件分辨率或单纯留白，而是完整身体、多个道具、微小文字和面部表情同时缩小后，视觉信息密度过高。

本任务不改变任何组件的 CSS 宽高，不修改表情协议、ID 或中文标签，而是将素材调整为适合 20–26 物理像素显示的“微缩识别版”。

## User Story

**As a** 在评论和信息流中使用校园鲨表情的用户  
**I want** 不放大行高也能快速看懂每个表情  
**So that** 文字与表情混排保持紧凑，同时表情含义清晰

## Description

### 现状诊断

- 默认正文表情为 `40rpx`，评论覆盖为 `44rpx`，信息流为 `48rpx`，详情正文通常为 `52rpx`。
- 原图主体已经接近画布边缘，自动裁透明边只能获得约 10%–20% 的线性增益，无法解决复杂场景缩小时的语义损失。
- `开摆`、`赶截止日`、`考试崩溃` 等场景型表情包含椅子、电脑、书本、头带或文字；缩小后面部只占图标中心很小区域。
- 当前 PNG 为 `96×96` 调色板图片，分辨率足够支撑现有显示尺寸，继续提高源文件像素不会改善辨识度，反而增加包体。

### 推荐方案

重新构图而非放大组件：

- 保持 `96×96` 透明 PNG、原文件名、表情 ID 和标签不变。
- 角色头部与核心表情占画布约 55%–70%，脸部成为第一视觉层级。
- 每张最多保留一个表达语义的关键动作或道具。
- 使用连续的深蓝外轮廓和必要的白色分隔边，保证在白色、浅灰和浅蓝背景上都清晰。
- 删除无法在 20px 级别阅读的装饰文字；`OK`、`DDL` 等必须保留的语义改为大块、极简符号。
- 减少高光、水花、纸张、火焰等碎片数量，保留强轮廓和大色块。
- 不给表情增加永久背景底板，不改变文字行高，也不改变点击热区。

## Implementation Overview

1. 先选择 4 张代表性素材制作概念样张：基础情绪、强烈情绪、生活场景、复杂道具各一张。
2. 在 `40rpx/44rpx/48rpx/52rpx` 四种现有展示尺寸下对比原图和样张。
3. 用户确认视觉方向后，按同一规范逐张调整 32 张素材。
4. 使用模型进行构图简化与轮廓强化；透明背景优先采用纯色键控生成后本地去背，并检查边缘色污染。
5. 将最终素材缩放到 `96×96`，进行调色板/无损压缩，控制总包体不高于当前素材集的合理范围。
6. 保持代码映射和正文解析协议完全兼容，仅替换图片资产。

## Features / Requirements

1. **尺寸与协议不变**
   - CSS 展示尺寸全部保持现状。
   - 源文件继续为 `96×96` PNG。
   - `sticker-01` 至 `sticker-32`、标签和存储 token 不变。

2. **小尺寸优先构图**
   - 面部表情优先于身体和场景。
   - 核心语义在不阅读微小文字的情况下可辨认。
   - 单张表情只保留一个主要视觉焦点。

3. **轮廓与对比度**
   - 角色使用稳定、连续的深色外轮廓。
   - 白色腹部、眼泪或纸张与浅色背景之间有足够边缘分隔。
   - 不只依赖细小颜色差表达不同含义。

4. **包体控制**
   - 不额外引入第二套常驻素材。
   - 替换后的 32 张素材总大小不应显著高于当前版本。
   - 构建后重新核对主包/分包体积。

## Technical Implementation

### Architecture Approach

- 沿用单套素材，选择器与正文渲染共享同一资源，避免包体翻倍。
- 优化发生在素材生产阶段，运行时不增加滤镜、Canvas 或额外计算。
- 以原图作为编辑参考，保留角色蓝白配色、头型、表情含义和关键道具，避免生成风格漂移。

### Technical Considerations

- 微信小程序中的 CSS 滤镜兼容性和性能不适合作为主要辨识度方案。
- 自动裁边只能小幅提升主体占比，不能替代复杂场景的重新构图。
- 生成图片必须检查透明边缘，避免绿色/洋红键控残边。
- 下采样到 `96×96` 后再判断质量，不能只看模型输出的大图。
- 必须保留未知表情降级为 `[中文标签]` 的现有行为。

### Design/UX Considerations

- 视觉层级：眼睛/嘴部表情 > 手势或关键道具 > 身体轮廓 > 装饰效果。
- 轮廓粗细应针对 96px 源图设计，缩小后仍至少保留约 1 个物理像素的连续边缘。
- 点击按压态保持现有短暂反馈，不增加选择态或永久背景。
- 深色模式和浅色模式均需检查；颜色不能成为唯一语义载体。

## Testing Requirements

### Unit Tests

- 32 张资源均存在且为 `96×96` PNG。
- 表情 ID、标签和 token 往返保持不变。
- 未知 ID 继续降级为 `[中文标签]`。

### Integration Tests

- 选择器、评论、信息流、详情页均加载替换后的同一路径资源。
- 图片替换后不引入第二份运行时资源。
- 构建产物仍能正确包含 32 张表情。

### E2E Tests

- 在评论中混排文字与多个表情，行高和基线不变。
- 在信息流和详情页检查 40–52rpx 下的情绪辨识度。
- 在浅色、浅灰和深色背景上检查轮廓清晰度。

### Manual Testing Checklist

- 四张概念样张在 40rpx 下明显优于原图。
- 基础情绪无需依赖标签即可辨认。
- 场景型表情的关键道具在小尺寸下仍可辨认。
- 没有永久选择态、底板或尺寸变化。
- 透明边缘无色边、毛刺或黑边断裂。
- 32 张整体风格一致。
- 表情资源总体积没有明显增长。
