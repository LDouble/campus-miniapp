# OUSea小程序：校园生活顶部 Bar Figma 复刻

**Priority:** High
**Status:** Completed
**Type:** Enhancement
**Created:** 2026-08-19
**Last Updated:** 2026-08-19

## 概述

依据 Figma 文件 `tQIWc49y8TRDwAVYSdllBU` 的节点 `173:837`、`171:324` 和 `171:572`，重构校园生活聚合页顶部 Bar。覆盖社区、闲置、跑腿和找同行四个业务状态，只处理顶部标题、搜索入口、一级业务导航及各业务真实筛选，不修改底部自定义 TabBar，也不重构内容卡片。

## 用户故事

**作为** 使用校园生活聚合页的学生

**我希望** 社区顶部 Bar 与最新 Figma 设计保持一致

**从而** 能以更清晰、紧凑的方式完成搜索、业务切换和社区板块筛选

## 设计依据

- Figma 文件：`tQIWc49y8TRDwAVYSdllBU`
- 社区目标节点：`173:837`
- 闲置默认筛选态：`171:324`
- 闲置类型下拉展开态：`171:572`
- 参考画布：约 `403 × 2038px`
- 顶部 Bar 参考高度：约 `184px`，其中状态栏区域约 `48px`
- 内容水平边距：`16px`
- 标题：`24px / 32px`，深色 `#1A2333`
- 搜索入口：`36px` 高、胶囊圆角、半透明 `#F3F4F6`
- 一级导航：选中项 `18px` 粗体并带 `#2B7AEF` 下划线；未选中项 `16px`、`#6B7A90`
- 社区二级筛选：`32px` 高胶囊；选中态为 `rgba(43,122,239,0.1)` 与 `#2B7AEF`，未选中态为 `#F7F7F7` 与 `#6B7A90`
- 跑腿、闲置和找同行顶部筛选：无论当前是否选择具体值，均保持默认灰色背景和深色文字，仅切换显示的筛选文案

## 范围

### 包含

1. 重组社区页顶部 Bar 的结构，使标题、搜索入口和微信胶囊安全区按 Figma 对齐。
2. 将「全部 / 闲置 / 跑腿 / 找同行」一级业务导航改为 Figma 的文字标签和蓝色短下划线样式。
3. 将服务端下发的社区根板块继续作为二级筛选数据源，并改为 Figma 的浅色胶囊样式。
4. 将闲置、跑腿和找同行的现有真实筛选提升到顶部 Bar，并统一为 Figma 的紧凑筛选控件。
5. 实现闲置类型筛选的顶部锚定下拉层、遮罩、选中勾选和关闭行为；不使用底部抽屉替代。
6. 保留搜索入口聚焦真实输入框、业务切换、模块开关、筛选请求、状态恢复和无障碍标签。
7. 保持横向滚动在微信小程序中的 `white-space: nowrap` 与行内布局兼容。
8. 在常见手机宽度下保留微信原生右上角胶囊的安全空间。

### 不包含

- 不修改底部 `custom-tab-bar` 的结构、样式或交互。
- 不修改社区帖子卡片、运营区、分页、点赞、评论和分享逻辑。
- 不新增推荐、关注或排序接口，不创建无真实查询能力的装饰筛选；跑腿只展示校区能力，找同行只展示现有日期、路线、人数和校区能力。
- 不硬编码服务端板块 ID、示例头像、示例图片或帖子文案。
- 不修改后端 API、数据库或数据模型。

## 实现方案

1. 继续使用现有 `CustomNavbar` 与 `getNavbarMetrics()` 获取状态栏、导航栏和微信胶囊安全宽度。
2. 在 `CommunityPage` 中将顶部标题、搜索入口、一级业务导航、社区根板块导航和三类业务筛选组织为明确的顶部 Bar 结构。
3. 将校区、闲置和找同行筛选值提升为受控状态，列表面板继续负责搜索、请求、分页和结果展示。
4. 保留 `lifeBusinessThemeList`、`communityRoots` 及现有筛选类型作为真实数据源，不复制第二套配置。
5. 使用 rpx 还原 Figma px 规格，并以弹性布局处理不同设备宽度。
6. 搜索入口仍调用现有 `focusSearch()`，社区和业务筛选仍更新现有请求参数，避免视觉控件与真实行为脱节。
7. 不引入新依赖；Taro `ScrollView` 继续使用 `scrollX`、`enhanced` 和 `showScrollbar={false}`。

## 验收标准

1. 四个业务首屏顶部 Bar 的垂直节奏、左右边距、字号、颜色、圆角和选中态与对应 Figma 节点一致。
2. 标题与搜索框不会进入微信原生胶囊区域，窄屏下搜索提示可安全截断。
3. 一级业务切换继续驱动全部、闲置、跑腿和找同行的真实页面内容。
4. 社区二级筛选继续使用服务端启用根板块，并保持真实查询语义。
5. 闲置类型下拉从顶部筛选栏下方展开，选中项、遮罩、下圆角和阴影与 `171:572` 一致。
6. 闲置、跑腿和找同行只展示真实可用筛选，改变筛选后继续驱动现有 API 请求；顶部触发控件保持正常灰色样式，仅文案反映当前值，不显示蓝色选中态。
7. 点击搜索入口仍能聚焦现有搜索输入并滚动到可见位置。
8. 下拉刷新、页面返回状态恢复、重复点击社区 Tab 回顶和运行时模块开关无回归。
9. 底部自定义 TabBar 与内容卡片无行为改动。
10. 页面滚动时，列表内容和顶部筛选不得穿透系统状态栏区域。

- 点击搜索入口，确认真实输入框可见并获得焦点。

## 风险与约束

- Figma 使用固定画布，实际设备的状态栏和微信胶囊尺寸不同；应以 `getNavbarMetrics()` 的真实测量值优先，并保持视觉比例。
- Figma 示例二级筛选文案不等同于当前服务端板块树；本任务只复刻视觉，不伪造不存在的推荐或关注查询能力。
- 微信开发者工具当前登录状态可能过期；若无法恢复登录，先完成构建与静态验证，并明确记录未完成的截图验证。
