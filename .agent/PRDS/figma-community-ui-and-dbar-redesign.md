# 小程序：Figma 社区聚合页与 dbar 视觉复刻

**Priority:** High
**Status:** Done
**Type:** Enhancement
**Created:** 2026-08-15
**Last Updated:** 2026-08-15

## 概述

依据 Figma 文件 `tQIWc49y8TRDwAVYSdllBU` 中 4 个指定节点，对校园社区聚合页的头部、业务切换、筛选区、社区动态、跑腿任务、二手商品、拼车行程以及底部 `dbar` 进行视觉复刻。改造目标是让真实小程序页面尽量贴近设计稿，同时继续使用现有 Taro 组件、服务端数据、筛选参数、发布入口和页面跳转逻辑。

## 用户故事

**作为** 校园小程序用户  
**我希望** 社区及各校园生活业务页面与最新 Figma 设计保持一致  
**从而** 在统一、清晰的界面中快速浏览内容、筛选业务并完成发布或查看详情

## Figma 依据

- 节点 `4:585`：二手闲置双列商品页面与闲置选中态。
- 节点 `4:852`：跑腿任务页面与跑腿选中态。
- 节点 `4:1051`：拼车行程页面与拼车选中态。
- 节点 `3:2`：社区综合内容流、公告卡片和全部选中态。

四个节点共同定义以下视觉基线：

- 页面背景为 `#F4F7FB` / `#F5F7FA`，顶部使用 `#EFF6FF` 向透明过渡的浅蓝背景。
- 顶部内容使用约 32rpx 水平边距，标题与胶囊搜索框同排。
- 一级业务标签使用白色胶囊；选中态使用 `#2B7FFF` 到 `#00D3F3` 的横向渐变和蓝色阴影。
- 主文本使用 `#1D293D`，辅助文本使用 `#62748E`、`#90A1B9` 和 `#45556C`。
- 内容卡片为白色、约 32–40rpx 圆角和克制的浅阴影。
- 底部 `dbar` 为半透明白色悬浮胶囊，中央发布按钮向上凸起并使用蓝青渐变。

## 范围

### 页面头部与业务切换

1. 将现有标题、搜索入口、一级业务导航整合为 Figma 中的紧凑头部。
2. 一级业务名称继续来自现有业务配置，不新增写死的服务端板块 ID。
3. 搜索继续聚焦现有真实搜索输入或触发现有搜索流程，不创建无功能的装饰输入框。
4. 当前业务标签使用统一蓝青渐变，不再使用四业务各自的旧主题色选中线。
5. 结构化筛选保留现有有效查询能力，但外观改为 Figma 的浅色胶囊样式。

### 社区内容流

1. 对齐节点 `3:2` 的白色大圆角单列卡片。
2. 保留真实作者、时间、板块、正文、图片、位置与互动数据。
3. 公告或置顶内容采用紧凑横向卡片，普通动态使用作者头部、正文、媒体、标签和互动栏结构。
4. 点赞、评论、分享和详情跳转继续沿用现有行为。

### 跑腿任务

1. 对齐节点 `4:852` 的单列任务卡片结构。
2. 突出任务标题、说明、取送地点、期望送达时间和赏金。
3. 使用圆点与信息面板表达路线，保留真实状态、标签和互动信息。
4. 不添加接口不支持的排序或筛选条件。

### 二手闲置

1. 对齐节点 `4:585` 的双列商品网格。
2. 图片、标题、价格、卖家和收藏数按设计层级展示。
3. 图片状态标签与更多操作位于图片上方；无图片时保留现有占位策略。
4. 保留现有价格筛选和详情跳转逻辑。

### 拼车行程

1. 对齐节点 `4:1051` 的单列行程卡片结构。
2. 突出标题、说明、起终点、出发时间、费用与人数信息。
3. 保留现有日期、路线和座位筛选能力，不编造车型或认证字段。

### dbar

1. 调整 `custom-tab-bar` 为 Figma 的悬浮白色胶囊：左右约 48rpx 页面边距、约 48rpx 圆角、半透明白色背景和柔和阴影。
2. 普通图标使用约 40rpx 尺寸，文字使用约 20rpx；未选中态为灰蓝色，选中态为 `#2B7FFF`。
3. 移除旧的暖橙色选中胶囊与暖色发布按钮。
4. 中央发布按钮使用约 96rpx 圆形、蓝青渐变、白色描边和蓝色投影，并向上凸起约 40rpx。
5. 消息未读红点保持现有数据能力并按 Figma 位置与尺寸展示。
6. 继续适配 `env(safe-area-inset-bottom)`，不遮挡列表尾部内容。

## 非目标

- 不修改业务状态机；为卡片展示真实发布者资料，可向现有只读 View 补充昵称与头像字段。
- 不修改详情页和发布页的信息架构，除非为保证入口或底栏兼容需要极小调整。
- 不引入新的 UI 组件库、网络字体或大体积装饰资源。
- 不把 Figma 示例文案、示例价格、示例头像或示例图片写入生产数据。
- 不为了视觉复刻移除现有加载、错误、空状态和分页能力。

## 技术实现

### 架构方案

- 继续使用 Taro React、TypeScript、SCSS 与原生微信自定义 TabBar。
- 保留 `CommunityPage` 的业务切换、模块开关、搜索聚焦与发布逻辑。
- 在现有 `CommunityFeedPanel` 和 `LifeServiceListPanel` 及其业务卡片上调整结构与样式，避免复制第二套数据请求。
- 将 Figma 的 px 视觉规格按小程序 750rpx 设计宽度换算，并通过弹性宽度适配不同设备。
- 优先复用项目现有 SVG 图标；仅在现有图标无法匹配时下载并提交 Figma 导出的原始资源。
- 交互元素使用 `hoverClass` 或现有点击反馈，主要触控区不小于 88rpx。

### 设计细节

- 页面主体底部预留 dbar 与安全区高度，避免最后一张卡片被遮挡。
- 固定或粘性头部保持透明度和层级稳定，不产生横向滚动。
- 商品图片与社区媒体预留固定容器，继续启用懒加载以减少内容跳动。
- 动效控制在 150–300ms，并兼容 `prefers-reduced-motion`。
- 普通正文和背景保持足够对比度；重要状态除颜色外保留文字。

## 验收标准

1. 社区、跑腿、二手、拼车四个业务状态的头部、标签、内容卡片与提供的 Figma 节点视觉一致。
2. `dbar` 的背景、圆角、阴影、图标、文字、选中态和中央发布按钮与 Figma 一致。
3. 四业务切换、搜索、结构化筛选、发布、详情、点赞、评论和分享等现有交互无回归。
4. 底栏在带安全区与不带安全区设备上均不遮挡内容，中央按钮可正常点击。
5. 动态接口数据正常渲染，缺图、空列表、加载失败与加载更多状态仍可用。
6. 构建、现有 smoke 测试和微信开发者工具编译通过。
7. 在至少一个常见手机视口完成社区、跑腿、二手、拼车与 dbar 截图核对。

## 测试要求

### 自动化验证

- 执行 TypeScript / Taro 生产构建。
- 执行社区与校园生活相关 smoke 测试。
- 检查自定义 TabBar 资源路径与编译产物。

### 手工验证

- 分别切换社区、跑腿、二手、拼车并核对头部选中态。
- 检查搜索与筛选条件能触发真实数据变化。
- 检查四类列表卡片的长标题、缺图、空状态和分页。
- 检查 dbar 四个普通入口、中央发布入口和消息未读点。
- 检查 iPhone 安全区下底栏、发布按钮和列表末尾的相对位置。

## 风险与处理

- Figma 使用约 393px 固定画布：实现时使用 rpx 与弹性布局，避免只适配单一机型。
- 设计稿包含演示字段：仅映射现有接口真实字段，缺失信息不伪造。
- Figma 图标资源链接会过期：需要使用时下载并提交原始资源，不在代码中保留临时 URL。
- 自定义 TabBar 同时服务多个主页面：样式调整后需回归首页、社区、消息和我的四个选中状态。
