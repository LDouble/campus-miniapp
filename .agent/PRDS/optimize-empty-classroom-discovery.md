# 海大校园小程序：优化自习室筛选与全天空闲视图

**Priority:** High
**Status:** Done
**Type:** Enhancement
**Created:** 2026-08-13
**Last Updated:** 2026-08-13

## 一、需求概述

当前空教室页面以自然日期和连续节次查询为主，用户无法快速聚焦某一栋教学楼，也无法按“教学周 + 星期”组织查询，更看不到一间教室从第 1 节到第 12 节的完整空闲变化。

本次优化将页面调整为面向自习场景的全天发现视图：选择校区、教学周和星期后，一次加载当天全部教室的 1—12 节空闲情况，再按楼栋即时筛选。空闲结果必须以现有课程占用页维护的“学期 + 教学周 + 星期 + 起止节次”记录为主数据，不能仅根据自然日期推测。

## 二、用户故事

**作为** 想找自习教室的同学  
**我希望** 按校区、楼栋、第几周和星期几筛选，并看到教室一天内各节次的空闲情况  
**从而** 不必反复切换节次查询，也能快速判断哪间教室适合连续自习。

## 三、范围与交互

### 3.1 筛选区域

筛选区按以下顺序组织；页面不提供自然日期选择和按节次查询，始终展示所选教学日的全天情况：

1. **校区**
   - 延续现有校区选择。
   - 切换校区后重新查询全天数据，并将楼栋恢复为“全部楼栋”。

2. **教学周**
   - 通过 Picker 选择“第 1 周”至当前学期配置的 `week_count`。
   - 默认选中当前教学周；学期尚未开始时默认第 1 周。

3. **星期**
   - 显示周一至周日七个选择项。
   - 周一固定为 1，周日固定为 7。
   - 周次和星期共同换算为服务日期，并在页面上同时展示实际日期。

4. **楼栋**
   - 全天结果返回后，从楼栋分组派生“全部楼栋”和各楼栋选项。
   - 切换楼栋只过滤本地结果，不重复请求。

### 3.2 全天空闲视图

- 每间教室展示名称、类型和容量。
- 展示第 1 至第 12 节的紧凑时间格：空闲与已占用使用可区分的颜色和文字语义。
- 同时把连续空闲节次汇总成易读文本，例如“1—2、5—8、11—12 节空闲”。
- 全天没有任何空闲节次的教室仍可展示完整占用状态，帮助用户理解当天情况。
- 结果继续按楼栋分组；默认折叠或分批展示较长列表，避免一次渲染数千个节点。
- 页面保留“课表和已审核反馈推算，不代表现场实时状态”的提示。

### 3.3 占用反馈

- 用户点击教室后仍可发起占用反馈。
- 反馈时选择具体起止节次，继续使用现有反馈接口与审核机制。

## 四、后端方案

### 4.1 兼容性策略

保留现有接口，不改变其请求或响应：

```text
GET /api/v1/classrooms/available
```

新增独立的全天查询接口：

```text
GET /api/v1/classrooms/availability/day
```

请求参数：

| 参数 | 必填 | 说明 |
|---|---:|---|
| `campus` | 是 | 校区名称 |
| `period_id` | 是 | 教学校历学期 ID |
| `teaching_week` | 是 | 教学周，范围 1 至学期 `week_count` |
| `weekday` | 是 | 星期，周一为 1、周日为 7 |

服务端根据校历计算 `service_date`，不信任客户端自行拼接的日期；计算结果必须落在对应学期内。请求中的 `period_id + teaching_week + weekday` 与现有课程占用管理页、`classroom_occupancies` 表使用完全相同的语义。

### 4.2 响应模型

全天响应至少包含：

- 校区、学期 ID、教学周、星期和实际日期。
- 数据更新时间与非实时说明。
- 按楼栋分组的教室列表。
- 每间教室第 1 至第 12 节的可用状态；传输层使用紧凑的 `available_sections` 数字数组，避免为 382 间教室重复传输 12 个冗长对象。

示意：

```json
{
  "campus": "崂山校区",
  "period_id": "2026:2",
  "teaching_week": 3,
  "weekday": 2,
  "service_date": "2026-09-22",
  "max_section": 12,
  "groups": [
    {
      "building": "教学楼2区",
      "classrooms": [
        {
          "classroom": { "id": 68, "room": "2505" },
          "available_sections": [1, 2, 5, 6, 7, 8, 11, 12]
        }
      ]
    }
  ]
}
```

### 4.3 查询实现

- 先按 `active + campus` 一次读取教室。
- 首先读取课程占用页维护的 `source_type=schedule + period_id + teaching_week + weekday` 周期占用，这是判定当天课程占用的主要依据。
- 再读取 `service_date` 对应的管理端临时占用和已审核学生反馈。
- 合并课程占用、临时占用和已审核反馈；任一来源覆盖某节次，该节次即为已占用。
- 两类占用分别查询并利用现有两组索引，避免带 `OR` 的全表式查询。
- 每条占用只读取教室 ID、开始节次和结束节次。
- 在应用层把占用区间合并为 1—12 节状态。
- 全程避免按教室逐条查询和前端 6～12 次并发查询。

### 4.4 数据库影响

- `classrooms(status, campus, building)` 已支持校区和楼栋顺序读取。
- `classroom_occupancies` 已有日期占用索引和学期周次占用索引。
- 本次不新增字段、不修改表结构、不新增迁移。
- 只有后续通过 Production `EXPLAIN` 证明确有瓶颈时，才独立评估索引调整。

## 五、小程序方案

### 5.1 数据层

- 在空教室 repository 增加全天查询方法。
- 对后端数组字段执行运行时校验和空数组降级，避免异常响应导致页面崩溃。
- 在校历工具中增加“教学周 + 星期 → 日期”纯函数，供 UI 展示和测试使用；服务端仍是最终日期事实来源。

### 5.2 页面状态

- 保存当前学期、教学周、星期、校区和楼栋；服务日期只由教学周与星期推导，不作为筛选项展示。
- 只有校区、学期、周次或星期变化才请求接口。
- 楼栋变化只过滤已有分组。
- 使用查询标识避免快速切换筛选时旧响应覆盖新状态。

### 5.3 Taro 交互

- 教学周使用 Taro `Picker` 的 selector 模式，避免 20～30 个周次 Chip 挤占页面。
- 星期和楼栋使用横向 `ScrollView`；微信小程序端保持 `white-space: nowrap` 和子项不换行。
- 全天时间格采用普通 `View` 列表，不使用 Canvas，保证可访问文本和稳定点击反馈。

## 六、课程占用数据前置条件

### 6.1 当前 Production 状态

2026-08-13 只读核对 Production：

- `classrooms` 已有 382 条启用教室。
- `classroom_occupancies` 当前为 0 条。
- 因此在课程占用数据写入前，任何空教室接口都会把所有启用教室判断为空闲。

### 6.2 上线要求

- 新全天视图发布前，目标学期的课程占用必须通过现有课程占用管理能力导入或同步到 Production。
- 每条课程占用必须具备：`classroom_id`、`period_id`、`teaching_week`、`weekday`、`start_section`、`end_section`、`source_type=schedule` 和 `status=active`。
- 课程记录中的教室必须能映射到 Production `classrooms.id`；无法可靠匹配的记录进入待确认清单，不能静默绑定到相似教室。
- 历史服务器 `weouc.course` 可作为转换来源，但只允许导入与目标 `period_id` 对应的学期数据；禁止把过期学期数据复制为当前学期占用。
- 导入前必须生成预览、统计匹配率并备份 Production 目标表；正式导入需使用事务并验证重复课程占用。
- 若当前学期课程数据尚未准备好，页面需要明确展示“课程占用数据待同步”，不能把结果表达为可靠的全天空闲状态。

## 九、验收标准

- 用户可以筛选校区和楼栋。
- 用户可以选择第几教学周和星期几，并看到对应实际日期。
- 用户可以在一个页面内查看每间教室第 1 至第 12 节的全天空闲情况，且页面不再提供自然日期或按节次筛选。
- 楼栋筛选即时生效且不产生额外网络请求。
- 全天数据只需一次接口请求，不产生逐教室或逐节次请求。
- 空闲结果正确叠加课程占用页按周维护的数据、临时占用和已审核反馈。
- 目标学期课程占用未同步时有明确告警，不输出误导性的全天空闲结果。
- 原有空教室查询、微信 AI handoff 和占用反馈不回归。
- 后端无需数据库迁移，现有 Production 教室数据可直接使用。
