## 问题与固定参照

上轮表单仍为粗标题、逐字段外框和短竖线分区；主操作使用旧焦糖色，与已确认首页及详情不一致。
本轮以现有 catalog.scss 与 atlas.scss 的 Figma 详情区块为固定参照，不重新设计首页或详情。

## 改造方案

- 发现新猫：顶部仅保留轻量导航与一句说明；第一视觉焦点为全宽照片上传区，上传后展示真实照片；校区、地点、名字归入一个紧凑信息组，特征备注不再单独堆叠厚重卡片。
- 我遇见了：简短猫咪名称和记录说明；照片区、地点与活动选择、备注组成轻量记录表单。照片仍可选，不为未上传照片填入假内容。
- 最近动态：收起大宣传文案和独立引导卡，改成猫咪名称、真实记录数和轻量记录入口；正文沿用首页的全宽照片 Feed，作者、时间、活动、地点分清主次。
- 三页统一轻量导航字号、圆角、边框和焦糖操作色，以首页/详情 #C86230 为参照；需要的值先登记到 Ousea 业务令牌并同步 CSS、Sass、文档、检查，不新增另一套页面私有颜色。
- 移除粗重分区竖线、重复星号和卡片套卡片；保留必要的必填说明与出错反馈。

## 业务与安全边界

- 保留用户点击后 choosePoi/getLocation、取消定位保留原选择、“其他”手输及位置回显。
- 新猫须照片上传成功后才能提交；普通目击照片可选。上传、重试、删除、进度、预览和提交防重复不降级。
- 最近动态保留活动状态、分页、下拉刷新、原图预览和点赞防重复。
- 导航与底栏固定，避让胶囊、键盘和底部安全区；触控区域至少 88rpx。
- 不变更后端、数据库、审核策略、发布环境、收藏能力和 API 契约。
- 当前 Feature 工作区构建，通过环境变量使用 http://localhost:8080，不合并 release。

## 实施范围

- report.tsx、report-journal.scss：两个表单的结构与交互布局。
- sightings.tsx、sightings-journal.scss：信息流与记录入口布局。
- 按需增加三个页面共享的基础样式，避免重复覆写。
- 同步 Ousea 令牌源、运行时、Sass 映射与页面规范；更新相关烟雾检查。

## 验收

- 对照首页及详情截图核对导航字号、强调色、卡片圆角、正文层级和照片比例。
- 320、360、375px 宽度检查长名字/地点无横向溢出；浅色和暗色可读。
- 进入页面不自动定位；手输、上传状态、空动态、分页错误可操作。
- lint、typecheck、design-tokens、typography、dark-mode、cat-atlas 检查与 build:weapp 通过。
- 开发者工具查看三个页面首屏及滚动状态；记录实际本地请求域名。不以截图成功代替投稿闭环测试。

## 技能约束
