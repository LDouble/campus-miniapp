# OUSea小程序：修复教务密码持久化与首页学期标签口径

**Priority:** High
**Status:** Done
**Type:** Bug
**Created:** 2026-08-09
**Last Updated:** 2026-08-09

## 一、问题概述

当前教务凭据仅保存在 JavaScript 运行时的 `Map` 中，小程序进程关闭或重新启动后内存被清空，导致用户必须重新输入教务密码。现有页面文案和冒烟测试也明确限制凭据不得进入本地存储，与用户期望的“保存在本机并跨重启使用”不一致。

首页左上角学期标签来自公共校历数据，课表卡片来自教务系统返回的学期与课程数据。两个数据源的学期边界可能不同，导致左上角显示的开学日期或教学周与课表卡片不一致。

## 二、修复目标

- 已成功验证的教务凭据保存在当前微信小程序的本地存储中，小程序重启后可以继续查询教务数据。
- 凭据按当前平台用户 ID 隔离，不允许账号切换后复用其他账号的凭据。
- 凭据只保存在本机，不新增后端存储或接口。
- 账号注销、明确解绑或凭据失效时能够删除对应本地凭据。
- 首页左上角标签与课表卡片统一使用同一份教务学期数据和同一套日期计算逻辑。

## 三、根因

### 3.1 教务密码

- `src/api/academic-credential.ts` 使用模块级 `Map` 保存凭据。
- `loadAcademicCredential` 只读取该 `Map`，没有本地存储回退。
- `scripts/academic-credential-smoke.ts` 当前断言源码不能包含 `StorageSync`。
- 因此小程序重新启动后凭据必然消失。

### 3.2 开学时间

- 首页 `academicCalendarLabel` 通过 `features/calendar` 的公共校历计算。
- 首页课表卡片通过 `AcademicScheduleCache.periods` 的教务学期计算。
- 公共校历的 `term.start_date/end_date` 与教务学期的 `startDate/weeks` 不保证完全一致。

## 四、技术方案

### 4.1 本机凭据持久化

- 增加带版本号的本地存储结构，包含平台用户 ID、学号、教务密码和培养层次。
- `saveAcademicCredential` 在验证成功后同时更新运行时缓存和本地存储。
- `loadAcademicCredential` 优先读取运行时缓存；缺失时读取本地记录，严格校验结构和平台用户 ID 后恢复运行时缓存。
- 发现损坏、跨用户或非法记录时拒绝加载并清理无效数据。
- `clearAcademicCredential` 同时清理运行时记录和对应本地记录。
- 账号注销继续通过既有本地数据清理流程删除凭据。
- 更新认证页说明，明确“仅保存在本机，可在设置中更新；不会新增服务端持久化”。

### 4.2 首页学期口径统一

- 首页左上角不再单独请求公共校历来计算学期标签。
- 使用与课表卡片相同的 `AcademicScheduleCache.periods` 计算“第 N 周”“M 月 D 日开学”或“本学期已结束”。
- 首页首次展示读取同一份课表缓存；刷新后使用同一次教务学期请求的结果同时更新标签和课表卡片。
- 独立校历页面仍保留公共校历数据，不改变校历功能。

## 五、安全边界

- 微信小程序本地存储属于应用沙箱，但不是系统钥匙串，也不提供可由前端独立保管密钥的强加密能力；该方案会使教务密码以可恢复形式保存在本机小程序存储中。
- 不使用 Base64 或固定密钥“加密”制造虚假安全感。
- 不在日志、错误上报、路由参数或远程配置中输出凭据。
- 不把凭据同步到后端。
- 用户需明确接受上述本机存储风险后实施。

## 六、拟修改文件

- `src/api/academic-credential.ts`：增加用户隔离的本地凭据读写、校验和清理。
- `src/pages/academic-verification/index.tsx`：更新密码保存说明。
- `src/pages/index/index.tsx`：统一左上角和课表卡片的学期数据源。
- `scripts/academic-credential-smoke.ts`：将“禁止本地存储”断言改为持久化、隔离和清理行为测试。
- 必要时补充首页学期标签的语义冒烟测试。

## 七、测试要求

- 保存凭据后清空运行时状态，仍能从本地存储恢复同一用户凭据。
- 不同平台用户无法读取彼此凭据。
- 非法或损坏记录会被拒绝并清理。
- 清除凭据后运行时和本地均不可读取。
- 首页左上角与课表卡片对当前、假期、临近开学和学期结束场景使用同一教务学期。
- `yarn typecheck`、`yarn lint`、既有冒烟测试和 `yarn build` 全部通过。

## 八、验收标准

- 小程序完全关闭并重新打开后，已验证用户无需重新输入教务密码即可刷新课表、成绩等数据。
- 切换到不同平台账号时不会复用原账号教务凭据。
- 左上角开学日期或教学周与首页课表卡片一致。
- 完整版和个人资格版行为一致，不增加后端改动。

---

**实施说明：**

本修复会改变此前“密码仅在本次运行期间保留”的安全策略。实施前需要用户确认接受教务密码以可恢复形式存放在微信小程序本地沙箱中。
