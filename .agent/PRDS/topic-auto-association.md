# 跨端：社区 AI 自动话题关联与话题广场

**Issue:** [#181](https://github.com/LDouble/campus-miniapp/issues/181)
**Priority:** High
**Status:** In Review
**Type:** Feature
**Created:** 2026-09-02
**Last Updated:** 2026-09-02

## 概述

将现有社区的单话题能力升级为可运营的话题广场和帖子多话题关联能力。用户发布帖子时无需浏览底部完整话题列表；系统通过用户显式 `#话题`、手动选择和 Water 大模型异步分类自动关联话题。没有关联结果时，帖子保持正常发布且不展示任何占位标签；关联完成后，标签再出现在社区主流、帖子详情和话题流。

选课专区是首个运营话题，但实现必须是通用话题能力，后续可用于迎新、复习、社团、毕业季等主题运营。

## 目标与成功标准

- 帖子只存一份，同时可在社区主流和一个或多个话题流获得曝光。
- 一篇帖子最多关联 3 个话题，其中恰有 1 个主话题和最多 2 个辅助话题。
- 用户显式标签和手动选择优先于 AI；AI 不覆盖用户已确认的关联。
- Water 对高置信度内容异步关联已有话题，失败、超时或低置信度时不影响帖子发布。
- 用户新输入的不存在话题可经自动安全审核、去重与限流后自动创建；不进入人工审核队列。
- 社区首页提供话题广场入口；帖子卡片和详情中的话题均可点击进入对应话题页。

## 用户故事

**作为** 希望讨论课程选择的学生，
**我想** 正常写帖子后自动进入相关选课、课程或老师话题，
**以便** 获得更精准的讨论和回复，同时仍能被社区主流用户看见。

**作为** 运营人员，
**我想** 配置和查看话题、别名、自动归类策略及效果，
**以便** 在选课期和其他校园节点持续运营内容，而不让话题库失控。

## 范围与非目标

### 范围

- 话题广场、话题详情、社区流和帖子详情的入口与展示。
- 发布页的自动识别结果、显式 `#话题` 解析、手动添加/替换话题。
- 帖子与话题多对多关联、主话题、关联来源和模型置信度。
- 基于 Water Worker 的异步模型分类、自动安全审核、重复合并和自动新话题创建。
- 管理端的话题运营和自动关联规则管理。
- 与旧 `topic_id` 的兼容读取和迁移。

### 非目标

- 不等待模型结果才发布帖子，不在发布页显示“正在整理话题”等占位反馈。
- 不允许无限数量的标签、自由标签云或同义词话题无限增长。
- 不让模型直接修改帖子正文、审核状态、可见范围或社区板块。
- 不将 AI 分类结果作为内容安全审核的替代。

## 产品与交互设计

### 社区首页与话题广场

- 在社区首页搜索区下方增加“热门话题”横向入口；选课期将“选课专区”置于首位，并以小型 `选课中` 状态点提示运营期。
- 常态入口与其他话题保持同一视觉语言，不新建独立选课品牌或抢占首页大卡片。
- 点击话题卡进入既有话题详情页；话题页扩展为可承载阶段信息、攻略入口和讨论筛选的通用模板。
- 主社区流继续展示所有符合板块范围的帖子。带话题帖子在元信息中显示主话题和辅助话题计数，例如 `#选课专区 +1`，点击主话题进入详情，点击 `+1` 查看全部关联话题。

### 帖子详情

- 正文前展示全部关联话题，采用轻量可点击文字标签，不做厚重胶囊。
- 无关联话题时完全不渲染该区域，不保留空白或提示语。
- 话题关联在异步完成后通过下次刷新、重新进入或局部数据更新出现；无需提示用户等待。

### 发布页

- 删除“关联话题（可选）”下平铺所有活跃话题的交互。
- 用户输入内容后，客户端只展示已确认或已建议的最多 3 个话题；每个话题可以删除，用户可通过“添加或更换话题”打开按名称搜索的选择器。
- 正文中的 `#名称` 优先解析。匹配既有话题或别名时直接关联；未匹配时将名称提交为创建候选，而非立即在客户端伪造话题 ID。
- 发布前可展示已确认的关联，发布后不因模型任务未完成显示任何占位。
- 用户手动选择或显式标签的来源为 `manual` 或 `hashtag`，优先级高于规则与 AI。

## 归类与自动创建规则

### 优先级

1. 用户手动添加或移除的话题。
2. 用户正文中的显式 `#话题`。
3. 运营规则的确定性匹配，例如别名、课程代码或活动时间窗口。
4. Water 模型返回的高置信度关联。

低优先级来源不得覆盖高优先级来源；冲突时记录审计原因并保留用户选择。

### Water 异步关联

- 复用现有 Water Worker 的队列、幂等、重试、超时、响应大小限制和 OpenAI-compatible Responses API 配置。
- 在帖子完成既有内容审核并可见后投递话题分类任务；任务包含帖子 ID、版本、板块、正文摘要和受限的活跃话题目录，不携带不需要的用户资料。
- 模型只返回结构化 JSON：已有主话题 ID、已有辅助话题 ID 列表、置信度、是否建议创建新话题、建议名称与简短理由。
- 后端校验所有模型返回的 ID 必须在输入目录中，限制 1 个主话题和 2 个辅助话题；模型不能任意写数据库字段。
- 只有达到配置阈值的关联生效。模型异常、任务过期、内容编辑、撤回或审核状态变化时丢弃结果并可安全重试。

### 自动新话题

- 仅当显式标签或模型候选未命中已有话题及别名时触发。
- 自动审核包括名称长度和字符规范化、敏感词与广告拦截、相同 slug 去重、近似名称合并、用户创建频率限制和运营期规则检查。
- 审核通过后创建为活跃但非热门的系统话题，并与首帖关联；未通过时不创建话题、不显示标签，原帖子保持可见。
- 自动话题默认不进入热门话题入口；达到可配置的讨论量、热度阈值或运营人员置顶后才被推荐。
- 所有自动创建、合并和拒绝事件记录来源、规则版本、模型置信度与理由摘要，供管理端审计和调优。

## 数据与 API 契约

### 数据模型

- 新增 `campus_circle_post_topics` 关联表：`post_id`、`topic_id`、`role(primary|secondary)`、`source(manual|hashtag|rule|ai)`、`confidence`、`rule_version`、`created_at`。
- 为每个帖子建立“最多一个主话题”的数据库约束或事务校验，并建立话题公开流分页索引。
- 保留现有 `campus_circle_posts.topic_id` 作为兼容期主话题镜像。迁移时将历史非空 `topic_id` 写入关联表的 `primary` 记录；新写入同时维护镜像，待客户端迁移完成后再执行 contract 阶段。
- 扩展话题实体：别名、自动关联启用状态、运营时间、优先级、自动创建标记和热门资格；归类规则可独立成版本化规则表。

### API 演进

- 帖子创建/更新请求在兼容期新增可选 `topic_ids` 与 `primary_topic_id`，保留现有 `topic_id`。
- 帖子响应新增 `topics[]`、`primary_topic` 与关联来源摘要，保留 `topic` 字段映射主话题。
- 新增发布前话题建议接口，仅用于客户端即时建议；最终关联仍由发布事务和 Worker 决定。
- 新增管理端话题规则 CRUD、自动创建审计查询与话题合并接口。
- OpenAPI 源契约位于后端 `schemas/campus_circle.yaml` 与 `api/modules/campus_circle.yaml`，聚合 `api/openapi.yaml` 只通过生成更新。

## 跨端实施边界

### 后端

- 扩展校园圈领域模型、迁移、Repository、OpenAPI operation、权限和管理接口。
- 在现有 Water Worker 基础上增加独立的 `classify_topics` 任务类型与队列/指标，避免与纯水贴分流任务相互耦合。
- 实现关联优先级、自动创建安全规则、幂等与审计。

### 管理端

- 从后端 OpenAPI 同步生成客户端。
- 提供话题列表、详情、别名/运营期/优先级、自动规则、自动创建审计、合并与推荐开关。
- 管理端仅管理规则与运营展示，不承担实时模型推理。

### 小程序

- 社区首页增加热门话题入口；帖子卡片和详情支持多话题展示与跳转。
- 发布页替换平铺列表为自动识别结果和按需搜索选择器。
- 话题详情复用现有页面并扩展运营期组件；未关联帖子不显示空标签区域。

## 验收标准

- 社区首页能展示热门话题入口，选课专区可在运营期置前；点击后进入话题详情。
- 话题帖子同时出现在社区主流和关联话题流；无话题帖子不显示任何话题占位。
- 帖子详情和帖子卡片均能进入主话题；详情可查看全部关联话题。
- 发布页不再平铺全部活跃话题；用户可通过显式 `#`、自动建议或按需搜索关联话题。
- 一篇帖子最多一主两辅；用户显式或手动选择永不被 AI 覆盖。
- Water 高置信度结果自动生效，低置信度、失败、超时和过期任务不影响帖子可见性。
- 自动新话题通过自动安全审核、重复合并与限流后创建；失败时不创建也不展示标签。
- 历史单 `topic_id` 帖子在迁移后仍能正常显示、筛选和进入话题页。
- 后端、管理端和小程序按各仓库规范完成生成、迁移、单元/集成测试、类型检查、视觉与构建验证。

## 风险与缓解

- 模型误分类：仅接受受限目录 ID、高置信度阈值、用户优先级和审计回溯。
- 话题膨胀：名称归一化、近似合并、频率限制、自动创建不默认推荐。
- 模型延迟或不可用：异步任务、幂等重试、无标签降级，不阻塞发帖。
- 多话题迁移风险：采用 expand/contract，兼容保留旧 `topic_id` 与 `topic` 响应字段。
- 运营误操作：版本化规则、启停、审计日志和话题合并而非直接删除。

## 交付顺序

1. 后端完成关联表、兼容 API、Water 任务和审计契约。
2. 管理端同步契约并提供话题/规则运营配置。
3. 小程序接入多话题展示、话题广场和发布页自动识别体验。
4. 使用选课专区进行灰度验证，再开放其他运营主题。

## 实现前决策

- Water 模型的生产资源 ID、置信度阈值和新话题自动创建的日限额由发布配置确定。
- 自动创建话题的近似合并算法先采用可解释的归一化与词法相似度；语义合并可在收集误判数据后单独迭代。
- 是否向 Flutter App 同步首期展示能力需要在实施启动时确认；本 PRD 首期范围为小程序、后端和管理端。
