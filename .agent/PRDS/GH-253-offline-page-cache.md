# 首页、论坛、课表缓存优先与离线容错

## 目标

用户进入页面先看到本机上次成功加载的内容，后台刷新成功后更新；网络中断、超时或服务异常不清空已有内容。首次使用无缓存时，保留页面结构并提供明确的失败提示与重试入口，不能把失败显示成正常的空数据。

## 实现前现状

- 首页 `src/pages/index/index.tsx` 的 `loadHome` 在信息流失败分支执行 `setHomeFeedItems([])`，公告、任务、提醒等也将失败结果替换为空值；聚合请求中的未捕获拒绝还需要进一步检查。
- 论坛 `src/features/community/feed-panel.tsx` 使用模块内 Map 缓存，不能覆盖进程重启；有效缓存命中后直接返回，不符合每次先展示再后台刷新的目标。
- 论坛 `src/pages/community/index.tsx` 的板块加载失败会清空板块和选中 ID；热门话题失败也会清空。因此只缓存帖子无法保证论坛可用。
- 课表页已有按平台用户、学期隔离的持久化缓存及先展示再刷新的流程（`src/pages/academic/storage.ts`、`src/pages/academic/schedule/index.tsx`）；应复用并回归验证。缺失学期元数据时使用可重试状态，不凭课程桶猜测学期。
- 首页 `loadLatestAcademic` 仅在课程桶不存在时请求课程，有旧缓存时不会后台更新课程，需要修正。首页学术缓存异步写入还需防止旧请求覆盖新请求；课表页已有课程请求序号保护。

实现前风险：课表页在 mount 固定获取 `getActiveAcademicUserId`，冷启动凭据尚未恢复时可能为 0，导致无法命中或写回用户缓存。实现前需核查平台账号恢复顺序并建立冷启动直达课表用例，使用可靠身份恢复缓存，禁止以 0 作为私有缓存身份。

上述为实现前调查。下方验证记录说明已复现问题与实际验证边界。

## 范围与实现规则

1. 首页：信息流、公告等内容模块分别恢复缓存、分别处理刷新失败；个人状态按用户隔离。模块开关与现有权限规则继续生效。
2. 论坛：板块、热门话题及帖子列表均支持持久化恢复；按当前校区、身份、板块、关键词和排序隔离。分页缓存必须保留一致的页码和列表，刷新第一页后重置分页；限制缓存条数、列表长度和总体大小。
3. 课表：复用现有学期和课程缓存，进入后先显示对应用户、学期缓存再刷新。保留自定义课、蹭课和现有来源规则，失败不得改写成功数据。
4. 共享缓存包含版本、作用域、更新时间及经过结构校验的数据；损坏、旧版本、读写异常视为不可用缓存，不阻止联网流程。过期用于触发刷新，不因短时过期立即隐藏已有内容；已知权限失效或作用域变化必须失效。
5. 成功空响应是权威结果，覆盖旧内容与缓存；请求失败不得落盘为空结果。认证失效不能当成普通网络错误继续展示不应访问的私有数据。
6. 账号切换、退出和环境切换隔离缓存与内存状态；每次异步提交前校验请求序号和作用域，防止旧请求覆盖新页面或写入其他账号缓存。
7. 发布、删除、点赞、置顶、课表编辑及刷新应更新或失效相关缓存，不允许旧缓存复活已删除内容。
8. 有内容时刷新不使用遮挡内容的加载态，失败使用轻量提示和重试；无内容且失败时显示错误态。所有请求结束路径均收起刷新指示器。

## 非范围

不修改后端契约，不增加离线写操作，不预下载全部图片，不对其他业务页面全面改造，不启动发布环境。本地缓存仅表示上次成功内容，不保证离线状态下图片资源或写入操作可用。

## 验收矩阵

| 场景 | 预期 |
| --- | --- |
| 缓存后退出并重新进入，网络响应延迟 | 先显示正确作用域缓存，随后更新为响应内容 |
| 已有内容时断网、超时、5xx | 内容保留，提示失败并可重试，加载态结束 |
| 首次使用且网络失败 | 页面结构可见，明确错误和重试入口，不误报无数据 |
| 请求成功返回空列表 | 正常空态，并覆盖旧缓存 |
| 存储损坏、版本不兼容、空间不足 | 页面不崩溃，网络加载仍执行 |
| 切换账号、校区、板块、筛选、学期或 API 环境 | 不展示其他作用域内容，旧请求不能覆盖新结果 |
| 第一页刷新与分页并发 | 去重且页码一致，不混入旧查询数据 |
| 删除、点赞、置顶或课表编辑后重进 | 不回滚为操作前缓存；失败操作不冒充成功 |
| 论坛板块接口失败但有缓存 | 仍可显示缓存板块和帖子 |
| 课表验证/学期/课程请求失败 | 同用户有效缓存仍可查看，首次失败不显示成无课 |

## 验证计划

先对当前缺陷建立可重复的行为用例，确认旧代码失败，再验证修复后通过；新增缓存读写、隔离及乱序测试，复用首页、论坛与课表既有回归脚本。运行 yarn lint、yarn typecheck、yarn test:design-tokens、yarn test:typography、yarn test:dark-mode、yarn build:weapp。使用微信开发者工具验证有缓存冷启动、延迟刷新、断网重试、切换作用域与恢复联网；若工具或环境不可用，明确标记未验证，不以静态测试替代真实交互。

## 实现结果

- 通过独立的本地展示身份恢复首页、论坛及课表缓存，不等待授权或配置接口。展示身份不授予接口权限；退出、切换账号和明确凭据失效仍清理会话。
- 首页模块分别刷新，单个接口挂起不阻塞其它模块。论坛板块、话题与首屏帖子，以及首页热聊均持久化；成功空响应覆盖旧结果，失败保留已有内容。
- 新页面缓存按 API 环境、会话代次、用户与查询维度隔离；无可信本地身份不读取私有页面缓存。结构校验、容量限制、存储异常兜底及旧响应防回写已接入。
- 课表沿用现有用户与学期缓存，以同步恢复的用户身份读取；自定义课增加账号隔离，未知归属的历史数据不自动归给新账号。
- 发布等内容变更失效信息流缓存，签到缓存按当天读取；分页继续使用内存状态，持久化以首屏为主。
