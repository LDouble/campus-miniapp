# 海大校园平台：社区与生活服务去标题字段迁移

**Priority:** High
**Status:** Done
**Type:** Migration
**Created:** 2026-07-26
**Last Updated:** 2026-07-26

## 概述

删除社区动态、跑腿任务、二手商品和拼车行程的独立资源标题字段。四类业务不再套用“标题 + 正文”的通用内容模型，而是由正文、描述、路线、时间、价格、报酬等业务字段直接承担信息表达。

调整覆盖小程序列表、详情、统一发布器、本地草稿、搜索、OpenAPI、Go 领域模型、数据库迁移、审核视图、订单快照和测试数据。

当前平台尚未上线，也没有真实业务数据。现有本地演示数据、测试数据和开发草稿均可丢弃，本任务不提供存量数据转换或旧客户端兼容。

## 用户故事

**作为** 发布或浏览校园服务的学生

**我希望** 直接看到正文、物品描述、跑腿路线或拼车路线

**从而** 不需要为了提交表单额外编写一个与业务字段重复的标题，也能快速理解内容。

## 字段边界

本任务删除的是资源领域字段：

- `CampusCirclePost.title`
- `ErrandView.title`
- `MarketplaceListingView.title`
- `CarpoolTripView.title`
- 对应创建、更新请求中的 `title`
- 对应数据库表中的 `title` 列

以下同名概念不属于资源字段，继续保留：

- 页面导航栏标题，例如“动态详情”“跑腿详情”
- Taro `showToast`、`showModal` 的 `title` 参数
- 发布器头部“分享校园动态”等页面说明
- 筛选面板、空状态和配置对象的界面标题
- 订单领域自身的 `title_snapshot` 字段，但其值不再读取业务资源标题

## 展示模型

| 业务 | 列表主要信息 | 详情主要信息 | 发布器主要输入 |
| --- | --- | --- | --- |
| 社区 | 正文、图片、作者、板块、互动 | 完整正文、图片、评论 | 正文、图片、服务端板块 |
| 跑腿 | 报酬、取件地、送达地、截止时间、说明摘要 | 路线、报酬、截止时间、完整说明 | 详细说明、取送地点、报酬、截止时间、联系方式 |
| 二手 | 图片、描述摘要、价格、状态 | 图片、价格、完整描述、交易状态 | 物品描述、图片、价格、联系方式 |
| 拼车 | 起终点、出发时间、余座、状态 | 路线、时间、人数、可选补充说明 | 起终点、出发时间、座位数、补充说明、联系方式 |

列表可以对正文或描述做视觉截断，但不得生成、持久化或回传伪标题。

## 功能需求

### 1. 社区

- 发布器移除标题输入。
- 发布校验调整为“正文或图片至少一项存在”，并继续要求选择服务端启用板块。
- 列表卡片直接显示正文；纯图片动态不显示空白文本占位。
- 详情页移除资源标题区和分享标题对资源标题的依赖。
- 搜索只检索正文，不再检索已删除标题列。

### 2. 跑腿

- 发布器移除标题输入，详细说明继续必填。
- 列表以报酬和取送路线建立首要层级，补充显示说明摘要。
- 详情页移除标题区，以取件地到送达地的路线作为首屏主要信息。
- 搜索覆盖说明、取件地和送达地。
- 订单 `title_snapshot` 改为服务端生成的路线摘要，例如“北区快递站 → 图书馆北门”，仅用于订单识别。

### 3. 二手

- 发布器移除标题输入，物品描述继续必填。
- 列表将描述作为商品主文案，最多显示约两至三行，不额外生成标题。
- 详情页移除标题区，图片、价格和完整描述构成首要信息。
- 搜索只覆盖描述及后续正式分类字段。
- 交易订单快照使用描述的安全截断摘要，不读取已删除标题。

### 4. 拼车

- 发布器移除标题输入。
- 将当前已显示但未提交的“详细说明”正式映射为可选 `description`。
- 列表与详情均以“起点 → 终点”为主要信息，时间和余座为第二层级。
- 搜索覆盖起点、终点和补充说明。

### 5. 发布器与本地草稿

- `PublisherForm` 删除 `title`。
- 删除标题输入组件、标题校验、编辑回填和提交映射。
- 草稿版本从 `lifePublisher.drafts.v1` 升级，旧版本草稿直接忽略或清理，不执行内容迁移。
- 页面头部的业务说明标题继续保留，它是固定界面文案。

### 6. API 契约

不新增资源路由，修改以下既有接口的请求和响应 Schema：

- `/api/v1/campus-circle/posts`
- `/api/v1/errands`
- `/api/v1/marketplace/listings`
- `/api/v1/carpool/trips`
- 对应详情、我的发布、审核和更新接口

要求：

- 创建和更新请求不再接受 `title`。
- 列表、详情和审核响应不再返回 `title`。
- 未知字段仍按平台现有绑定策略处理，不为旧客户端长期保留伪字段。
- 后端 `api/openapi.yaml` 继续作为小程序类型契约唯一来源。

## 数据库迁移

涉及表：

```text
campus_circle_posts.title
errand_tasks.title
marketplace_listings.title
carpool_trips.title
```

向上迁移顺序：

1. 为拼车增加可选或空字符串默认的 `description` 列。
2. 更新依赖标题的订单快照或审计快照生成逻辑。
3. 直接删除四张资源表的 `title` 列和相关索引。
4. 重新生成领域实体和 GORM Query。

向下迁移：

- 恢复四张表的 `title` 列及原约束，使用空字符串默认值满足开发环境结构回滚。
- 删除新增的拼车 `description` 列。
- 向下迁移只保证数据库结构可回滚，不恢复已经删除的开发数据。

迁移必须使用版本化 SQL；不依赖 `AutoMigrate` 删除列，因为 GORM AutoMigrate 不会主动删除未使用字段。

## 技术实现

### 后端

- 先修改 `schemas/campus_circle.yaml`、`schemas/errand.yaml`、`schemas/marketplace.yaml`、`schemas/carpool.yaml`。

- 为拼车领域、Schema、Store 和响应增加 `description`。
- 使用生成器更新 `.gen.go`、模块 OpenAPI、全局 OpenAPI、HTTP Adapter 和 GORM Query，不手工修改生成文件。
- 更新测试夹具、审核记录、事件负载和演示种子。
- 订单快照使用独立的服务端摘要函数，限制长度并避免空字符串。

### 小程序

- 从更新后的 OpenAPI 重新生成 `src/api/generated/schema.ts`。
- 更新社区卡片、生活服务卡片和四类详情页，删除资源标题渲染。
- 更新统一发布器表单结构、草稿版本、校验和提交载荷。
- 更新无障碍文案，使用正文摘要或路线描述资源。
- 删除不再使用的标题样式，保持列表密度和详情视觉层级稳定。

## 验收标准

1. 四类资源的数据库、OpenAPI、Go 模型和 TypeScript 类型均不存在领域 `title`。
2. 四类创建与更新请求无需标题即可成功提交。
3. 列表、详情和发布器不显示资源标题输入、标题文本或空白占位。
4. 社区使用正文或图片表达；跑腿和拼车使用路线；二手使用描述。
5. 拼车补充说明能够真实写入后端并在列表搜索、详情和编辑回填中使用。
6. 不执行存量标题转换，现有开发数据允许清理或重建。
7. 搜索、审核、订单快照和演示数据不再依赖已删除标题。
8. 页面导航标题、弹窗标题和筛选标题不受影响。
9. 后端生成、迁移、架构与目标测试通过。
10. 小程序类型检查、构建和微信模拟器完整发布链路通过。

## 风险与处理

| 风险 | 处理 |
| --- | --- |
| 旧客户端仍提交标题 | 前后端同版本联调发布；契约更新后旧字段不再参与业务 |
| 本地演示数据在字段删除后不可恢复 | 当前无线上真实数据，允许清理并重新生成演示数据 |
| 搜索召回下降 | 将搜索范围明确转移到正文、描述和路线字段 |
| 订单记录失去识别文案 | 使用服务端生成的路线或描述摘要写入订单快照 |
| 生成文件漂移 | 只修改 Schema 和手写扩展点，执行完整生成检查 |
| 本地旧草稿结构不兼容 | 使用新版本草稿键，直接忽略或清理旧版本草稿 |
