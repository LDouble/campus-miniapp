# Campus Miniapp：统一并优化详情评论列表组件

**Priority:** High
**Status:** In Progress
**Type:** Enhancement
**Created:** 2026-08-21
**Last Updated:** 2026-08-21

## Overview

继续优化详情页评论列表的布局、信息层级和触控体验。社区、跑腿、二手和找同行详情页必须继续复用同一个 `DetailComments` 公共组件，并由公共样式统一控制评论标题、一级评论、二级回复、点赞、时间、加载态和空状态；页面只提供数据、业务操作及发布按钮主题色。

## User Story

**As a** 浏览校园内容和生活服务详情的学生
**I want** 各类详情页的评论拥有一致、紧凑且易读的布局
**So that** 我能快速辨认评论者、回复关系、正文、时间和点赞状态，并顺畅地回复或点赞

## Current Findings

- 四类详情页已经引用同一个 `src/features/life-services/components/detail-comments.tsx`，数据加载、回复、点赞、撤回和本地乐观插入也已共用。
- 社区详情仍在 `src/packages/social/community/detail.scss` 中大范围覆盖公共评论样式，包括标题、头像、昵称、正文、点赞和回复底板，造成相同组件在不同场景下呈现两套布局。
- 公共 SCSS 前后存在两轮同名选择器覆盖，夹杂旧色值、非 Token 字重、圆角气泡、左侧回复缩进和新样式，盒子模型难以预测。
- 一级评论与二级回复的字号、头像和间距差异过多；回复容器左移且递归 DOM 嵌套，视觉上仍像多级缩进，不符合当前“平铺线程、不缩进”的规范。
- 生活服务详情容器与公共评论区各自设置了 `32rpx` 水平内边距，导致跑腿、二手和找同行评论内容从屏幕 `64rpx` 开始，而社区详情从 `32rpx` 开始。
- 公共默认样式会隐藏点赞数量，而社区页面再单独恢复；自己的评论“x赞”和其他评论“爱心 + 数量”没有在公共组件层稳定表达。
- 回复昵称目前按固定字符数提前截断，不能充分利用真实可用宽度；超长昵称、两个昵称加“回复”关系和作者徽章容易互相挤压。
- 标题区域仍包含硬编码黄色装饰和硬编码浅色值，未完整消费 Ousea / Global Token。

## Design Direction

`ui-ux-pro-max` 的通用推荐中，配色和大区块风格与项目既有 Ousea / Global 冲突，因此不采用其高饱和玫红方案；仅采用与移动评论场景一致的可用性原则，并由项目 Token 作为最终视觉来源：

- 评论正文使用 `comment` 层级：`30rpx`、Regular 400、`1.65` 行高，保证手机端长文本可读。
- 评论昵称统一使用高对比语义灰 `--campus-text-body`（浅色映射 Ousea `ink-700`），字号使用 `label`，字重控制在 Regular 400 或 Medium 500，不用蓝色或粗体抢正文层级；暗色模式切换为语义次级灰。
- 时间和审核状态放在正文下方的元信息行，避免和昵称、回复关系争抢首行空间。
- 一级评论头像使用稳定尺寸；回复使用更小头像，但所有回复平铺在同一个浅色线程区，不按层级继续缩进。
- 点赞的可见图形保持轻量，实际点击区域至少 `88rpx × 88rpx`；相邻可点击目标至少保留 `16rpx` 间距。
- 自己的评论只显示“x赞”，不显示爱心；其他评论显示爱心和数量，激活态使用 `--ousea-like-500`。
- 回复关系使用“昵称 + 线性回复箭头 + 昵称”；整段关系严格保持单行，两个昵称分别根据可用宽度弹性省略，图标不可丢失，三段之间只保留图标所需的最小间距。
- 列表项只使用紧凑留白建立节奏，不在评论之间添加分隔线，也不使用聊天气泡、重阴影或大圆角嵌套卡片。
- 一级评论之间以及回复之间不显示横向分隔线，层级只依靠头像、缩进面板和紧凑留白表达。
- 一级评论正文使用 `body` 层级 `32rpx`，二级回复继续使用 `comment` 层级 `30rpx`，明确主次关系。

### Long-content layout rules

- 一级评论昵称独占可伸缩身份区域，允许最多两行；两行仍放不下时才在末尾省略。作者徽章保持独立且不可被压缩，点赞操作固定在右上角，不参与昵称宽度计算。
- 二级回复关系作为独立单行渲染，不与回复正文拼在同一个行盒中。评论者昵称和被回复者昵称按内容宽度紧贴排列，不均分或撑满剩余空间；只有总宽度不足时才参与收缩并显示省略号，禁止按固定 6 个字符预裁剪。
- 回复关系使用固定尺寸、不可收缩的 SVG 线性箭头，不显示“回复”文字和 `@`。关系行禁止换行，不能因昵称收缩而丢失箭头。二级评论的“作者”标签必须紧跟评论者昵称，不能放在被回复者昵称之后。
- 一级评论和二级回复正文均不限行数。连续中文、长英文、URL 或无空格字符串使用 `overflow-wrap: anywhere` / 等价小程序样式断行，不能撑宽页面。
- 二级回复正文始终从内容列左边界开始，后续换行与第一行对齐；不能因为前面的昵称或“回复 @昵称”形成悬挂缩进。
- 时间与点赞位于正文之后的独立元信息行。长正文增加高度时只自然向下推，不覆盖、悬浮或挤压元信息。
- 贴纸与文字混排继续按正文基线排版；单个大贴纸不改变昵称和元信息列的宽度。

## Requirements

1. **单一公共组件**
   - 社区、跑腿、二手和找同行详情页继续统一使用 `DetailComments`。
   - 评论列表的结构和基础视觉只在公共组件及其 SCSS 中定义。
   - 删除社区详情对公共评论元素的页面级视觉覆盖。
   - `tone` 只允许影响发布按钮和业务主行为，不影响评论列表的昵称、正文、回复、点赞和间距。
   - 四类详情评论均以屏幕左侧 `32rpx` 为内容起始线；生活服务详情需抵消外层页面 gutter，避免公共评论自身 gutter 被重复叠加。

2. **统一一级评论布局**
   - 标题行采用 Ousea 标题、计数和分隔线 Token，不使用硬编码黄色装饰。
   - 一级评论采用“头像 + 内容列”：昵称与作者徽章在首行，正文独占内容行，时间与点赞在末行。
   - 昵称最多展示两行，超出后省略；作者徽章和右侧点赞不因昵称换行错位或被挤出屏幕。
   - 正文支持任意长度自然换行、`overflow-wrap: anywhere`，不限制行数，不得横向溢出。
   - 评论间距保持紧凑，但点击正文回复的热区覆盖完整内容区。
   - 短评论盒子模型使用 `20rpx` 顶部、`8rpx` 底部内边距；时间/点赞行视觉占位压缩至 `56rpx`，点赞真实热区仍保持 `88rpx`。

3. **统一二级回复布局**
   - 回复面板整体固定缩进到一级评论正文列；面板内部的二级、三级回复平铺展示，不再按回复层级继续增加左边距。
   - 同一根评论下的回复进入轻量 `surface-subtle` 区域，内部回复之间使用留白或细分隔线。
   - 回复关系明确展示“评论者回复被回复者”，单独占据一行且禁止换行；两个昵称分别弹性省略、三段之间无额外留白，作者徽章与评论者身份对齐。
   - 长二级回复正文不限行，所有换行均从正文左边界开始，不跟随昵称产生首行或后续行缩进。
   - 递归回复数据仍按现有父子关系生成，但视觉层级不递归缩进。
   - “查看全部 x 条回复”、加载和重试入口保持可用并使用统一文字按钮样式。

4. **点赞与状态表达**
   - 自己的评论始终只显示“x赞”，不渲染爱心图形。
   - 其他评论显示爱心与数量；可点赞时保留操作能力，不可点赞时只读展示。
   - 点赞按钮视觉尺寸紧凑、点击热区不小于 `88rpx`，异步中避免重复点击。
   - 未审核状态与时间同属弱元信息层，但状态必须有文字，不能只靠颜色。

5. **Token、暗色与无障碍**
   - 新样式使用 `--ousea-*` 或现有映射到 Ousea 的 `--campus-*` 语义 Token，不新增页面局部基础色。
   - 暗色模式同步覆盖背景、正文、昵称、时间、分隔线和点赞激活态。
   - 头像、昵称、评论正文、点赞和展开回复均保留可访问名称及原有事件阻止逻辑。
   - 进入、撤回和点赞动效保持轻量，并在 `prefers-reduced-motion` 下关闭。

6. **状态与行为不回归**
   - 保留分页、骨架屏、空状态、加载更多、回复线程拉取和错误重试。
   - 保留点击评论回复、长按操作、打开个人主页、点赞/取消点赞、撤回和举报。
   - 保留一级评论与二级回复成功后的本地即时插入，不触发整页刷新。
   - 列表评论输入弹层的 `composerOnly` 模式不展示评论列表，不改变既有行为。

## Implementation Overview

1. 整理 `DetailComments` 内部的评论展示结构，将一级评论、回复线程和元信息作为公共展示单元维护，页面不再参与布局。
2. 移除固定 6 字昵称裁剪，把昵称、回复关系和正文拆成独立行盒：一级昵称最多两行，二级回复关系固定一行，正文不限行；时间下沉至稳定元信息行。
3. 合并 `detail-comments.scss` 中重复的评论列表规则，按“容器、标题、一级评论、回复区、状态、动效”重排，并全部映射到现有 Token。
4. 删除 `community/detail.scss` 中针对 `.business-detail-comment*` 和 `.business-detail-comments*` 的场景覆盖，仅保留详情页面自身结构样式。
5. 同步字体与暗色全局断言，更新现有 smoke tests，明确四类详情复用同一结构且没有页面级视觉分叉。

## Files to Modify

- `src/features/life-services/components/detail-comments.tsx` - 统一评论行、回复关系、时间与点赞结构，保留现有数据及交互逻辑。
- `src/features/life-services/components/detail-comments.scss` - 合并重复规则并重做统一评论列表盒子模型。
- `src/packages/social/community/detail.scss` - 移除社区详情对公共评论组件的视觉覆盖。
- `src/styles/_typography.scss` - 让公共评论字号只映射 Ousea comment、label、caption 层级。
- `src/styles/_dark-mode.scss` - 同步统一评论列表的暗色语义样式。
- `scripts/community-detail-figma-smoke.ts` - 从社区专属样式断言改为公共组件复用断言。
- `scripts/community-detail-navigation-smoke.ts` - 移除已废弃的社区评论视觉覆盖断言。
- `scripts/comment-reply-smoke.ts` - 补充无缩进、长昵称、回复关系、时间位置和共享组件断言。
- `scripts/comment-like-smoke.ts` - 补充“自己的 x赞 / 其他爱心 + 数量”公共行为断言。
- `scripts/typography-smoke.ts`、`scripts/dark-mode-smoke.ts` - 更新 Token 与暗色模式断言。

## API Endpoints

不新增或修改接口。继续使用现有评论列表、线程、发布、撤回和点赞协议。

## Libraries/Dependencies

- 使用现有 React、Taro `View` / `Text` / `Image`、SCSS 和 `CommentView` 类型。

### Manual Testing

- 分别打开社区、跑腿、二手和找同行详情，确认标题、一级评论、回复区、时间和点赞完全一致。
- 验证无评论、加载中、超过一页、回复加载失败与重试场景。
- 验证一级评论、回复二级评论后立即插入正确线程；回复面板只做一次固定缩进，面板内更深层回复不继续缩进。
- 验证自己的评论仅显示“x赞”，其他评论显示爱心与数量，点赞激活态正确。
- 验证一级昵称一行、两行和超过两行三种情况；作者徽章、点赞和头像均不移位。
- 验证“短昵称回复长昵称”“长昵称回复短昵称”“两个昵称都很长”时关系始终只有一行，两个昵称可分别省略且“回复”完整可见。
- 验证二级回复正文达到 2、5、20 行时不截断，第一行与后续行从同一左边界开始。
- 验证超长中文、连续英文、URL、无空格字符串及贴纸混排不横向溢出。
- 验证 320px、360px、375px 宽度以及浅色、暗色模式。
- 验证点击正文回复、长按操作、头像跳转和点赞的热区不互相穿透。

## Risks and Constraints

- 现有 smoke tests 对社区详情的旧选择器和硬编码视觉规则绑定较深，重构时需同步更新，避免测试继续固化分叉样式。
- `DetailComments` 同时承载列表、输入框和详情底栏，本次只收敛评论列表展示，不改动键盘避让、底栏行为协议和业务状态机。
- 工作区已有同分支的帖子卡片与操作菜单修改；实现时必须保留并避免覆盖这些未提交内容。

---

**Implementation Notes:** 本任务不把 Feed 中最多三条的评论摘要改造成完整评论列表，也不改变列表页 `composerOnly` 评论输入弹层；统一范围是四类详情页的完整评论列表。业务色只保留在发布按钮与业务主操作上。
