# Feed 今天吃什么随机卡 PRD

## 背景

社区 Feed 是用户高频访问场景，可以自然承载校园生活服务推荐，帮助用户发现“今天吃什么”。

## 目标

- 在 Feed 中增加轻量、非侵入式的随机餐品推荐。
- 复用现有“今天吃什么”接口、详情页和设计规范。
- 不影响帖子排序、分页和滚动体验。

## 交互方案

1. Feed 加载完成后，在第 3～5 条内容附近最多插入一张推荐卡。
2. 当天首次获得推荐后缓存结果，刷新或重新进入当天保持一致。
3. 点击“换一个”重新请求/选择推荐并更新当天缓存。
4. 点击卡片或“去看看”进入对应餐品详情。
5. 接口无数据、加载失败或推荐不可用时不展示空卡片，也不打断 Feed。

## 范围

- Feed 数据组装和插卡位置。
- 随机推荐卡组件及加载、空数据、暗黑模式样式。
- 当天缓存、换一个和详情跳转。

## 非范围

- 不修改后端接口、数据模型和 Feed 分页协议。
- 不改变帖子排序规则。

## 验收标准

- 有可用数据时 Feed 最多显示一张随机卡。
- 无数据或请求失败时 Feed 正常展示且无空卡。
- 换一个可以更新推荐，点击可以进入详情。
- 同一天刷新推荐结果稳定。
- 通过 lint、typecheck、相关 smoke 和小程序构建。

## 技术方案

先复用“今天吃什么”现有 API 类型和详情路由，抽取 Feed 插卡模型；使用页面级缓存隔离推荐状态，插卡仅作为 Feed 渲染项，不修改服务端分页返回。推荐请求失败采用静默降级。
