# 小程序与后端：校园生活重复 Slogan 清理与多状态演示数据

**Priority:** High
**Status:** Done
**Type:** Enhancement
**Created:** 2026-07-26
**Last Updated:** 2026-07-26

## 概述

本任务包含两个增量改进：

1. 删除校园生活一级 Tab 下方重复出现的业务标题与 Slogan 卡片，保留页面 Header 中唯一的标题和说明，让搜索、筛选和首条内容更早进入首屏。
2. 在本地 Go 后端提供安全、幂等、可清理的演示数据初始化能力，为社区、跑腿、二手和拼车构造多种真实状态，方便直接在小程序公开列表与“我的服务”中查看。

## 用户故事

**作为** 本地开发和验收人员
**我希望** 页面不重复表达标题，并能一键获得覆盖主要状态的真实业务数据
**从而** 更高效地检查列表卡片、状态标签、详情操作和个人记录页面

## 范围

### 小程序界面

- 保留自定义 Header 中的业务标题和说明。
- 保留一级业务 Tab、社区服务端板块、搜索、结构化筛选、结果标题和发布按钮。
- 删除一级 Tab 与搜索之间的重复业务宣传卡：
  - 社区的 `api-community__context`。
  - 跑腿、二手、拼车的 `life-context`。
- 删除对应的装饰图形与无效样式。
- 不删除空状态说明、筛选摘要或结果标题。

### 本地演示数据

- 仅用于 `development` 环境。
- 默认选择最近一个已完成校园认证的非管理员用户作为演示数据归属人。
- 支持通过 `CAMPUS_DEMO_MEMBER_ID` 显式指定当前小程序登录用户 ID。
- 使用本地辅助账号构造接单人、买家和拼车参与者关系。
- 使用相对当前时间生成截止时间和出发时间，避免演示数据很快全部过期。
- 所有演示标题统一带 `[演示]` 前缀，并在清理时只作用于该前缀对应的精确资源 ID。

## 公开列表与个人列表边界

- 社区公开列表只显示已发布内容。
- 跑腿公开列表只显示已审核且可接的任务。
- 二手公开列表只显示在售商品。
- 拼车公开列表只显示已审核且尚可展示的未来行程。
- 待审核、驳回、进行中、完成、取消和撤回状态主要通过“我的服务”查看。
- 不为展示方便而放宽公开接口权限或绕过内容审核规则。

## 技术方案

### Go CLI

在现有 `campusctl` 中增加：

- `campusctl demo seed`：幂等创建或重建演示数据。
- `campusctl demo clean`：只清理本地演示数据和对应关系数据。

CLI 参数与环境变量：

- `--member-id` 或 `CAMPUS_DEMO_MEMBER_ID`：指定演示数据归属用户。
- 未指定时自动选择最近一个已认证的非管理员用户。
- 命令只允许 `CAMPUS_ENV=development`。
- 数据库连接必须解析为本机回环地址，否则拒绝执行。

### 数据写入

- 使用现有 `bootstrap` 配置加载和 MySQL 连接方式。
- 联系方式通过现有配置密钥与相同 AAD 规则加密，不写入明文或无效密文。
- 使用一个 GORM 事务完成清理与重建，任一写入失败则整体回滚。
- 关系表、状态转换、订单和参与记录保持与主记录状态一致。
- 演示数据不生成虚假的支付成功记录。
- 不修改迁移文件，不新增生产数据库表。

### 幂等与清理

- 演示资源使用稳定前缀 `[演示]` 和版本标识 `LIFE-DEMO-V1`。
- `seed` 先在事务内清理旧版同前缀数据，再重建最新数据。
- 清理时先解析精确资源 ID，再按依赖顺序删除：
  - 评论、点赞、图片等内容关系。
  - 拼车参与记录。
  - 二手预订、交易订单及订单转换记录。
  - 跑腿订单和任务转换记录。
  - 领域事件、Outbox 与演示资源主表。
- 不使用宽泛标题模糊删除，不删除普通用户数据。

### 本地开发入口

后端 Makefile 增加：

- `make demo-seed`：在本机 Go 环境执行演示数据初始化。
- `make demo-clean`：清理演示数据。
- `make demo-reset`：清理并重新初始化。

命令复用 `scripts/run-local.sh` 加载本地配置，Docker 仍只运行 MySQL 和 Redis。

## 安全要求

- 生产环境必须拒绝执行。
- 非回环数据库必须拒绝执行。
- 不输出密码、Token、联系方式明文或加密密钥。
- 自动选择用户时只输出数值用户 ID 和创建数量。
- 清理前必须先得到演示资源的精确 ID 集合。
- 失败时事务整体回滚，不留下部分状态。

## 验收标准

### 小程序

1. Header 下只保留一级 Tab 和必要的服务端板块/筛选，不再重复显示业务标题和 Slogan。
2. 社区、跑腿、二手和拼车首条内容相对改动前明显上移。

### 演示数据

1. 一条命令可以构造状态矩阵中的全部数据。
2. 重复执行不会持续增加重复演示数据。
3. `demo clean` 后演示资源和关系数据残留数量为 0。
4. 公开列表只出现允许公开的状态。
5. 指定用户能在“我的服务”中看到归属于自己的完整状态集合。
6. 联系方式读取不会发生解密错误。
7. 二手价格筛选和拼车日期、路线、座位筛选均能命中对应演示数据。

## 手动查看路径

- 公开状态：社区 Tab 下切换社区、跑腿、二手、拼车。
- 社区非公开状态：我的 → 我的服务 → 我的发布。
- 跑腿全状态：我的 → 我的服务 → 我发布的 / 我的接单。
- 二手全状态：我的 → 我的服务 → 我的商品 / 我的订单。
- 拼车全状态：我的 → 我的服务 → 我发起的 / 我的参与。

## 风险与控制

- **错误连接共享数据库**：环境与回环地址双重保护。
- **演示数据污染正常数据**：稳定前缀、精确资源 ID 和事务清理。
- **状态关系不一致**：同步构造转换记录、参与关系和交易订单。
- **当前登录用户未命中**：支持显式 `CAMPUS_DEMO_MEMBER_ID`，默认规则会在命令输出中提示选中的数值 ID。
- **公开列表看不到全部状态**：遵守公开接口约束，文档明确通过“我的服务”查看非公开状态。
