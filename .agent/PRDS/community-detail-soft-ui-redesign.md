# 小程序：社区动态详情页清新服务卡片重设计

**Priority:** High
**Status:** Done
**Type:** Enhancement
**Created:** 2026-07-26
**Last Updated:** 2026-07-26

## 概述

重新设计社区动态详情页，使其与社区列表已经确定的“校园清新服务卡片”视觉体系一致。详情页继续承载动态内容、图片、点赞、分享、编辑、审核说明、评论列表、评论分页和评论发布，不改变现有后端接口与业务规则。

最终风格基准：

- 移动端卡片式设计（Card-based Mobile UI）
- 轻量化新拟态（Soft Neumorphism）
- 柔和渐变与半玻璃拟态（Soft Gradient + Subtle Glassmorphism）
- 面向校园场景的清新服务平台视觉

## 用户故事

**作为** 浏览校园动态的学生

**我希望** 在详情页舒适地阅读正文、浏览图片、查看评论并快速互动

**从而** 更自然地参与校园交流，不被复杂装饰和重复按钮打断

## 当前问题

- 文章卡片与评论卡片使用普通白底、灰色描边，和新版社区列表的柔和层次不一致。
- 作者头像、可见状态和互动按钮都依赖矩形或胶囊容器，视觉较旧。
- 点赞与分享是纯文字按钮，缺少与列表一致的图标语言。
- 评论空状态只有文字，页面中段留白较生硬。
- 底部评论输入区使用高对比纯白工具栏和文字发送按钮，缺少半玻璃层次。
- 动态图片只能展示，无法点击进入微信原生图片预览。
- Navbar 副标题和页面内容中的校园身份信息存在重复。

## 设计方案

### 页面背景与导航

- 使用与列表一致的淡蓝紫、浅青多层渐变背景。
- 保留自定义返回导航，标题为“动态详情”，移除重复的学校副标题。
- 导航与内容之间不增加厚重分割条。

### 文章主卡片

- 使用高透明度暖白渐变、轻微背景模糊、极浅白色描边、双层柔和阴影与内高光。
- 卡片圆角控制为 28–32rpx，文字对比满足正文阅读，不使用传统新拟态低对比灰字。
- 作者头像使用与列表一致的圆形数字身份标识，颜色由 `section_id` 稳定派生。
- 作者名称、校园号和发布时间使用纯文字层级。
- 发布状态改为小圆点加文字，不使用胶囊背景。
- 标题作为首要阅读信息，正文保持 1.65–1.75 行高。

### 图片浏览

- 单图和多图均使用统一圆角与间距，保留 `lazyLoad`。
- 点击任意图片调用 `Taro.previewImage`，传入完整服务端图片 URL 列表并定位当前图片。
- 不新增本地演示图片，不硬编码图片内容。

### 文章互动区

- 点赞、评论、分享和编辑使用统一 SVG 线性图标。
- 点赞与评论显示数字，分享与编辑使用图标为主要表达。
- 移除三等分灰底按钮和按钮外框。
- 图标可见尺寸保持轻巧，实际触控目标不小于 88rpx。
- 点赞激活态使用珊瑚粉实心心形和数字，不只依赖颜色以外的状态变化。

### 审核说明

- 仅在 `review_reason` 存在时展示。
- 使用低饱和暖橙提示面板，保留清晰的“审核说明”语义。

### 评论区域

- 评论区域使用独立半玻璃卡片，与文章卡片保持层次但降低阴影强度。
- 评论标题显示“评论”和服务端统计数量。
- 评论头像使用圆形数字身份标识，颜色由 `author_id` 稳定派生。
- 作者、正文、时间和非公开状态建立四级文字层级。
- 评论之间使用留白和极浅分隔线，不为每条评论单独增加卡片边框。
- 空状态使用评论 SVG 图标、标题和引导文案，缩短无内容区域高度。
- “查看更多评论”保持纯文字操作和足够触控高度。

### 底部评论输入区

- 使用高透明度暖白半玻璃固定工具栏、顶部柔和阴影和安全区适配。
- 输入框采用轻微内凹的浅灰紫背景，但保持清晰边界与文字对比。
- 发送改为圆形图标按钮，发送中展示明确禁用状态，避免重复提交。
- 保留 `maxlength=300`、键盘发送和原有错误反馈。

## 业务与数据约束

- 不修改后端接口、OpenAPI、数据库或评论审核逻辑。
- 不硬编码动态、作者、评论、图片、互动数字或社区板块业务数据。
- 保持点赞、取消点赞、分享、编辑、评论提交和评论分页行为。
- 保持 `available_actions` 对编辑入口的权限控制。
- 保持评论创建后的审核状态与动态评论数量更新规则。
- 继续使用服务端返回的 `post.status` 和 `review_reason`。

## 技术方案

- 使用现有 React、Taro、TypeScript 与 SCSS，不新增 npm 依赖。
- 继续使用 `Input` 作为评论输入组件，避免在固定半玻璃工具栏中引入原生 `Textarea` 覆盖层兼容风险。
- 使用 `Taro.previewImage({ current, urls })` 提供微信原生图片预览。
- 使用 Taro `View.hoverClass` 提供 150–200ms 的按压反馈。
- 使用 `rpx`、BEM 类名、稳定 React `key` 和图片 `lazyLoad`。
- 原生小程序技能中禁止 Taro/TypeScript 的规则与项目技术栈冲突，不采用；仅采用响应式、触控和性能规则。

## Taro 文档依据

- Context7 Library ID：`/nervjs/taro-docs`
- `Taro.previewImage` 支持传入 `urls` 和当前图片 `current`，微信小程序支持原生全屏预览。
- `Input` 保留 `maxlength`、`confirmType='send'`、`onInput` 和 `onConfirm`。
- 图标化操作使用 Taro `View` 和 `Image`，可见图标与实际触控区域分离。

## 验收标准

1. 详情页与社区列表使用一致的淡蓝紫渐变、半玻璃卡片和轻量新拟态视觉。
2. 页面不存在粗边框、三等分灰底互动按钮或状态胶囊堆叠。
3. 作者、发布时间、状态、标题、正文和互动数据在 375px 等效宽度下清晰可读。
4. 点赞、评论、分享和编辑以图标为主要表达，触控目标不小于 88rpx。
5. 点赞状态和数字能够即时更新，原接口行为不回归。
6. 动态图片支持点击进入微信原生预览，并定位到所点击图片。
7. 评论列表、空状态、待审核状态、分页和评论发布均正确显示。
8. 底部评论输入区不会遮挡最后一条评论，适配 iPhone 安全区和键盘发送。
9. 无图片、无标题、长正文、无评论、有评论和审核说明场景均能正确排版。
10. TypeScript 检查、微信小程序构建和 `git diff --check` 通过。
11. 微信开发者工具真实模拟器截图通过人工视觉验收，控制台无未处理异常。

## 风险与处理

- 半玻璃和模糊效果在不同基础库版本上可能表现不同；卡片必须以高透明度暖白背景作为降级，不依赖模糊保证可读性。
- 固定评论栏可能受键盘与安全区影响；维持现有单行 `Input`，并保留足够内容底部间距。
- 当前本地动态可能没有图片或评论；视觉验收优先覆盖现有真实状态，缺失分支通过结构与构建验证。
