## 问题

Campus 暂无可扩展的成绩排名、个人计算明细、学生自主授权的汇总报告；目前教务身份缺少班级归属，需支持 provider 获取班级信息后由 analysis 消费更新。

## 目标

实现成绩排名一期：排名组邀请加入与成员确认、版本化课程/成绩规则、本人逐课明细、按学生授权汇总给指定接收人、站内通知跳转报告；真实教务班级作为带来源与版本的独立档案更新。

## 范围

- 成绩规则：课程范围、时间范围、成绩制换算、补考/重修策略、学分加权均分和并列排名。
- 排名组：创建、邀请、已认证学生申请加入、组主确认；自建组不等同已核实行政班级。
- 自主授权：本人选择接收人、期限及是否允许逐课明细，支持撤销；加入组不自动授权其他人查看。
- 报告与通知：个人与授权汇总来自同一不可变批次；站内定向通知；失败重试与去重；撤销权限立即影响读取。
- provider 班级信息：兼容添加学院/专业/入学年/行政班字段及来源、更新时间；analysis 消费更新，处理缺失、重复、乱序；不覆盖用户自建组关系和授权。
- 最小管理与客户端入口，以及契约、迁移、目标测试。

## 非范围

综测/竞赛加分、奖学金/推免资格和名额、强基考察、外部通知渠道、文件导出；不自动修改现有本地发布环境。

## 验收标准

1. 不同成绩口径共享计算内核；成绩明细可对账，0分/缺失/重补修按明确规则处理。
2. 发布排名标明参与群体和完整度，未核实的自建组显示参与者排名。
3. 非本人无权读取个人明细；汇总仅返回当前仍获授权的行及字段；组主身份不产生全组成绩查看权。
4. 授权撤销、过期、退出及链接转发不绕过服务端鉴权。
5. 同一批次重试不会重复通知；个人报告和汇总中同一行的成绩与原始名次一致。
6. provider 返回班级信息后 analysis 可观测地更新档案；重复/较旧事件不覆盖较新数据，空值不误清已有班级，自建组与授权保持独立。
7. 各端完成目标测试、生成漂移/迁移检查及类型检查。

## 跨端影响

主责界面：campus-miniapp。后端：backend_demo。教务 provider/analysis：campus-academic。管理端：campus-admin-web（按最终接口需求接入）。各端使用同一 Feature ID；实现时先确定兼容契约，不手改生成文件。
